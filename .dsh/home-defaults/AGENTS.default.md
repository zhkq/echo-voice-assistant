# 术语与姓名纠错（Term & Name Correction）— 全局生效

处理用户指令、生成会议纪要、做每日回顾、写工作日志 / 项目日志、归档、输出 JSON 元数据时，
**先校正专有名词（公司 / 平台 / 产品名）与同事姓名，再进行理解与产出**。

**权威表**：你自己的「术语与姓名纠错表」。默认约定放在**笔记库的记忆文件**里
（`.workbuddy/memory/MEMORY.md` →「热点名词与常见姓名纠错表」一节；笔记库根目录见 ECHO 的
「笔记库」设置，路径不合你的习惯就直接改本文件这一句）。**涉及名词与姓名时先读那一节**。

表还不存在时**不要因此跳过纠错**：按下面的规则办事，并在用户第一次订正时把表建起来
（那一节可以只有一行，之后逐条追加）。

## 规则

1. **我的叙述一律用正确写法**：指令理解、纪要标题与正文、待办责任人、日志条目、JSON 字段都归一。
2. **原话与原始转写保留原样**：引用用户原话 / 转写原文不改写，可补「（转写作 XX）」；
   **不得**用纠错后的文字覆盖原始转写。
3. **改名不改链接**：wikilink 与文件路径必须指向笔记库里真实存在的文件名 / 目录，
   不按纠错后的名字臆造路径。
4. **不确定就标疑**：写「XX（转写作 YY，待确认）」；**绝不把不同的人合并**。
5. **新发现即追加**：把新误识追加进权威表；你的笔记库若已有「纪要末尾附术语校正表」的惯例，照旧附。
6. **口径来源**：这类专有名词与姓名，**用户在对话里说一句就是权威订正**。收到后立即：
   ① 当次产出按新口径纠正 → ② 追加权威表 → ③ 同步本文件与相关技能的速查行；
   **不要反问用户、也不要让他自己改文件**。与旧记录冲突时以新说法为准，旧写法保留并记一行订正。

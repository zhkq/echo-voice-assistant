# 会议纪要归档（ECHO 委派）

## 用途

ECHO 开完会、生成了纪要文件之后，把"材料在哪"交给本技能。本技能负责：

1. **判断归属**：这场纪要该放进笔记库的哪个目录；
2. **写纪要**：把纪要写进那个目录（**内容从指令给的 `纪要文件` 读全文**，不要凭标题猜）；
3. **更新日志**：在相关工作日志/项目日志里留一条引用（**目录确实存在才挂**）；
4. **幂等**：同一个幂等键已经登记过就跳过，别重复写。

## 触发条件与指令给的字段

指令里出现 **`【纪要归档任务】`** 时使用。字段：

| 字段 | 含义 |
| --- | --- |
| `笔记库根目录` | **权威路径**，不要用别的 |
| `会议标题` / `会议时间` / `参会人` | 只用于命名与摘要，不是内容来源 |
| `纪要文件` | **纪要全文在这里**，动手前先读它 |
| `幂等键` | 同一场会议的唯一标识 —— 去重就靠它 |
| `归档要求` | 用户/面板给的**自由文本**要求，优先于本技能的默认规则 |

## 个性化：`profile`

**本技能刻意只带骨架** —— "会议按什么归位"是每个用户/每个库自己的事。规则放在
**`<笔记库根目录>/.echo/profile.md`**（与 `daily-review` 共用同一个文件）。

**第一步永远是：读 profile。**

- 读不到 → **先按"最小安全规则"把这一轮做完**（见下），然后在回复里问一个问题
  （"这类会议以后放哪个目录？"），把答案写进 profile；
- 命令里的 `归档要求` **优先于** profile（那是用户当场的要求）。

### 最小安全规则（没有 profile 也没有归档要求时）

1. 在笔记库里找一个**看起来就是会议记录**的目录（例如名字含"会议"的目录）；
   **找到就放进去，找不到就放在笔记库根目录下**，**绝不新建**一堆目录去猜；
2. 文件名用 `YYYY-MM-DD_标题.md`（标题里的 `/ \ : * ? " < > |` 换成 `-`）；
3. 工作日志只做**引用**（一条 `- 会议：[[<纪要相对路径>]]`），不改日志里别的内容；
4. **做完在回复里说清"放到了哪个文件"**，并问一句这类会议以后固定放哪。

## 执行流程

### 1. 先看幂等键

在笔记库里搜一下这个幂等键（或同一场会议的纪要文件名）。**已经登记过就跳过**，
回复"这场已经归档过了（<文件>）"，不要重复写。

### 2. 读纪要全文

**读 `纪要文件` 的内容** —— 归属判断与摘要都用它，不要凭会议标题推测。

### 3. 判断归属

优先级：`归档要求` → profile → 最小安全规则。判断依据只看两样：**这场会的类型**（从纪要
内容里看）与**笔记库里实际存在的目录**。**目录不存在就不要凭空造**（例外：最小安全规则
第 1 条那个"找不到就放根目录"）。

### 4. 写文件

- 目标目录里同名文件已存在 → 在文件末尾追加一节 `## 补记（YYYY-MM-DD HH:MM）`，**不要覆盖**；
- 保留纪要原文的标题层级；如需 frontmatter，用 profile 里约定的字段。

### 5. 更新日志与双向链接（存在才挂）

- 工作日志：在当天日志里加一条引用（`- 会议：[[…]]`）——按 `daily-review` 约定找到当天文件；
- 项目/专项日志：**只有** profile 里记着"这场会对应哪个专项目录"、且那个目录**确实存在**时才挂，
  并在项目日志里补一行 `> 相关会议：[[<纪要相对路径>]]`。
- **宁可只归档纪要、不挂链接**，也不要臆造专项目录。

### 6. 回复（硬性）

**只回一句话**（面板会原样显示给人看）：归档到了哪个文件；跳过了就说跳到哪一条。

```
已归档：02-会议记录/…/2026-10-11_周会.md（工作日志已挂链接）
```

- 不要输出 Markdown 列表、不要把纪要正文复述一遍；
- 顺带发现的问题（比如同一场会已有纪要）写进这一句里的人话部分。

## 已知边界

- 本技能**不生成**纪要（那是 ECHO 会议模块的事），只负责**归档**；
- **不改写**纪要正文，只做搬运/补记；
- 用户如果没配笔记库，回复里直接说明"没配笔记库，没法归档"，**不要写到别处去**。

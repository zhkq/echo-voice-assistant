# 每日回顾（ECHO 语音委派）

## 用途

下班后用户**一次性口述**当天做了什么，本技能负责五件事：

0. **自动收集当天素材**（新增前置步骤）：扫描企微（含联通私有化企微）/微信/桌面/WPS 缓存中的当天文件，以及 ECHO 自动会议纪要，按专项归属分类登记到工作日志；
1. **整理**成符合用户习惯的工作日志条目（不是流水账，是可归档的条目）；
2. **登记**进 Obsidian 笔记库的 `01-工作日志/YYYY-MM-DD.md`；
3. **反查遗漏**：结合「相关记忆」里的待办与重点项目，主动问用户可能漏掉的事；
4. **输出播报稿**：一段 ≤2 句 + 1 个问题的口语文本，供 ECHO 朗读（这是本技能唯一影响车内体验的输出）。

## 触发条件

指令文本里出现 **`【每日回顾】`** 时使用本技能。这是 ECHO 的委派：
用户在车里口述完，ECHO 把「原始转写」发过来，等你整理 + 追问。

用户也可能在 DSH 里直接说「我们来回顾今天」——同样按本技能执行。

## 输出契约（硬性，违反会让用户听到一整篇）

**每一条回复都必须包含恰好一段：**

```
【播报】口语化的两句话以内 + 恰好一个问题（也可以只有确认，不带问题）【/播报】
```

**播报段的硬规则：**

- **不可以有 Markdown**：没有列表、没有编号、没有加粗、没有表格、没有 `#`；
- **不可以出现书面标记**：不要「以下」「综上」「详见」；数字与日期口语化（说"十月六号"，不写 `2026-10-06`）；
- **长度**：目标 **60 字以内、最多不超过 120 字**（它是念出来的，不是看的）；
- **只问一个问题**。信息确认与遗漏检查**不要在同一轮里各问一个**——挑最要紧的那个；
- 播报段**之后不要再写正文**（ECHO 只读这一段，后面的东西用户当场看不到）。
- **第 0 步的自动收集结果**：在播报第一句用一句话带过，例如"今天自动扫到三份文件、一场会议，已经登记好了。"**不要展开清单**。
- **启动反馈例外**：第 0-0 步的"好，我先扫一下今天的文件和会议，大概需要一分钟。"是唯一允许**不带问题**的播报，且不计入后续"只问一个问题"规则。

正确示例：

```
【播报】今天自动扫到两份文件、一场会，已经登记好了。你下午要确认的那件事办了吗？【/播报】
```

```
【播报】今天没有新文件也没有新会议。我们来回顾今天的工作吧。【/播报】
```

## 执行流程

### 第 0 步：自动收集当天素材（前置步骤）

**在接收用户口述之前**，先自动扫描当天（`YYYY-MM-DD`）的文件和会议录音，完成初步登记。
这一步是静默执行的，结果汇总到播报里。

#### 0-0. 即时反馈（让 ECHO 先出声）

开始扫描前，**立即回复 ECHO 一句简短确认**，让用户知道回顾已启动：

```
【播报】好，我先扫一下今天的文件和会议，大概需要一分钟。【/播报】
```

> 这句回复**只有这一句播报**，不带问题。ECHO 念完这句就开始执行后面的扫描，用户听到后就知道系统已经在工作了，并且知道要等一会儿。
> 注意：这句播报不计入后续正式播报的"只问一个问题"规则——它是启动提示，不是正式回顾。

#### 0-A. 扫描文件

1. **运行扫描脚本**（调用 `wecom-file-to-obsidian` 的 `scan_cache.py`）：
   ```powershell
   python scripts/scan_cache.py --days 1 --platforms wecom,wechat,desktop,wps,unicom --json
   ```
   - 扫描范围：企微、联通私有化企微（`~/Documents/chinaunicom_data`）、微信、桌面临时文件夹、WPS 云缓存
   - 私有化企微只扫 `Profiles\*\Cache\chat\file\<YYYYMM>\`（收到的文档）；`chat\image` 等聊天图片不算工作文件，目录可用环境变量 `UNICOM_ROOT` 覆盖
   - 文件类型：Office 文档（xlsx/docx/pptx/pdf）、xmind、md 等常见工作文档
   - 时间范围：当天（`--days 1`）

2. **版本去重**：脚本输出的 JSON 已按文件名+扩展名分组，同一组内取**接收时间最新**的版本。
   若当天已有同名文件登记过（检查 `01-工作日志/assets/` 或对应专项目录 `assets/`），跳过。

3. **归属判断**（按 `obsidian-worklog` 的「专项工作目录的已知位置」表匹配）：
   - **命中已知专项**（文件名或内容关键词匹配**手册里那张专项表**；专项名不在本技能里写死，以 `obsidian-worklog` 手册的专项表为准）：
     → 登记到该专项的 `项目日志.md`（追加进展记录 + `> 相关工作日志：` 反向链接）
     → 同时在 `01-工作日志/YYYY-MM-DD.md` 对应时段追加条目，含 `[[专项目录/项目日志|显示名]]` 链接
     → 文件复制到 `{专项目录}/assets/YYYY-MM-DD_原始文件名.ext`
   - **未命中专项但有收集必要**（非临时性工作文件）：
     → 登记到 `01-工作日志/YYYY-MM-DD.md` 对应时段通用条目
     → 文件复制到 `01-工作日志/assets/YYYY-MM-DD_原始文件名.ext`
   - **明显临时/无关文件**（如截图碎片、临时缓存）：跳过，不登记。

4. **幂等检查**：读当天日志，若某文件已登记过（条目中已有同名文件 wikilink），跳过该文件。

#### 0-B. 检查会议录音纪要

1. **检查当天 ECHO 自动纪要目录**：
   ```
   02-会议记录/ECHO自动纪要/{YYYY-MM-DD}_*.md
   ```
   列出当天所有自动纪要文件。

2. **幂等检查**：对每份纪要，读当天日志检查是否已包含该会议标题的 `会议纪要：` 条目。
   已登记过的跳过。

3. **归属判定**（按 `meeting-archive` 技能的判定流程，命中即停）：
   - **① 命中既有固定例会**（例会名以 `obsidian-worklog` 手册的例会表为准，本技能不写死具体名）：
     → 归入 `02-会议记录/{例会目录}/{例会名}-{YYYY-MM-DD}.md`（存在则追加 `## ECHO 自动纪要` 一节）
     → 工作日志登记条目并链接该纪要文件
     → 按 `meeting-archive` 2.5 节规则，标记当日待办中对应的会议计划为完成
   - **② 命中既有专项/专题**（纪要内容明显指向某个已知专项）：
     → 纪要全文复制到 `{专项目录}/assets/{YYYY-MM-DD}_{标题}.md`
     → 专项目录 `项目日志.md` 追加进展记录
     → 工作日志登记条目并链接项目日志
   - **③ 以上都无法归类**：
     → 纪要全文副本存到 `02-会议记录/ECHO自动纪要/{YYYY-MM-DD}_{标题}.md`
     → 工作日志登记一条普通纪要条目

#### 0-C. 汇总结果

完成 0-A 和 0-B 后，记录以下计数供播报使用：
- 文件登记数（其中归入专项的份数）
- 会议归档数（其中归入例会的场数）

> **注意**：第 0 步是自动执行的，不需要用户确认。如果扫描过程中遇到异常（如脚本找不到、目录不存在），静默跳过，不要中断流程。

### 第 1 步：读事实，不要凭记忆

1. **笔记库根目录**：指令里的「笔记库根目录」；没给就用 `obsidian-worklog` 技能里记的那个。
2. **今天的日志**：`01-工作日志/YYYY-MM-DD.md`。**已存在就先 Read 再追加**，绝不覆盖。
   （注意：`01-工作日志/` 根目录下的文件才是当天日志；带月份的子目录如 `26年9月/` 是归档，不要往那里写。）
3. **昨天的日志**（`YYYY-MM-DD` 减一天）：**只看它底部的「待办」四个小节**，用于遗漏检查。
4. 需要时读 `02-会议记录/ECHO自动纪要/` 下**今天日期**的纪要 —— 当天开过的会也是当天的工作。
   **只看当天**，不要翻历史。

### 第 2 步：整理口述

按 `obsidian-worklog` 技能里定义的**日志格式**登记：

- 文件已存在 → 在 `# 上午` / `# 下午` 的**最后一条之后追加**，编号接续已有序号；
- 文件不存在 → 用完整模板（frontmatter + 上午/下午 + 待办四小节）创建；
- **时段判断**：12:00 前算上午，之后算下午；口述里明确说了时间的以用户为准；
- 一条工作 = 一个编号条目，条目下可以有缩进子项；
- **不要删除或重排已有条目**，只追加。
- **公式不要写成内联代码里的 `=…`**：Obsidian 的 Dataview 会把以 `=` 开头的内联代码当
  **内联 DQL** 求值，笔记里会渲染成 `PARSING FAILED` 红字（2026-10-15 用户实测 `` `=SUM(B3:B20)` ``）。
  写公式去掉等号（`SUM(B3:B20)`），或放进围栏代码块。

### 第 3 步：双向链接（有就挂，没有就别造）

若某条工作属于笔记库里的**既有专项**（对照 `obsidian-worklog` 的「专项工作目录的已知位置」表），
在条目下加一行 `[[专项工作目录/项目日志|项目日志显示名]]`，并按该技能的规范在项目日志里补一段
`> 相关工作日志：[[01-工作日志/YYYY-MM-DD|YYYY-MM-DD]]` 的倒序记录。

**判据**：目录**确实存在**才挂链接。宁可只登记工作日志，也**不要臆造专项目录**。

### 第 4 步：把待办写进底部小节

口述里出现的"后续安排/明天要做/待跟进"按类型填进对应小节：

| 内容类型 | 落到哪一小节 |
|---|---|
| 重点工作 | `#重点工作待办` |
| AI 相关 | `#AI待办` |
| 自动化 / 流程类 | 手册里对应的小节 |
| 对外输出（材料/汇报/文档） | `#对外输出待办` |
| 其它 | `#其它待办` |

**只追加，不清空已有条目**；已经明显办完的（口述里说了"做完了"）可以标注完成，但**不要删除**。

### 第 5 步：追问（这是本技能最容易被做差的一步）

**每轮只问一个问题。**问题从下面三处挑，按优先级：

1. **信息确认**：口述里有歧义、缺关键信息的地方。
   例：「供应商说的是本周还是下周到货？」「那份表填的是七月还是八月？」
2. **遗漏检查**（这是用户明确要的能力）：拿「昨天的待办」与「今天的口述」对照，
   找出**昨天挂着、今天既没提也没做**的事项问一句。
   例：「昨天记着要跟对方确认那件事，今天办了吗？」
3. **主动提醒**：口述里出现的时间点/承诺值得记一条待办。
   例：「你说的下周三交材料，我给你记进『对外输出待办』？」

**问完之后不要自问自答**，也不要列举"你可能还遗漏了 1、2、3"——那会变成念清单。

### 第 6 步：收尾

用户说「今天就这些」「回顾结束」或明显表示结束时：

1. 再核对一遍今天登记了哪些条目（**只读一遍文件确认，别重写**）；
2. 播报改成结束语，**不要再问问题**。

## 跨轮次：原始转写是唯一真相

指令里的 `【今日口述·原始转写】` 是用户的原话，**保留它、不要用你的改写覆盖它**。
用户后面说「回到第二段」「我刚才不是这么说的」时，要能对着原话回答。

同一天的多轮对话（用户补充、你追问、他再回答）都发生在**同一个会话**里，
所以"今天已经登记了什么"你能从上下文看到；不确定时**读文件确认**，不要凭上下文猜。

## 与其它技能的关系

- **`obsidian-worklog`**：日志格式、专项工作目录表、归档规范的**唯一权威**。本技能不重复定义，
  遇到格式/归属问题去读它。
- **`wecom-file-to-obsidian`**：文件扫描脚本 `scan_cache.py` 的调用者。本技能的第 0-A 步直接调用该脚本获取文件清单，但**登记逻辑由本技能自主完成**（不依赖该技能的快捷登记流程）。
- **`meeting-archive`**：会议纪要归档的判定流程与格式规范。本技能的第 0-B 步复用其归属判定逻辑（例会→专项→普通），但**不等待用户触发**，改为自动执行。
- **`meeting-record`**：会议录音开关。本技能**不调用**录音接口，只检查已生成的纪要文件。

## 已知边界

- 本技能**不负责**会议转写（那是会议模块的事）。
- 本技能**不负责**月度归档（那是 `obsidian-worklog` 的 D 节）。
- 用户在车里说的内容可能不完整、有口误。**宁可按原话登记 + 追问确认，也不要替他编**。
- 第 0 步的自动扫描**只处理当天**的文件和纪要，不翻历史。
- 第 0 步的自动登记**不覆盖**已有条目，只追加。若当天日志尚不存在，按完整模板创建。
- 文件扫描依赖 `scan_cache.py` 脚本，若脚本执行失败（路径不存在、Python 环境问题等），**静默跳过**第 0-A 步，不影响后续流程。
- 私有化企微（联通）依赖客户端把文件同步到本地缓存；客户端没登录/没打开时扫不到当天文件，属正常，**不要**因此判定脚本坏了。
- 会议纪要检查依赖 `02-会议记录/ECHO自动纪要/` 目录，若目录不存在，**静默跳过**第 0-B 步。
- 第 0-0 步的启动反馈播报**先于扫描执行**，ECHO 念完后才开始真正的扫描工作。若后续扫描全部失败（所有步骤都跳过），正式播报仍正常进行，只是结果为零。

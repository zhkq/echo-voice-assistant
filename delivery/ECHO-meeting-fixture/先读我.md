# 先读我 —— ECHO 真实会议测试夹具

给你一台**测试机**做端到端实测用的一份**真实会议录音**（不是合成样本）：29.6 分钟的多人会议，
用来验证「会议转写 + 说话人分离 + 能力后端」这条链路。

---

## 1. 包里有什么

```
ECHO-meeting-fixture\
├── 导入.ps1                     ← 在目标机上跑这一个脚本就完成导入
├── 先读我.md                    ← 本文件
├── meeting\2026-09-20_10-48-26\ ← 要导入的会议（只含音频与 meta.json）
│   ├── 01.wav  (10:00, 18.3 MB)
│   ├── 02.wav  (10:00, 18.3 MB)
│   ├── 03.wav  ( 9:37, 17.6 MB)
│   └── meta.json                ← 录音时的配置快照（引擎/分段/时长）
├── 参考-旧转写结果\             ← 只给对照用，**不会被导入**
│   ├── transcript.md            ← 这场会在源机器上的转写（**带说话人标注**）
│   ├── summary.md / topics.md / meeting_note.md
│   └── 说明.txt
└── 包内清单.txt                 ← 每个文件的字节数 + sha256（核对 54 MB 有没有拷坏）
```

音频规格：**16 kHz / 单声道 / 16-bit PCM WAV**，共 3 段（600 s + 600 s + 577 s = 1777 s ≈ 29.6 分钟），
54.2 MB。说话人：**多人会议**（源机器上那次分离出 5 个说话人：S1/S2/S3 说话最多，S4/S5 少量）。

> **旧转写结果**（含说话人标注）在 `参考-旧转写结果\`。导入脚本**不会**把它放进会议目录 ——
> 这样「重新转写」才是真的重跑一遍；它在这里只用于事后对比质量。

## 2. 目标机上怎么用（3 步）

**前提**：目标机已经装好 ECHO，且**跑起来过**（面板能打开）。

```powershell
# ① 把这个文件夹整个解压到任意目录，然后在里面跑：
powershell -NoProfile -ExecutionPolicy Bypass -File .\导入.ps1
```

脚本会：

1. 问**正在跑的 ECHO**（`GET /api/paths/env`）拿这台机器**真正生效**的三个路径：
   ECHO 代码目录、数据根（`echo.db` 所在）、会议目录；
   ECHO 没在跑时会回落到用本机解释器 `import app.paths` 现算 —— 两种布局都对：
   * 新布局：`<安装根>\meeting\`
   * 老（扁平）布局：`<数据根>\data\meetings\`
   * 面板里手工改过 `meetingsDir` 的，也按改后的来（脚本不写死任何路径）
2. 把 3 个 wav + `meta.json` 放进 `<会议目录>\2026-09-20_10-48-26\`（已存在且大小一致的会跳过）；
3. 用 ECHO 自己的代码路径（`app/db.py` 的 `create_meeting` / `update_meeting`，**不拼 SQL**）
   建一条会议记录，并当场用 `GET /api/meetings` + 取第 1 段音频复核一遍。

常用参数：

| 参数 | 用途 |
| --- | --- |
| `-DryRun` | 只报告会做什么，不动文件也不动库 |
| `-Port 18060` | 面板不在默认端口时 |
| `-EchoRoot D:\ECHO` / `-Python ...` | 自动发现失败时手工指定 |
| `-Force` | 已存在也重刷记录（并清掉本场转写行，便于再测一次） |
| `-Remove -Yes` | **删掉**这场测试会议（记录 + 音频目录） |

**幂等**：重复跑不会报错，也不会产生第二条记录（会议表 `name` 有 UNIQUE，脚本也会先查）。
脚本**不改任何设置**、**不碰别的会议**。

```powershell
# ② 面板 → 会议
# ③ 做完实验删掉：powershell -NoProfile -ExecutionPolicy Bypass -File .\导入.ps1 -Remove -Yes
```

## 3. 面板里怎么走

1. 打开面板（脚本最后会打印地址，一般是 `http://127.0.0.1:8970/`）。
2. 点左侧 **「会议」** 页签 —— 列表每 2 秒自刷一次，能看到：

   > **【测试夹具】真实会议 2026-09-20_10-48-26（约 29.6 分钟）** ｜ 状态 **「已中断」** ｜ `29:37` ｜ `3 段`

   「已中断」是**导入时的预期状态**，不是故障：它的含义是"有音频、没有可用的转写结果"
   （面板没有"待转写"这个状态；`transcribed` 会谎称已完成、`error` 又会被读成录音失败）。
3. 点这一场打开详情页 → 右上角 **「重新转写」**。

### 只验本机链路

直接点「重新转写」即可，用的是当前设置里的「会议转写引擎」（设置 → 语音与设备 → 模型）。

### 要验**能力后端**那条链路（本文重点）

在点「重新转写」**之前**：

1. 页签 **「能力后端」** → 卡片 **「会议转写服务」**；
2. 把 **「会议转写用哪个后端」** 选成 **「ECHO 后端」**；
   「会议产出」保持 **「全部」**（= 转写 + 说话人分离 + 声纹提取，三项一起跟着这个选择走）；
3. 同一页上方 **「ECHO 后端」** 那一节：填好后端地址、完成**配对**（两台机器要在同一内网）；
   「出网许可」**不能是「不出机」**（`none` 会把调用挡成 `blocked`）。
4. 回详情页点「重新转写」。

怎么确认这次**真的走了后端**（而不是悄悄回落本机）：

* 详情页转写上方的 **「这场会用了哪个后端」** 一行会显示 `转写 → ECHO 后端`，
  展开细节能看到"为什么没用别的"；
* 启动日志 / 日志页里会有 `source=meeting` 的 **「本场转写走能力后端（不加载本地模型）」**；
* 同一场的 `meta.json` 里会多出 `capability`（每个槽实际用了谁）与 `timestampsKinds`（时间轴档位）。

## 5. 大概要多久（后端那条是**估算**；本机那条是**实测**）

**问题**：「会议转写服务 = ECHO 后端」时，这 29.6 分钟要多长时间？

**依据（本机后端日志里的真实 RTF）**：`data/backend-dev/srv.err` 里 FunASR/SenseVoice 的记录是

```
rtf_avg: 0.003 / 0.004 / 0.007 / 0.010 / 0.011, time_speech: 30.000, time_escape: 0.118 ~ 0.304
```

即 RTF ≈ **0.003–0.011**（用户提供的引用值 **0.006**）。RTF 是"推理秒数 / 音频秒数"。

**换算**（RTF 取 0.006）：

* 纯推理：1777 s × 0.006 ≈ **11 秒**
* 加上每段的 VAD/前后处理（日志里 `time_escape` 每 30 秒样本 0.12–0.30 s → 3 段合计约 10–20 s）
* 加上首次请求的**模型冷加载**（SenseVoice 权重 0.9 GB，热起来约 5 s，冷启动几十秒）
* 加上 54 MB 音频走内网的上传（千兆 1–3 s，百兆 5–15 s）

**结论：后端已加载模型时，整场大约 1 分钟以内；冷启动或内网较慢时 1–3 分钟。**
（这是**按后端日志 RTF 换算的估算**，不是本次交付里的实测值；实际以你机器上的
后端日志 `rtf_avg` 与耗时行为准。）

### 对照：本机引擎（**这次是真测的**）

交付前在这台开发机（RTX 5060 Laptop + CUDA、`meetingSttModel=sensevoice`、
说话人分离**关闭**）上，用同一个夹具整场跑了「重新转写」：

| 阶段 | 实测（两次） |
| --- | --- |
| 点「重新转写」→ 模型加载完成 | 40 秒 / 60 秒（whisper small 骨架 + SenseVoice 权重，冷加载） |
| 3 段（600 s / 600 s / 577 s）转写 | 约 30–45 秒/段 |
| **合计（到 `status=transcribed`）** | **136 秒 / 181 秒（≈2 分 16 秒 ~ 3 分 1 秒）** |
| 产出 | 484 行（154 / 172 / 158）；`transcript.md` 36–37 KB |

另外一段 90 秒切片、**开着说话人分离**跑了一遍：模型已热，整段十几秒内跑完，
正确分出 2 个说话人（S1/S2，逐行标注）。

> 所以「本机大概多久」的量级是：**十几分钟以内、通常 2–5 分钟**（GPU 机器），
> 没有 GPU 的办公本会明显更慢。这一段是**实测**，与上面后端的估算不是同一台/同一条链路。

## 6. 怎么删掉这场测试会议

```powershell
# 推荐：脚本自己删（记录 + 音频目录），删除对象只有这一个会议名
powershell -NoProfile -ExecutionPolicy Bypass -File .\导入.ps1 -Remove -Yes
```

手工删也行，两步都要做：

1. **删记录**：`curl -X DELETE http://127.0.0.1:8970/api/meetings/<id>`
   （`<id>` 从 `GET /api/meetings` 里按 `name = 2026-09-20_10-48-26` 找；
   注意 ECHO 默认 `meetingKeepRawAudio=true`，**这一步不会删音频**）；
2. **删文件**：把 `<会议目录>\2026-09-20_10-48-26\` 整个删掉（省出 54 MB）。

面板的会议列表几秒内会自己刷新掉它。

## 7. 数据与隐私

* 这是**真实会议录音**，含真实说话内容（人名/项目名可能出现）。只在你自己的测试机上用，
  别上传到公网服务、别转发；测完按上一节删掉。
* 音频会**离开本机**——只要「会议转写用哪个后端」选了「ECHO 后端」，整段音频就会发到那台机器。
  要不要这么做由你定（这正是这个夹具要验的东西）。

## 8. 什么情况下这个夹具**不适用**

* **想验"面板里那个「导入录音」按钮"**：目前 ECHO **没有**这个功能，本包用脚本补这一步；
  将来真做了导入功能，这个脚本就不是那条路了。
* **目标机是 macOS**：`导入.ps1` 是 PowerShell，macOS 上请照 §3 的等价步骤手工做
  （把文件夹放进 `paths.meetings_root()` 指到的目录 + 在 `echo.db` 里建记录），或把脚本翻成 shell。
* **目标机的会议目录被设成不可写/网络盘**：脚本会在"放音频"那一步失败并说明（不会去改设置）。
* **目标机跑的是非常老的 1.x**（既没有 `app/paths.py` 的安装根概念、也没有 `/api/paths/env`）：
  脚本会走"离线探测"分支，需要你手工给 `-EchoRoot`；那种树能不能被这个夹具覆盖要另行确认。
* **想测"边录边转"或麦克风链路**：这条夹具只测**文件转写**（录音已结束的会），不涉及录音设备。
* **想测超长会议（>1 小时）或超多说话人（>10 人）**：这场的规模是 30 分钟 / 3 段 / 5 个说话人。
* **想压后端并发**：本包只有一场会；要压并发得复制多份（`-Name` 改个名，或把目录复制成新时间戳，
  同时别忘了数据库里也建对应记录 —— 直接跑本脚本导入复制出来的包即可）。

## 9. 排障

| 现象 | 先看什么 |
| --- | --- |
| 面板里**看不到**这场会议 | 脚本最后那几行：`GET /api/meetings` 里有没有它。没有 = 你导入到的**数据根**与面板那个 ECHO 用的不是同一个（多实例/多棵树很常见）。用 `-Port` 指对端口，或看 `GET /api/paths/env` 的 `DATA` / `MEETINGS` |
| 有记录、但音频 404 | 会议目录不是脚本写的那一个（改过 `meetingsDir`？）；脚本复核那一步会直接告诉你 |
| 点「重新转写」没反应/立刻失败 | 看 `GET /api/meetings/<id>` 的 `error` 字段与日志页：多半是"引擎用不了"或"后端不可用"—— 3.0 起这些原因都会写成人话（含下一步怎么办） |
| 转写完行数是 0 | 后端/引擎这条路确实失败了：日志里 `source=meeting` 有具体原因；本机引擎要确认模型已下载 |
| 说话人是空的 | 「会议产出」选成了「只要文字」，或分离那一槽没有可用后端（能力路由**不兜底**到本机，这是有意的） |
| 脚本挑错了实例（多实例/多棵树） | 端口发现顺序是 `-Port` → `$env:ECHO_PORT` → 候选安装根下的 `data\echo-port.txt` → `8970`，**谁先答就用谁**；`-Port` 不是隔离开关：它指的那个端口没在听时会继续往下试。要钉死目标，用 `-Port` 指对 + 清掉 `ECHO_PORT`，或直接 `-DataRoot` / `-MeetingsRoot` |
| 只想重刷、不想动转写结果 | 不加 `-Force` 就是幂等跳过（记录与文件都不动）；`-Force` 会重刷记录字段**并清空本场转写行**，便于再测一次 |

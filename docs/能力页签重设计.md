# 「能力」页签重设计：把模型 / 组件 / 能力 provider 三处合并成一处（2026-09-19）

> 起因（用户原话）：「设置中的能力 provider，模型和组件，设计上重叠，合并一个一级页签重新设计。」

## 1. 重叠在哪

改之前，同一件事散在**四个面**上：

| 面 | 位置 | 数据源 | 它回答的问题 |
|---|---|---|---|
| 原「模型」页签 | 顶部一级页签 | `/api/models`（`modelinfo.CATALOG`）+ `/api/stt/status` + `/api/voiceprints` | 用哪个本地引擎、装没装、怎么下 |
| 原「组件」页签 | 顶部一级页签 | `/api/components`（`components.catalog`） | 装没装、体积、获取方式（**纯表格，没有动作**） |
| 「能力 provider」卡片 | 设置页底部 | `/api/providers` + `/config` + `/presets` | 用哪个实现（本地/在线/路由）、出网吗、在线服务地址与密钥 |
| 「模型与引擎」兜底组 | 设置页（仅页签故障时） | `/api/settings` | 同上那 9 项的兜底编辑 |

四者合起来只有两句话：**「每个功能由什么实现」** + **「装好了没、怎么装」**。用户得在三个页签之间来回找，
而且同一份权重有两个读数（`modelinfo` 与组件清单各写一套探测规则），**分叉就会出现"组件说已装、模型说没装"**。

## 2. 改成一个一级页签「能力」

顶部页签：`模型` + `组件` → 合并为 **`能力`**（`#view-capabilities`，导航里排在「模型路由」之后）。
设置页的 provider 卡片**删除**，只留一句指路（模型相关项照旧在页签故障时回退到设置页）。

页面结构（一眼一层，不用跳页签）：

```
能力                                    组件就绪 x/y      [一键下载缺失] [刷新]
  概览条：语音转写 <当前实现> · 语音合成 <当前实现>

┌ 🎤 语音转写 ────────────────────────────────────────────────
│  [本地转写引擎（本地 · 已就绪） / 在线转写（OpenAI 兼容）（出网 · 未就绪）▾] ⚠
│  ┌ 在线服务（选中在线实现时展开）：地址 / 模型名 / 密钥 + 预设一键填 + [保存在线服务设置]
│  本地引擎   [命令转写 ▾]  [会议转写 ▾]
│  可装的本地模型  组件 | 状态 | 体积 | 用途 | 获取（下载 / 复制命令 / 官方链接）   ← 当前用的那行标「▶ 当前」
├ 🔊 语音合成 ────────────────────────────────────────────────
│  [自动（优先 edge-tts，失败回退离线） / edge-tts（微软在线）（出网 · 已就绪） /
│   本机离线合成（sapi）（本地 · 已就绪） / 关闭朗读（不出声）▾] ⚠
└ 其他功能卡：唤醒 / 说话人分离 / 声纹 / 计算设备（沿用原来的功能卡渲染）

🧱 运行环境：运行时核心 / CUDA 加速 / DSH 智能体后端（pip 类，给「复制安装说明」）
   不适用本平台的组件**显示但标注原因**（D24）
```

**语言模型不在这里**（2026-09-19 用户要求整合）：它的"用哪个实现"（ECHO AUTO 多上游派发 /
在线 LLM）与路由的上游配置本来就是同一件事 —— 那块渲染在 **「模型路由」页签最上方**（通道设置
之前），复用同一套渲染函数（`capProviderBlock("llm")`：状态并在下拉选项里、出网三角图标、
在线服务地址/模型/密钥 + 预设）。两个页签共用一份 provider 数据（`ensureProviderData`），
改完实现只刷新当前正在看的那一页（`refreshAfterProviderChange`）。

要点：

* **每个能力只出现一次**：转写模型只在转写卡里、只在 ASR 的组件表里；不再有第二处列表。
* **"用哪个"与"装什么"同屏**：先选实现，紧接着就能看到它缺什么、怎么装。
* **状态只写一次**：并进下拉选项文字（名字 + 出网/本地 · 就绪），不再另起"当前 XXX"行。
* **出网提醒收成黄色三角图标**：贴在下拉右边，悬停看说明（原生 `title`）；不出网时什么都不显示。
* **TTS 不造新开关**：它的"用哪个"就是设置里的 `ttsEngine`（含 `off` = 关闭朗读），
  页签里那个下拉直接写这个键，`providerTts` 已弃用 —— 一个功能一个开关。

## 3. 后端只做了一件事：让"装没装"只有一个判据

`app/components.py` 的模型类组件新增 `model_id`（指向 `app/modelinfo.py` 的条目），
`_detect()` 遇到 `model_id` 就直接问 `modelinfo.ready(model_id)`（新增的公开函数）。
这样：

* 组件清单的"状态"与模型清单的"就绪"**不可能再分叉**（`tests/test_components_alignment.py` 钉住）；
* 面板拿 `model_id` 就能给「下载」按钮（`/api/models/download` 只认 modelinfo 的 id），
  不必再维护第二份 id 映射表。

`/api/models`、`/api/components` 两个端点都保留（1.x 兼容 + 各自的语义：装什么 / 怎么下）。

## 4. 怎么验证

```powershell
# 打开能力页签要看的东西（源码断言，本仓库没有前端单测框架）
.\venv\Scripts\python.exe -m unittest tests.test_providers tests.test_settings_wiring tests.test_components_alignment -v

# 门禁五项（编译 / 导入 / 平台契约 / 全量单测 / ruff）
powershell -ExecutionPolicy Bypass -File scripts\check-windows.ps1
```

钉住的接线（`tests/test_providers.py::PanelWiringTests`）：

1. 顶部**只有一个** `data-view="capabilities"`，且 `loadCapabilities()` 在切页签时被调用；
2. 旧的两个页签挂载点（`providersHost` / `componentsHost`）与 `loadProviders()` / `loadModels()` 都不许再存在；
3. 页签自己承载编辑：`data-provider-kind`（ASR 的实现选择）、`data-tts-engine`（TTS 唯一开关）、
   `data-cap-save`（在线服务保存）、预设一键填；
4. `CAP_KINDS = ["asr","tts"]` + `capCompTable` / `renderCapEnv`：每个能力都能同时看到"用哪个/装没装"；
5. **语言模型那块在「模型路由」页签里**（`#rtLlmHost` 排在通道设置之前、`loadRouter()` 会一并渲染、
   复用 `capProviderBlock("llm")`），能力页签不再有语言模型卡；
6. 状态只在下拉选项里说一次（`capOptLabel` / `capTtsOptionLabel`），出网提醒是图标 + `title`
   （`capEgress` / `capEgressIcon` + `cursor:help`），整行文案不许再出现。

对齐测试（`tests/test_components_alignment.py`）：模型类组件必须有 `model_id`，且
`components.catalog()` 的就绪值 == `modelinfo.ready(model_id)`。

## 5. 已知遗留

| 项 | 说明 |
|---|---|
| 「启动」页签的组件列表 | 那是**服务**（server/stt/tts/dsh/路由）的启停状态，与"可安装组件"不是一回事；命名上容易混，待改名区分 |
| 在线实现的活体端到端 | 仍只做了 stdlib 假上游（无外网、不动用户密钥），与 P5 的记法一致 |
| `dsh-failover/` 物理搬迁 | 仍与 P4 组件布局一起做（见 PROGRESS §42） |
| mac 侧未实测 | 能力页签的路由基于已有的 `/api/components` 平台过滤，mac 上应只少 CUDA；未在 mac 上跑过 |

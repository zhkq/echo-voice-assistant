## 二、本轮修掉的三条（含测试）

### 1. 说话人分离的**下载落点**（你点名的那条）

`scripts/install_pyannote.py` 把落点写死成 `MODEL_ROOT = <安装根>/models/pyannote`，
而就绪判据 `modelinfo.ready_pyannote()` 查的是**可配置的** `models_dir()`（`modelsDir`）。
默认值相同时看不出来，**一旦用户在技能第 1 步填了"模型放哪"，就会下到 A 地、查 B 地** ——
装完永远显示未就绪。

修法：新增 `model_root()`，**与就绪判据同源**（`app.paths.models_root()` + `"pyannote"`），
`download()` 与 `complete()` 都改用它；`complete()` 的默认根也改成运行时解析。
注意 `scripts/` 下直接运行时 `sys.path[0]` 是 `scripts/`，所以函数里自己把 ECHO 根塞进 `sys.path`，
否则 `import app` 会失败、悄悄退回兜底路径（那就等于没修）。

测试：`tests/test_pyannote_install.py` 新增"落点跟随 `modelsDir`"与"写与查同源"两例。

### 2. B2：本机回环调用被系统代理劫走（**静默失效**）

新增 `app/netlocal.py`：

* `is_loopback(url)` —— `127.0.0.0/8`、`localhost`、`::1` 全认；
* `urlopen()` —— 按 URL 分派：回环走**无代理 opener**，外部地址**仍走系统代理**
  （企业网里访问 PyPI/ModelScope 往往正需要它，不能一刀切）；
* `ensure_no_proxy_env()` —— 把回环地址补进 `NO_PROXY`/`no_proxy`，给子进程与
  requests/httpx/huggingface_hub 兜底（已有的域名不丢）；
* `install_loopback_bypass()` —— 进程启动时装一次**全局转发**。

为什么用全局转发而不是逐个改调用点：仓库里有 **10 处** `urlopen` 直接打 `127.0.0.1`
（面板自查、模型路由探活、harness/DSH 适配器…），逐个改既慢又**必然会漏**（以后新加的又忘）。
`app/main.py` 在 import 阶段就装上（越早越好）。

> Windows 上有个必须知道的细节：`urllib` 的 `proxy_bypass` 读的是**注册表**里的 ProxyOverride，
> **光设环境变量并不保证绕过** —— 这就是为什么主要手段是"显式无代理 opener"，环境变量只是兜底。

测试：`tests/test_netlocal.py`（12 例）：回环/外部分派、无代理 opener 里没有非空代理、
`NO_PROXY` 幂等且不覆盖已有值、全局开关可装可撤、`Request` 对象也认。

### 3. B1：桌面快捷方式启动找不到 node

* **平台接缝**新增 `node_dirs()`（win32：托管式 WorkBuddy → nvm → 官方安装包；darwin：Homebrew/volta/nvm；
  linux：/usr/local/bin 等），`app/platform/__init__.py` 给中立访问器；
* `app/harness_proc.py` 新增 `find_node_dir()` / `ensure_node_on_path()`，
  在 `ensure_running()` **最开头**调用。

关键点（同事自己排查出来的）：`shutil.which("npx")` 读的是**本进程**的 `os.environ`，
早于给子进程准备的那份 env —— **只在 Popen 前构造 env 完全没用**。
在 `env = dict(os.environ)` 之前改，子进程顺带也继承到。

测试：`tests/test_harness_node_path.py`（8 例）：探测跳过没有 npx 的目录、幂等注入、
找不到就不动 PATH、`_argv()` 能解析出绝对路径。本机实测接缝探到
`C:\Users\zhkq\.workbuddy\binaries\node\versions\22.22.2-3`（正是同事报的那种托管 node）。

## 三、最该接着做的一条：B5（同事列为 P0）

| 启动方式 | 就绪耗时（同事实测） |
|---|---|
| `npx -y @deepseek-ai/dsh web` | **2 分以上**（1403 行 `npm warn cleanup`） |
| `node <本地 bin.js> web` | **9 秒 / 9 秒** |

建议按同事的方案把默认改成"**本地永久安装 + 绝对路径直连**"，npx 只当兜底：

1. 技能脚本 `Prepare-Agent`：现在是"`npx -y @deepseek-ai/dsh --version` 预热"，
   改成 `npm install @deepseek-ai/dsh@<版本> --no-audit --no-fund` 到 `<dest>\harness\dsh`；
2. 自检 `package.json` / `lib/index.js` / `prebuilds/win32-x64/conpty.node` 齐全（B4 的坑）；
3. 写 `harnessCommand = "<node 绝对路径>" "<…>\lib\bin.js" web`（ECHO 会自己追加 `--port/--no-open`）；
4. npx 预热仅作为兜底路径保留。

顺带的收益：绝对路径写法同时绕开 B1（PATH）与 B3（shim）—— 这两条本轮虽已从产品侧兜住，
但安装侧改成直连仍然更稳。

另需注意的两个"安装侧纪律"：**npx/npm 阶段禁止中途强杀**（B4 就是这么来的）；
**安装完成仍要 `POST /api/install/report`**（否则面板会一直提示"还没装完"）。

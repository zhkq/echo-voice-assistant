# 每日回顾 —— 前端开发计划（2026-10-06 夜）

> 用户的要求（原话）：
> *"仪表盘要有一个回顾卡片，会议历史后面要增加一个回顾历史页签"*

## 0. 现状（已有什么，先摸清再动手）

| 层 | 已有 | 说明 |
|---|---|---|
| 设置 | 10 项 `dailyReview*` | `enabled` / `vaultRoot` / `broadcastChars` / `prompt` … |
| 逻辑 | `app/daily_review.py` | `enabled/ready/status/start/submit/stop`、`extract_broadcast`、`build_prompt`、`ensure_session` |
| 接口 | `GET /api/daily-review`、`POST /{start,submit,stop}` | 状态 + 起停 + 提交转写 |
| 语音 | `app/assistant.py` 的回顾模式 | `_review_speak()` 把 `【播报】` 读出来（≤2 句 + 1 问） |
| DSH | 技能 `~/.dsh/skills/daily-review/SKILL.md` | 整理进 Obsidian 工作日志 + 反查遗漏 + 追问 |
| 前端 | **Settings 里一张小卡**（`setReviewHost`） | 只有状态与起停。**仪表盘与历史页签都没有** |
| 登记 | `dsh_sessions` 表 `kind='review:YYYY-MM-DD'` | 每天一条（UNIQUE 约束逼出来的设计） |

**回顾的产物落两处**：ECHO 侧（语音转写 + 播报原文）、Obsidian 侧（工作日志条目，由 DSH 写）。

## 1. 数据从哪来（"回顾历史"的关键决定）

三个候选：

| 来源 | 好 | 坏 | 判 |
|---|---|---|---|
| DSH 会话文件 `~/.dsh/sessions/**/session.v4.jsonl.zstd` | 有完整对话 | **zstd 压缩的 jsonl**，要解压+解析；单文件 0.7~1.5 MB；格式是 DSH 内部实现，会变 | ✗ |
| Obsidian 工作日志 | 是最终成果 | 只有整理后的条目，**没有"我说了什么"**；且要解析 Markdown | 用作"打开原文"的链接 |
| **ECHO 自己的库** | 转写与播报**本来就经过 ECHO**；结构化、快、可查询 | 与 vault 有信息重叠 | **✓ 用它做索引与原文** |

**决定：ECHO 侧落一张 `daily_reviews` 表**，每次回顾完成时写一行：

```
id | date(YYYY-MM-DD) | created_at | transcript | broadcast | session_id | vault_note | ok | detail
```

* `date` + `created_at` → 历史列表（按天倒序）
* `transcript` / `broadcast` → 详情页的"我说了什么 / 播报了什么"
* `session_id` → 需要时能继续那条 DSH 会话
* `vault_note` → 当天工作日志的路径（**点一下能在资源管理器/Obsidian 打开** —— 那才是最终成果）

这样"回顾历史"页签 = 一张表 + 一个详情，**不依赖 DSH 内部格式**；而成果仍在 vault 里（单一事实源不变）。

## 2. 三个界面各自要什么

### 2.1 仪表盘「每日回顾」卡片

> 仪表盘 = 「常规」页顶部的状态格（`renderDash`），已有「后端：本机 / Agent：DSH标准版 / 语音合成：在线」那三格。

卡片要说清四件事，每件都要有**可点的下一步**：

```
每日回顾   [今天已回顾 / 今天还没回顾 / 未启用]
  最近一次：10-05 22:14 ·「今天主要在处理后端归属与端口统一…」（12 字摘要）
  [现在开始]  [看历史 →]
```

* **未启用** → 说"去设置里打开"（`data-goto` 到设置）
* **今天已回顾** → 显示今天那次的时间与播报摘要，入口是"看历史"
* **今天还没回顾** → 「现在开始」按钮（走已有的 `POST /api/daily-review/start`）
* **vault 没配** → 明确说"笔记库还没配，回顾只能记在 ECHO 里"（`ready.reason` 原文）

### 2.2 「回顾历史」页签（会议历史之后）

页签顺序：`… 指令历史 | 会议历史 | 回顾历史`。

* **列表**：按天倒序。每天一行：`日期 · 时间 · 播报摘要 ·（有日志 ↦）`
* **详情**：点开显示
  * 我口述的原文（`transcript`，保留换行，等宽小字）
  * 播报原文（`broadcast`）
  * 「打开工作日志」按钮（`vault_note` 存在时）
  * 起止时间、DSH 会话 id（可复制，排障用）
* **空态**：说清"还没有回顾记录，去仪表盘那张卡开始一次"

### 2.3 Settings 里那张小卡

保留（它管"启用/停用/测试"这类**配置动作**），但**不再重复状态展示** —— 状态归仪表盘那张卡，
这里只留一个「去看历史」的链接，避免又出现"同一件事两处说"。

## 4. 纪律（自己盯住，别忘）

* **不碰用户数据**：`daily_reviews` 是新表，不迁移/不改动既有表；vault 只读（点"打开"是 shell 的事）。
* **改前端就跑真渲染冒烟**（`tests/test_panel_renders.py`）—— 今天三次"静态查不出"的教训。
* **`.js` 改完 `node --check`**、`.html` 改完验标签配平（`tests/test_js_syntax.py`）。
* **一次替换改多处时，改完回读那段**（今天的 `}}` 就是这么进去的）。
* 提交信息写清**真因**与**判据**；门禁绿了才提交。
* 出包顺序：`build_kit.py` →（`--check` 绿）→ `build_backend_portable.py` → `build_delivery.py`。

## 5. 明确**不做**的（避免夜里跑偏）

* 不做"从 DSH 会话文件回读对话"（内部格式、会变、要 zstd）。
* 不做"回顾内容反向编辑"（整理是 DSH 技能的事，ECHO 只呈现与索引）。
* 不新增设置项（除非实现中真缺一个——那也要写进这份文档并说明为什么）。

# ECHO 新机器部署指南（同事版）

> 目标：在你的 Windows 电脑上把 ECHO 跑起来（语音命令 + 会议录音转写纪要 + 控制面板）。
> 预计耗时：**拷贝 15–40 分钟（取决于传输方式）+ 配置 10 分钟**。
> 交付包由周克勤提供（一个 `ECHO` 文件夹），本文按"整包拷贝"路线写；只想拿代码自己装环境的见 [附录 B](#附录-b从零重建环境不推荐)。

---

## 0. 你需要准备什么

| 项目 | 要求 | 说明 |
|---|---|---|
| 系统 | Windows 10 / 11 64 位 | ECHO 依赖 Windows 的媒体键钩子、SAPI、ctypes |
| 磁盘 | **≥ 25 GB 空闲** | venv ≈7.1 GB + 模型 ≈1.8 GB，录音数据另算 |
| 麦克风 | 任意 | 面板设置里可选设备 |
| DSH Desktop | **必备** | 语音命令执行 + 会议纪要生成的底层；见 [§5](#5-接上-dsh-desktop执行引擎必须) |
| NVIDIA 显卡 | 可选 | 有则转写快 5–10 倍；没有也能跑（CPU 模式，慢一些） |

不需要：Python、Node、git、CUDA 工具链（venv 里都带好了）、联网（拷贝路线全程离线）。

## 0.5 一键安装（推荐，同事拿到交付包后的最快路线）

> 交付包会带一个**一键安装向导**：`install.bat`（双击入口）+ `install.ps1`（向导本体）。
> 把它俩和 `ECHO-交付包-YYYYMMDD.zip` 放在**同一个文件夹**里，然后双击 `install.bat` 即可——
> 全程 8 步自动完成：环境/磁盘检查 → 自动找 zip → 选安装目录 → 解压 → venv 初始化建库 → 自检 → 桌面快捷键 + 开机自启 → DSH 检测提示。

**双击 install.bat，跟着提示走就行**（默认装到 `D:\ECHO`，纯英文路径，正好避开 §2 说的坑）。

想自定义，也可以在 cmd / PowerShell 里带参数跑：

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1 -DestDir "E:\ECHO"
```

| 参数 | 作用 | 默认 |
|---|---|---|
| `-Zip <路径>` | 指定交付包 zip | 自动找同目录 `ECHO-*.zip` |
| `-DestDir <目录>` | 安装到哪 | `D:\ECHO` |
| `-DryRun` | 模拟模式，只预览不写系统 | 关 |
| `-Silent` | 无人值守，全部取默认值 | 关 |
| `-SkipSetup` / `-SkipDesktopLnk` / `-SkipStartupLnk` / `-SkipDshCheck` / `-SkipStart` | 跳过对应步骤（重装自愈用） | 全执行 |

安装器会自动做掉原来手工的 §2（纯英文路径/磁盘空间检查）、§3（解压 + `new-machine-setup.ps1` 初始化建库）、§4（快捷方式/开机自启、启动）。装完会打印下一步建议（面板设置里的计算设备选 `cpu`/`cuda` 等）。

> 不用手动去执行文档里的 `tar -xf`、`new-machine-setup.ps1` 这些命令了，安装器内部都包好了；遇到问题再看下面的详细说明。
> 日志：`%TEMP%\ECHO-install.log`。

## 1. 先把包拿到手（源机器操作）

### 推荐：整包拷贝（含 venv + 模型）

在源机器上打包（**不含** `data\`（含源机器的会议录音与历史）、`.git\`、以及用不到的冗余模型）：

```powershell
$src = 'C:\Users\<你的用户名>\Desktop\学习\ECHO'
$dst = 'D:\ECHO-transfer\ECHO'
robocopy $src $dst /E /MT:16 /NFL /NDL /NJH /NJS /NP /XD `
  "$src\data" "$src\.git" "$src\models\hub" `
  "$src\models\faster-whisper\medium" "$src\models\faster-whisper\large-v3" `
  "$src\models\pyannote\faster-whisper-base" "$src\models\pyannote\faster-whisper-small" `
  "$src\models\pyannote\faster-whisper-medium" "$src\models\pyannote\faster-whisper-large-v3" `
  "$src\models\pyannote\sherpa-onnx-streaming-zipformer-bilingual-zh-en-2023-02-20"
```

实测结果：**约 8.8 GB / 6 万个文件**（其中约 7.1 GB 是 venv）。

> 传 6 万个小文件时，局域网共享直接拖拽很慢，**建议先压成一个 zip 再走移动硬盘或网盘**。
> 用系统自带 tar 打包（`Compress-Archive` 在 WinPS 5.1 上压 >2GB 的包会失败）：
> ```powershell
> tar -a -c -f 'D:\ECHO-transfer\ECHO.zip' -C 'D:\ECHO-transfer' ECHO
> ```

### 如果你拿到的是现成的 zip 包

交付包名形如 `ECHO-交付包-YYYYMMDD.zip`（解压后约 8.8 GB）。解压到 `D:\`，就会得到 `D:\ECHO`：

```powershell
cd D:\
tar -xf "$env:USERPROFILE\Downloads\ECHO-交付包-20260912.zip"
```

或用 7-Zip / WinRAR 右键解压。**别用资源管理器双击解压**：6 万个文件的大 zip 容易卡死或中途报错。

### 完整清单（含哪些、不含哪些）

| 目录 | 体积 | 拷不拷 | 用途 |
|---|---|---|---|
| `app\` `web\` `assets\` `scripts\` `docs\` `.dsh\` | ~6 MB | ✅ | 代码、面板 SPA、脚本、DSH 技能 |
| `venv\` | 7,259 MB | ✅ **必须** | Python 3.11.15 + torch(cu128) + funasr + sherpa-onnx + pyannote 全套装好 |
| `models\faster-whisper\base` + `small` | 605 MB | ✅ | whisper 转写（`small` 是默认） |

## 2. 放到纯英文路径（很重要）

```
✅ D:\ECHO          ✅ C:\ECHO
❌ D:\学习\ECHO     ❌ D:\我的软件\ECHO
```

原因：**funasr（SenseVoice）和 nagisa/dynet 无法读取含非 ASCII 字符的本地路径**，中文路径下 SenseVoice 会加载失败、转写直接不可用。源机器是靠一个 ASCII junction（`C:\Users\<你>\.echo-venv`）绕过去的，你**不要**建那个 junction，直接把 ECHO 放在英文路径下就没这问题。

> 顺便：`venv\` 里的基础解释器路径写死在 `venv\pyvenv.cfg` 里（指向周克勤机器上的 Python），所以**放好后必须跑第 3 步**。

## 3. 一键初始化（关键一步）

```powershell
cd D:\ECHO
powershell -ExecutionPolicy Bypass -File scripts\new-machine-setup.ps1
```

脚本做四件事：

1. `[1/4]` 检查/修正 `venv\pyvenv.cfg` 的 `home` 指向（本机没有那个 Python 就会 `Fatal Python error: init_fs_encoding`）——会自动找到你机器上的 Python 3.11（`%APPDATA%\uv\python\...` 或 `py -3.11`），找不到就用 `uv python install 3.11.15` 装一个；改前自动备份为 `pyvenv.cfg.bak-*`。
2. `[2/4]` 校验 venv（Python 版本、fastapi/uvicorn/pydantic、torch 是否可用/是否认到 GPU）。
3. `[3/4]` 跑 `scripts\setup.ps1`：补装轻量依赖 → 校验模型齐全 → 建库 `data\echo.db`。
4. `[4/4]` 打印后续步骤。

**手工等价做法**（不想用脚本时）：

```powershell
winget install --id astral-sh.uv -e     # 或 pip install uv
uv python install 3.11.15
# 然后把 venv\pyvenv.cfg 里的 home 改成：
#   home = C:\Users\<你的用户名>\AppData\Roaming\uv\python\cpython-3.11.15-windows-x86_64-none
```

两个必须记住的坑：

- **`setup.ps1` / `start.ps1` 必须在 ECHO 根目录下执行**（脚本自己不会切目录，否则报 `No module named app`）。桌面快捷方式不受影响。
- **装依赖一律用 `python -m pip`**，不要用 `venv\Scripts\pip.exe`（exe 里写死了源机器的绝对路径）。

## 4. 启动

```powershell
cd D:\ECHO
powershell -ExecutionPolicy Bypass -File scripts\start.ps1              # 前台（调试用，Ctrl+C 停）
powershell -ExecutionPolicy Bypass -File scripts\start.ps1 -Background  # 后台隐藏
powershell -ExecutionPolicy Bypass -File scripts\stop.ps1               # 停止
```

日常用法（推荐）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install-desktop-shortcut.ps1   # 桌面一键启动（后台 + 开面板）
powershell -ExecutionPolicy Bypass -File scripts\install-autostart.ps1          # 开机自启（-Remove 卸载）
```

面板地址：**http://127.0.0.1:8970** （只监听本机 loopback，局域网内别人访问不到，这是设计如此）。
默认端口就是 8970；如果这个端口落在 Windows 的动态保留段里会 bind 失败（`[Errno 13]`），
在 设置 → 通用 → ECHO 面板端口 换个值（如 `18060`）再重启即可。**权威端口是 ECHO 启动时写出的
`data\echo-port.txt`**（源机器就是因为这个原因改成了 18060），别把 8970 当成写死的。

## 5. 接上 DSH Desktop（执行引擎，必须）

ECHO 自己不做推理：语音命令和会议纪要都交给**本机的 DSH Desktop**（默认 `http://127.0.0.1:43120`）执行。

> ⚠️ **"本机 DSH"不等于"数据不出网"**：DSH 只是个壳，它会把指令文本与会议转写**转发给配置好的模型服务**——
> 内网网关＝贵单位内网，公网 API＝模型厂商服务器。另外**默认的语音合成 edge-tts 是微软在线服务**。
> 逐项见下面的「5.5 本地 / 联网对照」。

1. 安装并启动 **DSH Desktop 2.x**。
2. 打开**普通浏览器访问**：DSH Desktop → 设置 → 常规；或改 `%USERPROFILE%\.dsh\settings.yaml`：
   ```yaml
   dsh-desktop:
     mode: compatibility   # 兼容模式
     openBrowser: true     # 允许普通浏览器/本机程序访问
   ```
3. 确认凭据文件存在：`%USERPROFILE%\.dsh\.credentials.yaml`（ECHO 靠它自铸签名 Cookie 调 DSH API，缺失就报 401）。
4. 在 ECHO 面板 → 仪表盘 → **DSH 执行引擎 → 检查**，显示正常即可。

**托管插件（echo-host，可选）**：让 DSH Desktop 启动时自动拉起/守护 ECHO，并在 1 号屏右缘提供 `Ctrl+Shift+E` 仪表盘边条。交付包已带源码 `plugin\echo-host\`，部署一条命令：

```powershell
cd D:\ECHO
powershell -ExecutionPolicy Bypass -File scripts\install-echo-host-plugin.ps1
```

脚本把插件复制到 DSH 安装目录的 `resources\app.asar.unpacked\echo-host\`，并往 **Profile 补丁层** `%USERPROFILE%\.dsh\profiles\<活动 profile>\cordis.patch.yml` 写注册行（标记块 `# >>> echo-host plugin ... >>>`），最后用 DSH 自带 loader 离线校验（补丁能否解析、行是否进树、入口是否存在、模块能否 import），校验不过直接报错，不会拖到下次启动才炸。**重启 DSH Desktop 后生效**；卸载加 `-Uninstall`。

## 5.5 本地 / 联网对照（哪些数据会出网）

**"本地部署"说的是 ECHO 这一侧的转写与存储在机器上，不代表数据不出网。** 逐项：

| 功能 | 执行位置 | 数据去向 |
|---|---|---|
| 命令/会议转写、唤醒词、说话人分离 | **本机**（SenseVoice / Whisper / Qwen3-ASR / sherpa-onnx / KWS / pyannote） | 不出网 |
| 录音、转写、纪要文件、数据库 | **本机** `data\`（wav + md + echo.db） | 不出网 |
| **会议纪要 / 议题分段** | 本机发起，**推理在 DSH 所连的模型服务** | **转写全文发往该服务** |
| **指令执行** | 同上（DSH 会话 + 技能） | **指令文本与上下文发往该服务** |
| **语音播报（TTS）** | 默认 `ttsEngine=auto` → 先试 **edge-tts（微软在线，需 `speech.platform.bing.com`）**，失败降级 Windows SAPI | **播报文本发往微软** |
| 纪要归档（委派给技能） | 本机（DSH 会话 + 技能） | 由技能决定（写本地笔记库＝不出网） |
| 模型下载 | 本机（ModelScope / hf-mirror） | 只下载权重，不上传数据 |

**要"全程不出网"**：① 设置 → 语音命令 → 语音合成引擎改 `sapi`（或 `off`）；
② DSH 的 provider 指向本机/内网模型服务（没有本地大模型时这条满足不了，等于"纪要/执行"必然出网，
请据此判断会议内容能不能交给那个服务商）；③ 关掉「会议 → 自动生成纪要」，需要时手动生成。


> ⚠ **要写进哪个 profile**：Desktop 只组合它**当前活动**的那个 Profile。脚本会自动读 `%APPDATA%\DSH Desktop\profile-selection\state.json` 的 `active`（本机是 `web`，不是 `desktop`），并为活动 profile 与 `desktop` 各写一份。手工改时先确认这个字段。
>
> ⚠ DSH Desktop **2.0.9 不再读取** `app.asar.unpacked\cordis.patch.yml`（2.0.5 会读）——2026-09-12 由 2.0.5 升到 2.0.9 时插件"静默消失"就是这个原因。注册行因此放在 Profile 补丁层；该层只在 Desktop 启动时组合，**必须重启 DSH Desktop**。`scripts\launch-desktop.ps1` 与 `scripts\start.ps1` 每次启动都会自动补装（自愈），升级后启动一次 ECHO 即可，也可手动重跑上面的命令。
>
> ⚠ 补丁文件里别写非 ASCII 注释：Windows PowerShell 5.1 会把无 BOM 的 UTF-8 当 ANSI 读回，行会读串、YAML 直接坏掉。

> 已知遗留：`scripts\launch-desktop.ps1` 里还按旧版端口 3080 探测 DSH（实际是 43120），因此"自动拉起 DSH"这一步实际是空操作——**DSH Desktop 请自己启动**，不影响其他功能。

## 5.6 模型路由（ECHO AUTO，可选）

ECHO 里带了**本机模型路由**（`dsh-failover\`，只监听 `127.0.0.1:8899`，端口可用 `config.json` 的 `port` 改）：把多个上游
（内网网关 / 官方 API / 任意 OpenAI 兼容端点）组成「模型组」，**按通道号顺序派发**，
前面的通道连不上、首字节超时或返回 401/429/5xx 时自动改走下一个。

**怎么用（三步，不用改 JSON）**：

1. ECHO 启动时会自动拉起路由，并把它注册成 DSH 的本地 provider `echo-auto`
   （写 `%USERPROFILE%\.dsh\settings.yaml`，幂等，可重复执行；设置里可关自动注册）。
2. 在 **DSH Desktop** 里把模型切成 **ECHO AUTO** —— 之后 DSH 的所有调用都经本机路由派发。
3. 在 ECHO 面板顶部 **模型路由** 页签里管理：列表顺序 = 通道号 = 派发顺序，每条通道一个
   可改的昵称；可开关通道、点「立即探测」、看「派发情况」（累计派发 / 失败 / 成功率 /
   各通道命中）。仪表盘小卡片与右缘折叠条的路由灯显示的都是**当前在服通道的昵称**。

| 项 | 说明 |
|---|---|
| 命令行 | `powershell -File dsh-failover\start.ps1` / `stop.ps1` / `status.ps1`；自检 `python dsh-failover\check.py --call` |
| 配置 | `dsh-failover\config.json` 的 `groups`（成员、顺序、超时、熔断阈值）；改完可点面板「重载配置」热生效 |
| 凭据 | `config.json` 里**只写凭据名字**（如 `DEEPSEEK_API_KEY`），真实值在 `%USERPROFILE%\.dsh\.credentials.yaml`，**不要把密钥写进 config.json** |
| 端口 | 8899 只监听回环，且与 8970 一样装了来源守卫（见 §7.5） |
| 不装会怎样 | 不影响语音命令、转写、会议纪要任何功能；只是 DSH 里没有 ECHO AUTO 这个模型可选 |

> ⚠ **源机器的 `config.json` 里是公司内网成员**（内网网关地址、`userId` 等属于个人环境）。
> 别人拿到包后应当把成员换成自己的上游：面板 → 模型路由 → 添加成员（下拉里是 DSH 里
> 已配置的模型），或直接改 `config.json`。故障表里"模型路由显示失败（提示脚本缺失）"
> 指的就是这种情况，属正常现象。

## 6. 面板里要改的设置

打开 http://127.0.0.1:8970 → **设置**：

| 分组 | 设置项 | 改成 | 为什么 |
|---|---|---|---|
| 会议 | 会议纪要工作区 | `D:\ECHO` | 默认值指向源机器路径，会议纪要 DSH 会话的工作区要用本机路径 |
| 通用 | 计算设备 | 无 N 卡 → `cpu` | `auto` 会优先试 CUDA，无卡时回退 CPU；显式设 `cpu` 可少一次报错 |
| 通用 | ECHO 面板端口 | 冲突时改（如 `18060`） | 默认 8970；落在系统保留段会 bind 失败，改完重启服务；权威值见 `data\echo-port.txt` |
| 通用 | 用户所在地 | 你的城市 | 影响天气/时间类问答 |
| 语音命令 | 唤醒热键 / 回退热键 | 默认 `Ctrl+Alt+C` / `Ctrl+Alt+V` | 与其他软件冲突时改 |
| 语音命令 | 命令转写引擎 | `sensevoice`（默认） | 最快；`qwen3asr` 更准但要额外下 ~1.5GB 模型（`scripts\install-qwen3asr.ps1`） |
| 语音命令 | 转写语言 | `zh`（默认） | 命令与会议共用；可选 `zh/en/ja/ko/yue/auto`。**Whisper 只认 ISO 码**，填全名（如 `Chinese`）会自动纠正，非法值回退 `zh`（否则 whisper 报错、转写结果会变成空） |
| 会议 | 会议转写模型 | `sensevoice`（默认） | 源机器用的是 `qwen3asr`；想一致就跑上面那个脚本 |
| 唤醒词 | 启用语音唤醒 | 按需开 | 默认关闭；开了才监听唤醒词（默认「回声回声」） |
| 面板 | API 鉴权 | 保持关闭 | 仅本机访问，无需 token |

> ⚠️ **Whisper 系列（`small`/`medium`/`large`）的中文可能输出繁体字**：它的中文训练语料以繁体为主，

## 7.5 安全：本机 API 的来源守卫（2026-09-13 加了 CRITICAL-1 修复）

8970（ECHO API）与 8899（模型路由）都只监听 `127.0.0.1`，但**只监听回环不等于安全**：
你打开的**任意网页**的 JS 都能请求 `http://127.0.0.1:8970`。修复前那是一条完整攻击链：

- 读走会议原始录音 / 逐字转写 / LLM 纪要（`GET /api/meetings` + `/audio` / `/file`）；
- `POST /api/meeting/start` 让 **ECHO 服务进程**开始录音——不需要浏览器麦克风权限、也不亮录音指示灯，
  之后再把音频下载走（可远程触发的窃听）；
- `POST /api/assistant/command` 让大模型执行任意指令；`POST /models/download` 拉几 GB 占满磁盘。

修复（`app/netguard.py`，8970 与 8899 都装了）：

1. CORS 从 `allow_origins=["*"]` 收紧为**只放行回环来源**；
2.6. **API 密钥不再明文落库（MEDIUM-2）**：`api_keys` 表只存 `sha256(token)`（token 是
   `secrets.token_hex(24)` = 192 位随机，用 sha256 足够，无需慢哈希），校验走
   `hmac.compare_digest` 恒定时比较；`GET /api/keys` **不再回 token 也不回哈希**（只回
   id/名称/权限/启用/时间），明文只在 `POST /api/keys` 时返回一次，丢了就删掉重建。
   v1 老库启动时自动迁移：已发出的 token 原样有效，只是库里不再有明文。2.5. **路径穿越收口（HIGH-1）**：`GET /meetings/{id}/file?kind=` 以前把 kind 直接拼进路径
   （`os.path.join` 遇到绝对路径会整段替换、遇到 `..` 会逃出目录），后缀又固定拼 `.md` ——
   对全是 .md 的笔记库等于"任意文件读取"。现在 kind 走白名单（transcript/topics/summary）、
   目录名取 basename、最终路径必须仍在 `data\meetings\` 内（realpath 判定）；`/meetings/{id}/audio`
   同样加了兜底。自查：
   ```powershell
   curl.exe -s -o NUL -w "%{http_code}`n" "http://127.0.0.1:8970/api/meetings/1/file?kind=../../../../Windows/win"   # 400
   curl.exe -s -o NUL -w "%{http_code}`n" "http://127.0.0.1:8970/api/meetings/1/file?kind=C:/Windows/win"             # 400
   ```2. **Host / Origin 守卫中间件**：`Host` 或 `Origin` 不是回环一律 **403**——这一层同时封死
   **DNS Rebinding**（域名先解析到真实 IP 过校验、再改指 127.0.0.1），并挡住"简单请求"式跨站写入
   （那种请求浏览器不预检，只收紧 CORS 拦不住，必须在服务端拒绝）。
   `Origin: null`（`file://`、sandbox iframe）也拒，所以**折叠条页面改成经
   `http://127.0.0.1:8970/web/rail.html` 同源加载**（边条 exe 已随之重编；ECHO 没起来时会重试 6 次
   再退本地文件兜底）。

**副作用（预期）**：用局域网 IP 从手机/别的机器访问面板会 403。
**手机访问请走反代**（不要把服务绑 0.0.0.0）：Caddy/Nginx + Basic Auth + TLS，并打开
`apiAuthEnabled`、用 `POST /api/keys` 生成 Bearer Token。注意 `GET /api/status` 设计上不需要 token，
别把它直接暴露到公网。

自查命令（新机器上一条条跑，预期值见行尾）：

```powershell
curl.exe -s -o NUL -w "%{http_code}`n" http://127.0.0.1:8970/api/status                       # 200
curl.exe -s -o NUL -w "%{http_code}`n" -H "Origin: https://evil.com" http://127.0.0.1:8970/api/status   # 403
curl.exe -s -o NUL -w "%{http_code}`n" -H "Origin: null" http://127.0.0.1:8970/api/status               # 403
curl.exe -s -o NUL -w "%{http_code}`n" -H "Host: evil.com" http://127.0.0.1:8970/api/status             # 403
curl.exe -s -o NUL -w "%{http_code}`n" -X POST -H "Origin: https://evil.com" http://127.0.0.1:8970/api/meeting/start  # 403
```

## 8. 常见故障

| 症状 | 原因 | 处理 |
|---|---|---|
| `Fatal Python error: init_fs_encoding` / `No module named encodings` | `venv\pyvenv.cfg` 的 home 指向源机器的 Python | 重跑 `scripts\new-machine-setup.ps1`（第 1 步就是修这个） |
| `No module named app` | 没在 ECHO 根目录执行 | `cd D:\ECHO` 后重试 |
| pip 安装慢/失败 | 内网访问 pypi 受限 | 加 `-i https://pypi.tuna.tsinghua.edu.cn/simple`；或干脆整包拷贝 venv |
| 双击桌面快捷方式没反应 | 缺 `venv\Scripts\pythonw.exe`、或组策略拦截 | 看 `data\logs\launch.log`；先跑 `setup.ps1` |
| 面板打不开 | 8970 被占用 / 服务没起 | `netstat -ano \| findstr 8970`；改 `serverPort` 后重启；看 `data\logs\echo-server.log.err` |
| 语音命令不执行、面板提示"ECHO 服务未运行"式报错 | DSH Desktop 没启动，或没开"普通浏览器访问" | 见 [§5](#5-接上-dsh-desktop执行引擎必须)；确认 `~\.dsh\.credentials.yaml` 存在 |
| 转写很慢（一句话要好几秒） | 没有 N 卡，走 CPU | 正常现象；可把 `device` 明确设为 `cpu`；会议长录音建议用 `sensevoice` |
| torch 报 CUDA / 驱动相关错误 | 显卡驱动太旧（venv 里是 CUDA 12.8 轮子） | 设置 `device=cpu`，或升级显卡驱动 |
| 启动时提示"模型缺失" | 拷贝时漏了模型目录 | 按 [§1 清单](#完整清单含哪些不含哪些) 补拷 |
| SenseVoice 加载失败 / funasr 路径报错 | 安装路径含中文 | 整体挪到 `D:\ECHO` 这类纯英文路径 |
| 录音没声音 | 系统麦克风权限 | Windows 设置 → 隐私和安全性 → 麦克风 → 允许桌面应用；面板设置里指定输入设备 ID |
| 媒体键（耳机音量键）不触发 | 被其他软件占用 | 用回退热键 `Ctrl+Alt+V`；或跑 `venv\Scripts\pythonw.exe scripts\probe_mediakeys.py 90` 排查 |
| 仪表盘上"模型路由（ECHO AUTO）"显示失败（提示脚本缺失） | 该组件（`dsh-failover\`，源机器的成员指向公司内网网关）**未随包提供**——它只对源机器环境有意义 | 正常现象，忽略即可；不影响语音命令、转写、会议纪要任何功能 |
| DSH Desktop 升级后，`Ctrl+Shift+E` 边条失效、ECHO 不再随 DSH 自动启动 | 升级会重建 `<DSH 安装目录>\resources\app.asar.unpacked`，把 echo-host 的 `cordis.patch.yml` 补丁与部署副本一并删除（插件就此"消失"） | 重跑 `powershell -File scripts\install-echo-host-plugin.ps1` 后重启 DSH Desktop；`scripts\launch-desktop.ps1` 已内置自愈，启动一次 ECHO 也会自动补装 |

> 交付包里**只有 `meeting-record` 一个 DSH 技能**（语音"开始录音/结束录音"需要它）。
> 其余个人技能（笔记库归档、绩效填表、NAS、腾讯文档等）属于周克勤自己的技能库，没有随包发出；需要时单独找他要。

# 会议纪要归档（委派给归档技能）

ECHO 在归档环节**不做任何归档决策**。它只负责三件事：

1. 把纪要拼成一份自包含 markdown，落到会议目录（`data/meetings/<会议名>/meeting_note.md`）；
2. 把「笔记库路径 + 会议结构化信息 + 该 md 的绝对路径 + 归档要求」送进 DSH；
3. 把 DSH（实际是你的**归档技能**）回的一句话结果原样显示在面板上。

写哪个目录、工作日志什么格式、有哪些专项与例会体系——**全部是技能的事**。
因此 ECHO 代码里不含任何个人笔记库路径、专项清单或单位会议体系，
换个人只要写好自己的归档技能、改两个设置就能用。

> 历史背景：2026-09-12 之前，ECHO 自己硬编码了笔记库路径、14 个专项和 5 类例会，
> 还和 DSH 约定了一套 `TOPIC` / `PROJECT_LOG_START` 文本协议再反向解析。
> 那套实现不可移植、暴露隐私且每加一个专项都要改 Python 代码，已整体移除。

## 一、配置

面板 → 设置 → **纪要归档**：

| 设置项 | 默认 | 说明 |
|---|---|---|
| `worklogEnabled` | 关 | 总开关（**唯一的开关**）。关闭时「归档会议纪要」按钮直接提示不可用 |
| `worklogEnsureSessionAccess` | 开 | 归档前把 DSH **新建会话**的默认权限校正为全盘访问（笔记库在会话工作区之外，权限不足会被沙箱拦下）；关闭后只告警不修改 |
| `worklogPrompt` | 内置模板 | 送入 DSH 的提示词模板，可改 |

> ⛔ `worklogMode`（`skill`/`off`）已**弃用**（2026-09-19）：它与 `worklogEnabled` 表达同一个
> 「不归档」，属重复开关，只保留总开关。老配置里选过 `off` 的，启动时会自动把
> `worklogEnabled` 置为关（见 `app/config.py` 的 `DEPRECATION_MIGRATIONS`），行为不变。

条件不满足时，`GET /api/worklog/status` 会返回 `ready=false` 和一条
**可操作的**原因（例如"未配置笔记库根目录"），面板据此提示而不是静默失败。

提示词里给的是 `{vault}` 与 `{md_path}` 的**绝对路径**——技能直接用绝对路径最稳，
因为会话的工作目录是会议工作区，不一定是笔记库。

### 会话权限（为什么归档会"写不进去"）

笔记库在归档会话的工作区**之外**。DSH 会话权限默认是 `workspace-write`，于是首次
写入会被沙箱拒绝，要靠 DSH「升级一次权限重试」才写得进去——整场实测约 640s，
等待窗口一旦先到就显示成"归档失败"（**其实还在写**）。2026-09-15 的"写入工作日志
没成功"就是这个原因。

ECHO 因此固化了三件事：

1. **每次归档前**复核 DSH 的 `permission.defaultPreset`，不是 `danger-full-access`
   就当场改回来（`settings/update`，live 生效，**无需重启 DSH**）；
2. **ECHO 启动时**（`worklogEnabled` 为开）也做同样的自检，结论写进日志，
   面板「日志」里搜 `归档权限自检` 即可看到；
3. 归档前**检查本场会话已存的权限**，受限就提前告警"这场会慢一次"。

把 `worklogEnsureSessionAccess` 关掉则只告警、不修改。注意该默认值只影响**新建**
会话：历史会话保留各自已存的权限，第一次归档仍可能慢一次（之后正常）。

## 二、技能契约

### 何时被调用

用户在会议详情页点「📝 写工作日志」→ 填「归档要求」（可留空）→ 确认归档。
后端 `POST /api/meetings/{id}/worklog` 同步等待技能完成（超时 900 秒；
权限受限的旧会话要先被沙箱拦一次再由 DSH 自动提权重试，实测约 640s，
所以窗口不能小于它，否则会把"还在写"误报成失败）。

### 输入

ECHO 用 `worklogPrompt` 模板渲染一段文本发给 DSH。默认模板如下
（`{...}` 为占位符，技能不需要解析它——它是给模型看的自然语言）：

```
【纪要归档任务】
笔记库根目录：{vault}
会议标题：{title}
会议时间：{started_at}（{date} 第 {hour} 时，约 {duration} 秒）
参会人：{speakers}
纪要文件：{md_path}
幂等键：{meeting_id}
归档要求：{archive_hint}

请调用你的归档技能完成归档：判断归属位置 → 写入会议纪要 → 更新相关工作日志/项目日志。
要求：
1) 归档要求为空时，按你自己技能的默认规则判断，不要臆造目录；
2) 幂等：若该幂等键已登记过，跳过重复写入；
3) 纪要全文读 {md_path}，不要凭标题推测内容；
4) 完成后只回复一句话说明归档结果（写到哪个文件）。
```

| 占位符 | 含义 |
|---|---|
| `{vault}` | 笔记库根目录（= 会话 cwd） |
| `{title}` | 会议标题（DSH 自动命名或时间戳名） |
| `{started_at}` | 会议开始时间 `YYYY-MM-DD HH:MM` |
| `{date}` | 会议发生日期 `YYYY-MM-DD`（**归档应落这一天**，不是执行命令的日期） |
| `{hour}` | 会议开始时刻 0–23（用于判断上午/下午） |
| `{duration}` | 时长（秒） |
| `{speakers}` | 参会人显示名，顿号分隔；分不出人时为「未区分」 |
| `{md_path}` | 纪要 md 的**绝对路径**（技能直接读它，不要靠标题猜内容） |
| `{meeting_id}` | 幂等键 = 会议目录名（如 `2026-09-12_10-00-00`） |
| `{archive_hint}` | 归档要求自由文本；为空时渲染为「（无，按你的默认规则判断）」 |

模板里的未知占位符**原样保留**，不会让归档失败（方便你加自己的字段）。

### 技能必须做到

1. **决定归属位置**——归档要求为空时按技能自身默认规则判断，**不要臆造目录**；
2. **写入会议纪要**——读 `{md_path}` 的全文写入目标位置；
3. **更新工作日志 / 项目日志**——这是"归档"区别于"存文件"的地方；
4. **幂等**——用 `{meeting_id}` 判重，已登记过则跳过，避免重复点按钮写多条；
5. **回一句话**——说明归档结果（写到哪个文件），ECHO 会原样显示给用户。

### ECHO 不做什么

- 不解析技能的结构化输出（只要一句人话）；
- 不直接改笔记库（唯一例外是 `meeting_note.md` 这个本地材料文件）；
- 不知道你的目录规范、专项清单、例会体系。

## 三、写一个最小归档技能

放在 `~/.dsh/skills/<你的技能名>/SKILL.md`。示例（纯文件夹归档，不用 Obsidian）：

```markdown
---
name: my-archive
description: 把 ECHO 会议纪要归档到我的笔记库。当收到「纪要归档任务」时使用。
---

# 我的归档技能

## 配置
- 笔记库根目录：由任务里的「笔记库根目录」字段给出（会话 cwd 就是它）
- 纪要目录：`会议记录/{YYYY}/`
- 日志目录：`日志/{YYYY-MM-DD}.md`

## 执行步骤
1. 从任务里取 `笔记库根目录`、`会议标题`、`会议时间`、`纪要文件`、`幂等键`、`归档要求`
2. 读「纪要文件」的绝对路径拿全文
3. 幂等检查：日志文件中若已含「幂等键」，直接回「已登记过，跳过」
4. 写纪要：`会议记录/{年}/{日期}_{标题}.md`
5. 追加日志：在 `日志/{日期}.md` 追加一行「- 会议纪要：{标题}（链接到纪要文件）」
6. 只回复一句话：`已归档到 会议记录/2026/... 并登记日志`
```

要点：
- 技能是**你自己的**，目录结构、命名、日志格式随便定；
- 归档要求是自由文本，技能自己解释（"这是周例会"、"归档到 XX 项目"…）；
- 幂等靠 `{meeting_id}`，不需要 ECHO 帮忙。

## 四、API

| 端点 | 说明 |
|---|---|
| `POST /api/meetings/{id}/worklog` | 触发归档。body：`{"archive_hint": "自由文本"}`（旧字段名 `project` 仍兼容） |
| `GET /api/worklog/status` | 归档可用性：`{ready, reason, enabled, mode, vault}` |

`reason` 为空表示可用；否则是给用户看的原因说明。

## 五、排错

| 现象 | 原因 |
|---|---|
| 按钮提示"纪要归档未启用" | `worklogEnabled` 为关 |
| 提示"未配置笔记库根目录" | `worklogVaultRoot` 为空 |
| 提示"笔记库根目录不存在" | 路径写错，或盘符未挂载 |
| 提示"归档技能未返回结果" | 技能没跑完/超时（900s）或 DSH 未就绪，见 `data/echo.db` 的 logs 表 |
| 归档很慢（好几分钟）或面板先报失败、但笔记库最后确实有文件 | 该会话权限低于全盘访问，走了"沙箱拦下 → DSH 自动提权重试"；新建会话已默认全盘访问，见上面「会话权限」 |
| 归档了但笔记库里没变化 | 技能没真正写文件，或写到了别的目录——看技能回复的路径 |

日志查询：`GET /api/logs?source=meeting`。

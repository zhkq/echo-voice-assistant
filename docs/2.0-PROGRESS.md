## 二、P1 已经开工

**产出 1：`app/paths.py`（新增，217 行）** —— 2.0 的统一路径解析层（D18–D21）

四类根分开：`{ECHO}`（代码）/ `{DATA}`（系统数据，**分平台**）/ `{MEETINGS}` / `{MODELS}`（后两者**用户可指定**）。

- `data_root()`：Windows `{ECHO}/data`；macOS `~/Library/Application Support/ECHO`；其它 XDG；`ECHO_DATA` 环境变量优先（测试与多实例隔离靠它）
- `resolve()`：`~` + `{ECHO}`/`{DATA}` 占位符 + 相对路径补全，**拒绝 `..`**
- `validate_dir()`：拒磁盘根 / 主目录本身 / 系统目录 / Program Files / 非目录 / 不可写（用"建了就删"探针），`create=True` 按需创建，ASCII 只提示不拦（见 S11 结论）
- `preflight()`：环境体检（四类根 + 存在性 + 可写性 + 磁盘余量），**任何异常都不抛**
- 关键纪律写进模块头注释：**不要在任何模块顶层缓存这些函数的返回值**（那等于把 1.x 的 import 期常量换个地方）

**产出 2：`tests/test_paths.py`** —— 27 个测试，覆盖占位符展开、`..` 拒绝、平台默认值、配置优先、危险位置拦截、`preflight` 健壮性。**全部通过。**

**产出 5：端口分配器（P1；对应"Windows 保留段漂移"那个历史事故）**

`app/ports.py` + `tests/test_ports.py`（17 个用例），并接到 `main.py` 的启动路径：

- `excluded_ranges()` 读 `netsh int ipv4 show excludedportrange protocol=tcp`
  （**本机实测有 8 段**：1168-1267 / 1368-1467 / 1468-1567 / 1900-1999 / 3828-3927 /
  5284-5383 / 5523-5622 / 50000-50059）。非 Windows 或命令失败返回空表，永不抛异常
- `probe()` 区分**保留段 / 已占用 / 可用**；故意**不设 SO_REUSEADDR**（Windows 上它会允许
  抢占已监听端口，把"已占用"误判成"可用"）
- `pick()` 退让顺序：首选 → `+1..+200` → **安全带**（18000-18999 / 20000-20999）→ 最后才
  让系统分配；返回时必须给出 `note`，调用方要打日志
- `listening()` / `read_port_file()` / `write_port_file()`（**原子写**，脚本不会读到半个文件）
- `main.py`：仍然保留"端口上已有监听者 → 判定重复实例并退出"的兜底语义，但把
  "端口不可 bind（保留段）"从**崩溃**改成**自动让位 + 响亮日志**，并把**实际**端口写回
  `echo-port.txt`（脚本靠它找服务）

**实测（真机验证）**：首选 1168（在保留段内）→ 整段跳过 → 让位到安全带/系统端口且可用；
首选被占用 → 让到下一个可用端口；`listening()` 对"只 bind 未 listen"正确返回 False
（这正是它与 `probe()` 的分工）。

⚠️ **一个产品级的坑（实测发现）**：`bind(0)` 刚分配又释放的临时端口，Windows 会**短暂保留**，
紧接着再 bind 同一个端口有约 **1/6** 的概率报"已占用"（12 次里 2 次）。所以
① `pick()` 的兜底**不再优先用 `bind(0)`**（那条路会把"起不来"的概率引进启动路径），
② 测试里**禁止**"先 bind/probe，再对同一个端口断言"的写法——这也是本轮门槛一度 flaky
（8 次红 5 次）的真正原因。护栏已在测试注释与 `pick()` 的 docstring 里写明。

2. ⬜ 面板"环境体检"页（消费 `paths.preflight()`）+ 目录选择/校验交互
3. ⬜ `DATA_DIR` / 平台数据根（D18）：**故意留到 P3**。理由：它不是用户可配置项，而
   `tests/test_voiceprint.py` / `test_api_voiceprints.py` 用"直接给模块属性赋值"来隔离
   数据目录，改成动态要先改这些测试；且 mac 布局迁移本来就在 P3（D17 要求接缝一次性分层）。

**这一轮踩的坑（都值得记）**

- **PEP 562 的模块级 `__getattr__` 对模块内部函数里的裸名字无效**（只管 `module.NAME`
  属性访问）。我一开始用它替换常量，结果 ruff 报 41 个 F821、测试一片 NameError。
  正确做法：内部引用也改成函数调用，不留"半成品"兼容别名。
- **PowerShell 的 `-replace` 默认不区分大小写**：`'\.MEETINGS_DIR\b'` 会把已经改好的
  `.meetings_dir()` 又匹配一遍，变成 `meetings_dir()()`（表现为 `TypeError: 'str' object
  is not callable`）。需要区分大小写时用 `-creplace`，或直接 `.Replace()`。
- 用 PowerShell 的 `Parser::ParseInput` 去"语法检查" Python 是无效的（那是 PowerShell
  的解析器），会报一堆假错；Python 的语法检查交给 `compileall`。

两次都只有一次样本，而 whisper 对短音频的输出本身就不稳定。**路径类/引擎类 spike 必须：多次重复 + 足够长的音频 + 关注"是否为空"而不是单次文本。** 已在计划 §9.1 记下这条。

## 第十七节 · Round 5（验证轮）：发现一个面板元数据的坑 + 交接

本轮没有改产品代码，只做验证与交接（会话上下文接近上限，改前端 JS 风险偏高）。

**验证结果（都通过）**：`check-windows.ps1` 五项全绿（161 个单测）；`GET /api/paths/env`
返回四根 + 会议目录数 + 端口(18060)；面板 `/api/settings` 能带出 `meetingsDir`/`modelsDir` 两项。

**发现的真问题（未修，下一轮优先）**：`/api/settings` 的 `grp` / `label` **来自数据库元数据**
（由 `settings.seed_defaults()` 在启动时同步），**不是直接读 `config.DEFAULTS`**。因此在
TestClient 这种"没走启动引导"的场景里，这两项会显示成 `grp=general` + 空 label。要紧的是：

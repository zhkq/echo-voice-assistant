## 二、P1 已经开工

**产出 1：`app/paths.py`（新增，217 行）** —— 2.0 的统一路径解析层（D18–D21）

四类根分开：`{ECHO}`（代码）/ `{DATA}`（系统数据，**分平台**）/ `{MEETINGS}` / `{MODELS}`（后两者**用户可指定**）。

- `data_root()`：Windows `{ECHO}/data`；macOS `~/Library/Application Support/ECHO`；其它 XDG；`ECHO_DATA` 环境变量优先（测试与多实例隔离靠它）
- `resolve()`：`~` + `{ECHO}`/`{DATA}` 占位符 + 相对路径补全，**拒绝 `..`**
- `validate_dir()`：拒磁盘根 / 主目录本身 / 系统目录 / Program Files / 非目录 / 不可写（用"建了就删"探针），`create=True` 按需创建，ASCII 只提示不拦（见 S11 结论）
- `preflight()`：环境体检（四类根 + 存在性 + 可写性 + 磁盘余量），**任何异常都不抛**
- 关键纪律写进模块头注释：**不要在任何模块顶层缓存这些函数的返回值**（那等于把 1.x 的 import 期常量换个地方）

**产出 2：`tests/test_paths.py`** —— 27 个测试，覆盖占位符展开、`..` 拒绝、平台默认值、配置优先、危险位置拦截、`preflight` 健壮性。**全部通过。**

**产出 3：`app/platform/` 接缝切片 + D12 契约改写（计划外但必须做）**

写 `paths.py` 时被现有契约测试拦住了：`tests/test_platform_contract.py` 的 1.x 规则是
**"`app/` 里不得出现 `darwin` 分支"**，而 §10 的 P1 明确要求 `app/platform/<os>/env.py`——
两者直接冲突。按计划 D12 的方向把契约改写提前到了现在：

- 新增 `app/platform/__init__.py`（`current()` / `defaults()` / `dangerous_prefixes()`）
  + `app/platform/{win32,darwin,linux}/env.py`（各平台默认值：系统数据目录、禁区前缀）
- `app/paths.py` 因此**不含任何平台分支**，只向接缝取值
- 契约测试改为：**平台差异只允许出现在 `app/platform/<os>/` 里**，且要求该目录与三个
  `env.py` 真实存在。规则没有变松——只是把"唯一合法位置"从 `mac/` 扩到 `app/platform/`，
  并额外要求接缝目录存在

⚠️ 改的过程中踩了两个坑，都记在这里以免重犯：
① `data_root()` 一开始调 `expand()`，而 `expand()` 的占位符表里含 `{DATA}` → **无限递归**
   （`RecursionError` 表现为 23 个测试 error）。现在 `data_root()` 只展开 `~` 与 `{ECHO}`。
② `app/platform/<os>/` 起初没放 `__init__.py`，成为**命名空间包**，
   `from app.platform import darwin` 拿到的是目录而不是 `env.py`。现每个平台目录都有
   `__init__.py` 转出公开面。

## 三、重要发现与更正（建议先看这段）

### ① D26 要改：`dsh --profile web` 在 0.1.5rc1 上不可用

启动时插件树解析不到 `@deepseek-ai/dsh-session-title-llm`（`--dump-config` 正常，一启动就报 `ERR_MODULE_NOT_FOUND`）→ **官方 wheel 的打包缺陷**。
**影响**：P6 的两条会话路径里，**"面板内嵌会话视图"（消费 `RunResult.events`）才是可靠的那条**；"ECHO 自带 web 实例"降为 best-effort，等升级运行时再验。**别把 D26 的验收押在 `--profile web` 上。**

### ② §3.1 记载更正：`sdk` profile 里没有 `dsh-mcp-client`

`--dump-config` 出来的组合树里没有这一行（`dsh-skill`/`dsh-skill-filesystem`/`dsh-workflow`/`dsh-subagent` 都在）。2.0 若要用 MCP，**先确认启用方式，不能假定它在**。

### ③ `app/audio/stt.py` 把"空结果"和"失败"混为一谈（真实缺陷）

每个引擎分支都 `except Exception → print(stderr) → return ""`。实测：**whisper 对一段 23 秒的短音频会无异常、无 stderr、直接返回空串**；调用方（会议转写）无法区分"这段没说话"和"引擎挂了"。
**后果**：可能静默产出空纪要。**建议 P1/P5 一并处理：空结果要显式上报，不要静默吞掉。**

### ④ 方法学教训：单次 A/B 会得出互相矛盾的结论

S11 第一次跑：whisper「ASCII 正常 / 中文路径空」；第二次跑：**完全反过来**（「ASCII 空 / 中文正常」）。
两次都只有一次样本，而 whisper 对短音频的输出本身就不稳定。**路径类/引擎类 spike 必须：多次重复 + 足够长的音频 + 关注"是否为空"而不是单次文本。** 已在计划 §9.1 记下这条。

### ⑤ 运行时是 SEA 快照

`deepseek_harness_runtime/runtime/` 下只有两个 `.exe`，`node_modules` **不在磁盘上**。排查插件缺失**只能看运行时自身的解析错误** —— 用 `Test-Path` 找包会得出错误结论（我这次就先被误导了一次）。

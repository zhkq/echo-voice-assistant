## 二、P1 已经开工

**产出 1：`app/paths.py`（新增，217 行）** —— 2.0 的统一路径解析层（D18–D21）

四类根分开：`{ECHO}`（代码）/ `{DATA}`（系统数据，**分平台**）/ `{MEETINGS}` / `{MODELS}`（后两者**用户可指定**）。

- `data_root()`：Windows `{ECHO}/data`；macOS `~/Library/Application Support/ECHO`；其它 XDG；`ECHO_DATA` 环境变量优先（测试与多实例隔离靠它）
- `resolve()`：`~` + `{ECHO}`/`{DATA}` 占位符 + 相对路径补全，**拒绝 `..`**
- `validate_dir()`：拒磁盘根 / 主目录本身 / 系统目录 / Program Files / 非目录 / 不可写（用"建了就删"探针），`create=True` 按需创建，ASCII 只提示不拦（见 S11 结论）
- `preflight()`：环境体检（四类根 + 存在性 + 可写性 + 磁盘余量），**任何异常都不抛**
- 关键纪律写进模块头注释：**不要在任何模块顶层缓存这些函数的返回值**（那等于把 1.x 的 import 期常量换个地方）

**产出 2：`tests/test_paths.py`** —— 27 个测试，覆盖占位符展开、`..` 拒绝、平台默认值、配置优先、危险位置拦截、`preflight` 健壮性。**全部通过。**

**产出 5：端口分配器（P1；对应"Windows 保留段漂移"那个历史事故）**

`app/ports.py` + `tests/test_ports.py`（17 个用例），并接到 `main.py` 的启动路径：

- `excluded_ranges()` 读 `netsh int ipv4 show excludedportrange protocol=tcp`
  （**本机实测有 8 段**：1168-1267 / 1368-1467 / 1468-1567 / 1900-1999 / 3828-3927 /
  5284-5383 / 5523-5622 / 50000-50059）。非 Windows 或命令失败返回空表，永不抛异常
- `probe()` 区分**保留段 / 已占用 / 可用**；故意**不设 SO_REUSEADDR**（Windows 上它会允许
  抢占已监听端口，把"已占用"误判成"可用"）
- `pick()` 退让顺序：首选 → `+1..+200` → **安全带**（18000-18999 / 20000-20999）→ 最后才
  让系统分配；返回时必须给出 `note`，调用方要打日志
- `listening()` / `read_port_file()` / `write_port_file()`（**原子写**，脚本不会读到半个文件）
- `main.py`：仍然保留"端口上已有监听者 → 判定重复实例并退出"的兜底语义，但把
  "端口不可 bind（保留段）"从**崩溃**改成**自动让位 + 响亮日志**，并把**实际**端口写回
  `echo-port.txt`（脚本靠它找服务）

**实测（真机验证）**：首选 1168（在保留段内）→ 整段跳过 → 让位到安全带/系统端口且可用；
首选被占用 → 让到下一个可用端口；`listening()` 对"只 bind 未 listen"正确返回 False
（这正是它与 `probe()` 的分工）。

⚠️ **一个产品级的坑（实测发现）**：`bind(0)` 刚分配又释放的临时端口，Windows 会**短暂保留**，
紧接着再 bind 同一个端口有约 **1/6** 的概率报"已占用"（12 次里 2 次）。所以
① `pick()` 的兜底**不再优先用 `bind(0)`**（那条路会把"起不来"的概率引进启动路径），
② 测试里**禁止**"先 bind/probe，再对同一个端口断言"的写法——这也是本轮门槛一度 flaky
（8 次红 5 次）的真正原因。护栏已在测试注释与 `pick()` 的 docstring 里写明。

2. ⬜ 面板"环境体检"页（消费 `paths.preflight()`）+ 目录选择/校验交互

   `tests/test_voiceprint.py` / `test_api_voiceprints.py` 用"直接给模块属性赋值"来隔离

**这一轮踩的坑（都值得记）**

- **PEP 562 的模块级 `__getattr__` 对模块内部函数里的裸名字无效**（只管 `module.NAME`
  属性访问）。我一开始用它替换常量，结果 ruff 报 41 个 F821、测试一片 NameError。
  正确做法：内部引用也改成函数调用，不留"半成品"兼容别名。
- **PowerShell 的 `-replace` 默认不区分大小写**：`'\.MEETINGS_DIR\b'` 会把已经改好的
  `.meetings_dir()` 又匹配一遍，变成 `meetings_dir()()`（表现为 `TypeError: 'str' object
  is not callable`）。需要区分大小写时用 `-creplace`，或直接 `.Replace()`。
- 用 PowerShell 的 `Parser::ParseInput` 去"语法检查" Python 是无效的（那是 PowerShell
  的解析器），会报一堆假错；Python 的语法检查交给 `compileall`。

## 第十七节 · Round 5（验证轮）：发现一个面板元数据的坑 + 交接

本轮没有改产品代码，只做验证与交接（会话上下文接近上限，改前端 JS 风险偏高）。

**验证结果（都通过）**：`check-windows.ps1` 五项全绿（161 个单测）；`GET /api/paths/env`
返回四根 + 会议目录数 + 端口(18060)；面板 `/api/settings` 能带出 `meetingsDir`/`modelsDir` 两项。

**发现的真问题（未修，下一轮优先）**：`/api/settings` 的 `grp` / `label` **来自数据库元数据**
（由 `settings.seed_defaults()` 在启动时同步），**不是直接读 `config.DEFAULTS`**。因此在
TestClient 这种"没走启动引导"的场景里，这两项会显示成 `grp=general` + 空 label。要紧的是：

## 第二十五节 · 附加：防"私人邮箱被推上去"的 pre-push 钩子

**背景**：我实测了 GitHub 那两个开关（*Keep my email addresses private*、*Block command line
pushes that expose my email*）**没有 REST API** —— `/user/email_visibility`、`/user/settings/emails`、
`/user/private_emails` 全是 404，而且当前 gh token 的 scope 是 `gist/read:org/repo/workflow`，
**没有 `user`**，本身也不够改账号设置。所以那两个开关只能在**网页**里点：
GitHub → 右上头像 → Settings → Emails。

**我做的等价防护**：`.githooks/pre-push`（随仓库版本化，可 `sh .githooks/pre-push --install` 安装）：

- 读 `git push` 喂进来的 ref 行，按 `remote..local`（新分支用 `local --not --remotes`）取出
  本次要推的提交；
- 任一提交的**作者或提交者**邮箱不是 GitHub noreply 形式（`*+*@users.noreply.github.com`
  或 `noreply@github.com`）→ **拦下并列出具体提交**，提示改用 noreply 身份或 `--no-verify`；
- 行尾做了 `\r` 清理（实测：CRLF 的输入行会让 `remote_sha` 粘上 `\r`，导致范围拼错、
  `rev-list` **静默失败** → 钩子形同虚设）；
- 同一提交的作者/提交者相同时只报一次。

**实测三个用例**：坏邮箱的新提交 → exit 1 并列出 `1635558@qq.com`；已推过的 noreply HEAD →
exit 0；已有分支上的新提交（`HEAD~1..HEAD`）→ exit 0。

注意：这只在**本机**生效（钩子不随仓库自动安装，需要每个克隆自己 `--install`）；它也挡不住
在网页上直接编辑或用其他机器推送。你本人要的那两个开关仍然得去网页点一次。

### 28.2 修掉 28 引入的 split-brain：`config.expand_path()` 也走路径层

给 `echo_root()` 加上 `ECHO_ROOT` 覆盖之后，`app/config.py` 里还留着自己那份

## 第三十九节 · P5 第二切片：在线服务预设 + 凭据管理（2026-09-19）

## 第四十节 · P5 第三切片：纪要接通直连 LLM（P5 验收点达成）

**要解决的问题**：1.x 的纪要**必须**经 agent —— DSH 会话 + `read` 工具读 `transcript.md`。
不装 agent（或 DSH 没跑）就完全出不了纪要。规划里 P5 的验收点是
"**配一个在线 ASR/LLM 即可完成一次转写 + 一次纪要**"，本切片把它做出来。

**两条路，判据明确**（`meeting.direct_llm_decision()`）：

| 情况 | 走哪条 | 为什么 |
|---|---|---|
| 用户显式选了 `providerLlm`（非空） | **直连 LLM** | 用户的选择优先，哪怕 agent 也在 |
| 没选，且 agent（DSH）就绪 | agent（原路） | 老用户行为**零变化** |
| 没选，agent 不可用，LLM provider 就绪 | **直连 LLM** | 这就是"不装 agent 也能出纪要" |
| 两边都不可用 | agent（原路） | 保持原路，错误由原路径如实报出 |

**直连路径的实现要点**

- **材料内联**：LLM 没有 read 工具，所以把转写正文拼进 prompt（`_provider_summary_text()`，
  复用 `_meeting_parts()`/`_meeting_full_text()`）；**超过 12 万字会截断并写明"被截断"**
  （不能让模型以为这就是全部）；
- **格式要求只有一份**：Mermaid/timeline 那些坑抽成 `_SUMMARY_REQUIREMENTS`，
  agent 路径与直连路径**共用** —— 各写一遍等于将来只修好一条路；
- **落盘纪律与 agent 路径一致**：回复过短或疑似占位话**不回写**（保留已有纪要）、
  失败写 `error` 日志（"点了没反应"是 1.x 的老毛病，不能再犯）；
- **不串台**：走直连时不碰 DSH 客户端（测试用"一调用就炸"的替身证明）。

**顺手修掉一个真 bug**：`regenerate_summary(extra_prompt=…)` 把"追加要求"记进了 `summary_runs`，
**却从没传给 `request_summary`** —— 也就是面板里"重新生成并加要求"的那个要求框一直是无效的。
现在 `request_summary(..., extra="")` 两条路都会带上它，测试分别钉住。

**测试**：`tests/test_summary_provider.py`（20 用例）—— 判据表四种情况、材料内联与截断说明、
格式要求单一来源（源码里只允许出现一次）、落盘纪律（过短/占位不覆盖旧文件）、
provider 报错必须留痕、以及 `request_summary`/`regenerate_summary` 的分流与透传。

**P5 验收点状态**：✅ "配一个在线 LLM 即可完成一次纪要"（`providerLlm` 指向 `openai-llm`
或 `echo-auto` 均可用）；"配一个在线 ASR 即可完成一次转写"的 provider 已就绪，
但**转写链路还没接** `active("asr")`——下一批做（与 `stt.py` 空结果显式化一起）。

## 第四十一节 · P5 第四切片：转写接 `active("asr")` + 空结果显式化

**① 空结果显式化（§19 发现③的根治）**

`stt.transcribe()` 原来每个分支都是 `except → print(stderr) → return ""`，于是
**"这段没人说话"和"引擎挂了"在调用方看来完全一样**（实测：whisper 对 23 秒静音音频
无异常、无 stderr、直接返回空串）→ 可能静默产出空纪要。现在：

- 新增 `stt.transcribe_ex()` → `{"text", "status", "detail"}`，
  `status ∈ ok / empty / error / missing`（**兼容**：`transcribe()` 保持原签名，返回 text）；
- 四个状态各有测试；`empty` 的 detail 还写明"可能是这段没有语音，也可能引擎内部静默失败"
  —— 不假装能区分，但不再把区别抹掉。

**② 会议转写接 provider（P5 验收点的 ASR 那一半）**

判据：**只有用户显式配了 `providerAsr` 才走外部/在线 provider**（`_active_asr_provider()`）。
刻意**不做**"本地引擎不可用就自动切在线"：换引擎同时改变**准确率/耗时/费用**，而且在线转写会把
**整段音频**传出去 —— 这种事必须用户显式选择（出网标注就写在 provider spec 里让他看见）。
默认（`providerAsr` 为空）= 完全沿用原路径，**老用户零变化**。

接上之后：走 provider 时**不加载本地模型**（省显存/省时间，也是"没 GPU 也能转写"的意义）；
外部转写没有词级时间戳，所以返回文本**按句切分、按字数在段时长内均摊时间**
（`_split_provider_text()`）—— 时间不精确但顺序与位置对，注释里写明别当精确时间戳用；
空结果写 `warn` 日志（与"引擎挂了"分开）、provider 报错写 `error` 日志，
单段失败不拖垮整场会议。

**测试**：`tests/test_asr_provider.py`（15 用例）—— 四种状态、选择判据（默认 None / 显式生效 /
配错留痕回退）、切句与均摊时间、以及集成：配了 provider 时**本地引擎一次都不加载**
（patch 成"一调用就炸"）、provider 文本真的落库（5 元组位置正确）、
失败与空结果各自的日志与"不写行"行为。

**P5 验收点**：✅ 在线 LLM → 一次纪要；✅ 在线 ASR → 一次转写。

**P5 剩余**：① D25 的第二半 —— 把 `dsh-failover/proxy.py` 物理并入 `app/providers/`，
并让"注册进 DSH 配置"**仅在装了 `agent-dsh` 时**执行（现在启动时按开关无条件执行）；
② 面板的 provider 选择界面；③ 命令转写（`sttModel` 那条路）也走 provider（会议已接，
命令口述还没接，属可选）。

## 第四十二节 · P5 第五切片：D25 收口（注册进 DSH 改成 agent 门控）

**D25 原文**：多上游派发路由属于主包 → 重构为 **LLM provider 的一种实现**
（`openai-compat + failover`）；**"注册进 DSH 配置"那一半改为仅在装了 `agent-dsh` 时可选执行**。

**本轮做的（行为要求）**：`boot._start_failover` 现在有三道闸，且**顺序与语义都写进了测试**：

| 情况 | 行为 |
|---|---|
| 路由起不来 | 组件 `failed`（照旧） |
| `routerAutoRegister=false` | 跳过注册，detail 写明"已按设置跳过" |
| **没装 `agent-dsh`** | **不写 DSH 的配置文件**；组件仍 `online`，detail 写"未注册进 DSH（原因）· 路由本身可用"，并写一条日志 |
| 装了且设置开 | 照常 `llm_router.sync()`；失败/异常只体现在 detail 上，**不影响路由在线** |

为什么这道闸是对的：把模型组写进 `~/.dsh/settings.yaml` + `.credentials.yaml` 是**给 agent 用的**，
没装 agent 时写了没人读、还平白改用户家里的配置文件；而**路由本身照常可用**——它是 LLM provider
`echo-auto`（P5 的纪要直连路径已经证明"不靠 agent 也能经它出纪要"）。
手动"注册到 DSH"的面板按钮不受限制：D25 管的是**自动**那一半。

**本轮做了一个取舍并记录在案：`dsh-failover/` 目录暂不物理搬迁。**

D25 说的是"重构为 LLM provider 的一种实现"，我们已把它做成 provider（`app/providers/router.py`
是调用面；路由本体仍在原目录）。真正的**目录搬迁**刻意留到 P4 的组件布局期，理由具体：

1. 会牵动 8 处代码引用（`failover_proxy.PROXY_SCRIPT/PROXY_CONFIG/LOG_DIR`、`llm_router.ROUTER_CONFIG`、
   `router_admin` 的写回路径）＋ `.gitignore` 3 行 ＋ `build-package.ps1` 的白名单与内容校验；
2. **还牵动"开机自启"**：`dsh-failover/install-autostart.ps1` 生成的计划任务/快捷方式指向该路径，
   搬完必须重新安装自启，否则"重启后路由不见了"这种最难受的故障；
3. **稳定树 `C:\echo1.0` 有它自己的一份**（冻结版）：开发树单方面改路径会让两棵树的脚本/文档分叉，
   而 1.0 不能动；
4. D25 的**功能意图**（路由是主包的 provider、注册进 DSH 变成可选）**已经满足**，剩下的纯是目录整洁。

→ 记在 REFACTOR-PLAN §15 的"仍未做"里，与 P4 的组件目录一起做（那时本来就要重排 `providers/` 的落盘位置）。

**测试**：`tests/test_failover_boot.py`（11 用例）—— agent 判据三种（未注册适配器 / 适配器报不可用 /
探测异常）、`_start_failover` 四种分支（路由失败不谈注册 / 设置关掉 / 没装 agent 不碰 DSH 且仍 online /
装了则注册，含失败与异常不影响在线）、以及 provider 边界三条（`echo-auto` 以 LLM provider 存在、
标注出网、`ready()` 不碰 agent 注册表）。

### 42.1 追加：堵住"保存设置把密钥清空"的数据丢失风险（同一轮内发现并修）

**怎么发现的**：做完全局遮罩后回头查面板的保存路径 —— `web/app.js` 的「保存」按钮会
**遍历 `#settingsForm [data-key]` 把每一项整批 PUT**。而密钥项在出口被遮成空串、渲染出来的
input 也是空 → **用户只要点一次保存，密钥就被空串覆盖**。这是我自己引入的事故面（不是既有 bug），
当场修掉，服务端 + 面板各一道闸：

| 层 | 规则 |
|---|---|
| 服务端（权威） | `Settings.update()`：`secret=True` 的项，**空串/纯空白 = 不改**（跳过）；要清空必须显式送哨兵 `CLEAR_SECRET="__clear__"`。普通项不受影响（`meetingsDir` 空串仍是合法值） |
| 面板 | 密钥行渲染成**密码框**（占位符显示"已配置（留空 = 不改）"/"未配置"）+ 「清除」按钮（送哨兵）；整批保存时**只提交这一轮真输入了新值的密钥** |

**回归测试（6 条，含端到端）**：空串不清、纯空白不清、**模拟面板整批回传（密钥为空的
`settings.all()` 结果）密钥仍在**、只有哨兵能清、普通项的空串仍生效、
以及 `/api/settings` 的 PUT 端到端（拿真实响应构造面板那套 payload 再打回去，密钥必须还在）。

## 第四十四节 · P5 收口盘点（第七切片：命令转写接 provider + 总账）

**本切片**：命令口述转写也接 provider —— 至此 **ASR 在"会议"和"命令"两条路上判据一致**。

- 判据上提到 provider 层：`providers.asr_if_configured()`（一份实现，两处调用），
  `meeting._active_asr_provider()` 与 `assistant` 都走它 —— 各写一份必然会分叉；
- `assistant` 里把转写步骤抽成 `_transcribe_command(wav, cfg) -> (text, note)`：
  **空结果与失败都带 note**（`provider=… reason=…` / `engine=… 失败：…`），
  日志里能一眼看出"是没人说话还是引擎挂了"（§19 发现③在命令路径上的落地）；
- 抽成函数的意义：**不开麦克风就能测**（5 条新用例：provider 生效时不碰本地引擎、
  provider 报错/空结果各自带原因、未配置时本地路径与空白归一化不变、本地引擎失败也带原因）。

### 明确延后 / 未做（不是遗漏，是决策）

1. **`dsh-failover/` 的目录物理搬迁**（迁进 `app/providers/`）：四条理由见 §42
   （自启脚本、稳定树分叉、打包白名单、8 处引用），安排与 **P4 的组件布局**一起做。
   **功能意图（路由是 provider、不依赖 agent）已经满足**，剩下的纯是目录整洁。
2. **未接 provider 的路径**：`/api/stt/transcribe`（面板里的"试转写"）仍走本地引擎参数；
   它的入参本来就是"指定引擎"，与被 provider 接管的"按配置选"是两回事，暂不改。

### 清点结论（改造前）

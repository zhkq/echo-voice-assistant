# 安装方式重构：技能优先（skill-first install）

> 起因：2026-09-21 同事在一台新机器上跑 `ECHO-kit-20260921` 的安装技能，回传了
> `ECHO-部署完成说明.md`，同时反馈「装完进 ECHO 还是进向导页；选了 dsh 标准版没看到下载提示；
> 选了 qwen3asr 只显示『正在准备中 / 排队中』」。下面每一条都在代码里定位到了根因。

## 一、实测反馈 → 代码级根因

| # | 现象 | 根因（代码位置） |
|---|---|---|
| 1 | 技能装完，进 ECHO **仍然进向导页** | `web/app.js:3347` 的 `bootView()` 用 `/api/wizard/first-run` 决定进哪个页签；判据是 `data/installed-components.json` **在不在**（`app/wizard.py:369`）。而这个文件**只有向导末页**才写（`app.js:3325` → `/api/wizard/finalize`）。技能安装只写 `/api/settings`，**从不登记** → 首装判据恒为真。 |
| 2 | 选「dsh 标准版」**没有下载提示** | `app/wizard.py:686` 的 `build_plan()` 只把 `engines / wake / diarize / accel / fallback` 当工作项；**智能体只产出 config 行**（`_setting_updates`），不进 `downloads`。于是确认页「将下载 N 项」不含它、执行页也没有它的行 —— 用户看不到任何"要准备智能体"的迹象（harness 的实际动作是 `execute_plan` 里静默 `ensure_running()`）。 |
| 3 | qwen3asr **永远"排队中"** | **两层**。① 主因：`app/wizard.py` 的 `execution_state()` 拿到 `modelinfo.jobs()` 后直接 `jobs.get(mid)`，但那个函数返回的是**包装**结构 `{active, items:{id: job}}` —— 在包装字典上找 id 永远找不到，于是**每一项都落到"排队中"，与真实进度无关**。② 雪上加霜：`modelinfo._download_worker`（`modelinfo.py:402`）失败写的是 `status="failed"`，而 `status_of()` 判断的是 `"error"` —— 就算取到了 job，失败也会被显示成"排队中"。同一个词表 bug 在技能里还有两处：`echo-install-components.ps1` 的 `Wait-Model`、`echo-install-components.sh` 的 `wait_model`（它们会一直傻等到 30 分钟超时）。 |
| 4 | 同事被 PowerShell 安全策略拦，**手改删了一行** | `scripts/install.ps1:264` 用 `Add-Type -AssemblyName System.IO.Compression.FileSystem` 读 zip 顶层目录；受限语言模式（ConstrainedLanguage / WDAC）下 `Add-Type` 被拦。 |
| 5 | sherpa 下载**必须设 `HF_HUB_VERIFY=0`** 才能过 | `app/modelinfo.py:391` 对 sherpa **硬编码走 `huggingface_hub`**，而目录里它标的是 `source="modelscope"`（`app/components.py:105`）→ 撞上公司代理对 hf-mirror 的证书拦截。**实测：同一个模型在 ModelScope 上叫 `pkufool/…`（文件齐全）**，本可以完全不碰 HF。 |
| 6 | 首次启动**卡在 uvicorn "Waiting for application startup"** | `app/db.py:302` 是 `sqlite3.connect(timeout=15)`；被卡时用户只看到 uvicorn 那行、没有任何原因。残留 `-wal/-shm` 时要能被诊断出来，而不是静默等。 |

## 二、新模型：技能是唯一的安装路径

```
用户 → 他惯用的 agent → 加载 echo-install 技能
                      → 问清要什么（引擎/唤醒/分离/智能体/目录）
                      → 环境 → 主程序 → 引擎依赖 → 模型 → 设置 → 智能体 → 自检
                      → POST /api/install/report（登记：装了哪些、什么版本、在哪）
```

**ECHO 侧跟着改（不为旧向导将就）**：

1. **不再用"首装"当"进向导"的理由**：面板默认进仪表盘；没登记时显示一条**不打断的横幅**
   （"这台机器还没登记安装完成 → 用助手按 echo-install 技能装 / 或走手动向导"）。
   向导**保留但降级**为手动入口（`?view=wizard`），**永不自动弹出**。
2. **安装情况成为一等概念**：
   - `data/install-report.json`：技能登记的真值（谁装的、装了哪些、版本、时间、目录）。
   - `GET /api/install/state`：面板与技能**共用**的一份状态（登记 + 还缺什么）。
   - `POST /api/install/report`：技能装完登记（同时满足首装判据，替代写 `installed-components.json`）。
3. **"还缺什么"由真值推导**（`install_state.missing()`）：模型 `modelinfo.ready()`、pip 模块能否
   `import`、`node/npx` 在不在、harness 是否 online、pyannote 是否 gated 未授权…
   技能用它做自检与最终汇报，面板用它做横幅与「能力」页 —— **一套判断，两处复用**。

## 四、明确的取舍

- **向导不删**：没有 agent 的机器仍需要一条手动路径，且它是既有的验证过的 UI。它只是**不再是默认路径**。
- **`installed-components.json` 不删**：老安装靠它；新的 `install-report.json` 与它**同样满足**首装判据（`install_state.declared()` 认两者）。
- **不改**：组件/能力页、设置页、模型页 —— 它们是"装完以后补能力"的地方，与安装路径无关。
- **不做**：自动装 Node / 自动装 CUDA（体积与驱动绑定，且要用户决定）。

## 五、验收标准

1. 技能装完 → 打开面板**直接进仪表盘**，横幅显示"已登记安装（时间/组件）"。
2. 技能日志里**能看见智能体那一步**（含首次 npx 拉包的过程），失败时给出可操作的补救命令。
3. 模型下载失败 → 技能与面板都显示**失败原因**（不再是"排队中"），技能非 0 退出并给重试命令。
4. 在受限 PowerShell 上 `install.ps1` 不再需要手改（无 `Add-Type`）。
5. 本机（公司网）装 sherpa / whisper-base / qwen3asr 三者都**不需要**关闭 TLS 校验。
6. 上述每一条都有测试或实测记录。

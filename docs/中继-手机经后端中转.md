# 中继：手机与电脑互相连不通时，经能力后端中转（2026-10-15）

## 一句话

手机连不上电脑、电脑也进不了手机 —— 但**两边都能连到那台能力后端**时，
让电脑**主动**去后端"取活"，手机的请求经后端转进来在电脑上执行。

```
手机 ──HTTP──▶ 后端 /v1/relay/<hostId>/api/… ──排队──┐
                                                      │（电脑来 poll，长轮询）
电脑 ──POST──▶ 后端 /v1/relay/host/poll ───────────────┘
      ◀─ 取回一条调用 ─→ 在电脑本机 127.0.0.1:8970 执行 ─→ 交回结果 ─▶ 手机
```

**为什么是"电脑主动取"**：公司网里办公电脑的**入站**通常被挡着（AP 隔离 / 跨网段 /
防火墙），**出站**是通的。所以连接方向只能是这个方向。

## 三处各改了什么

| 位置 | 文件 | 做什么 |
|---|---|---|
| 能力后端 | `server/relay.py`（新）、`server/main.py`（挂路由 + 主机身份中间件） | 主机取活/交结果的端点、手机入口、白名单、限流、离线与超时的分类错误 |
| ECHO 电脑 | `app/relay.py`（新）、`app/api.py`（`X-Echo-Relay` 判据）、`app/boot.py`、`app/settings_effects.py`、`app/config.py` | 常驻线程去取活、在本机执行、断线退避；**转发请求带标记让 ECHO 不再把回环当免检** |
| 手机 | 无需改代码 | 配对页把地址填成**中继地址**即可（其余照旧，令牌还是 ECHO 那枚） |

## 怎么开（顺序别颠倒）

### 1. 后端：更新并重启

后端要带上 `server/relay.py`。二选一：

* **用新的后端包**：`dist\ECHO-backend-portable-20261015-1051.zip`（薄包，24 MB，
  只带解释器，依赖仍然按原来的方式装），按你平时的方式装到那台 GPU 机上；
* **只换两个文件**：把仓库里 `server/relay.py`（新文件）与 `server/main.py`（改动）
  拷到那台机器的对应目录，然后重启后端容器/进程。

重启后自检（在**任何**能连到后端的机器上）：

```bash
# 这条路由"在不在" = 新版后端有没有就位。注意它**要凭据**，所以 401 才是好消息：
#   401 = 新版后端已就位（路由在、只是要令牌）；404 = 还是旧后端（连路由都没有）
curl -s -o /dev/null -w '%{http_code}\n' -X POST http://<后端>:8900/v1/relay/status
```

> 为什么这条状态接口是 POST 而不是顺手写成 GET：能力面那套契约里**免凭据的 GET 必须是公开的**
> （`tests/test_backend_pairing.py` 会逐条对账），而它含主机名与 hostId —— 匿名公开等于给
> 扫描器一张地图。要凭据就得走 POST。

### 2. ECHO 电脑：同步代码 + 开两个开关

* 代码：这份改动在 `app/` 里，**要同步到跑 ECHO 的那棵树**（`deploy-stable.ps1`）。
* 设置 → **面板与服务**：
  1. **API 鉴权（手机 App）= 开** —— 中继**必须**要它（转发进来的请求来自回环，
     不开鉴权 = 把这台电脑对整个中继敞开）。开了之后本地面板照旧能用（回环免令牌）。
  2. **允许手机经后端中转（中继）= 开** —— 默认关。
     打开时若没配对后端 / 没开鉴权，面板会**当场说明原因**（不会静默不生效）。
* 看地址：`GET /api/relay`（面板"能力/中继"处显示）——
  由后端认下来的 `hostId` 拼出，形如 `http://<后端>:8900/v1/relay/<hostId>/`。

### 3. 手机：配对页填中继地址

* 先在电脑面板生成**配对码**（6 位）；
* 手机配对页：**后端地址**填上面的中继地址，**配对码**填那 6 位 → 配对。
  之后所有功能（指令 / 语音 / 会议 / 回顾 / 后台听写）都自动走中继，**不用再改什么**。

## 安全边界（这一版刻意怎么定的）

| 边界 | 判据 |
|---|---|
| **默认关** | `relayEnabled=false` 时，电脑**一个请求都不发**，后端上也没有主机在 poll（手机那条路只会 503） |
| **只放行两样** | `/health` 与 `/api/*`；两处都判（后端 + 电脑侧），`..` 之类爬出去的路径一律拒 |
| **令牌是端到端的** | 中继**不做**自己的登录：手机带的是 **ECHO 那枚令牌**，电脑侧原样送给本机 API 去验。中继这层只粗筛"必须带 Authorization" |
| **两条豁免** | `health`（ECHO 那条探针本来就不要令牌，口径要一致）与 `api/pair/*`（首次配对时手机还没有令牌，配对码本身是凭据） |
| **不许冒充主机** | `hostId` = **后端认证出来的 client_id**，不接受请求里自报 |
| **回环不再免检** | 电脑侧转发时带 `X-Echo-Relay`，`app/api.py::_is_loopback_call()` 见到它就当成"网上来的"。**少了这一条，中继就是一个绕过令牌的后门** —— 改动时这两半必须同时存在 |
| 限流 / 上限 | 每来源 IP 120 次/分；单次 body ≤ 12 MB；等主机结果 ≤ 600 秒 |
| 手机能做的不变 | `_NETWORK_DENIED` 那张拒收清单照旧生效（停服/重启/删会议/改设置一律 403） |

> ⚠️ **这条改动了 2026-10-09 的一条老决定**（"不把 ECHO 暴露到公网、不做内网穿透"）。
> 2026-10-15 用户明确接受这个取舍（原话："我们可以都连接后端来中转吗"），
> 于是做成**默认关 + 手动开**。老文档里那句以本文件为准。

## 排障：看错误码就知道该干什么

| 现象 | `code` | 怎么办 |
|---|---|---|
| 手机说"电脑的中继没连上" | `relay_host_offline` | 电脑上中继开关没开 / 没配对后端 / 电脑断网；看电脑面板上的中继状态与原因 |
| 后端自检回 404 | —— | 后端还是旧版（没有 `/v1/relay/*` 路由）：按上面第 1 步更新并重启 |
| 手机 401 | `relay_unauthorized` | 这条请求没带令牌（除 `health` 与 `api/pair/*`）；重新配对一次 |
| 手机 403 | `relay_forbidden_path` | 路径不在白名单里（只有 `/health` 与 `/api/*`） |
| 手机 429 | `relay_rate_limited` | 请求太频繁，等一会儿 |
| 手机 413 | `relay_too_large` | 单次上传超过 12 MB：长音频分段发 |
| 手机 504 | `relay_timeout` | 电脑那边太久没回（可能正忙/卡住）；重试或看电脑面板 |
| 电脑日志 `中继没起来：...` | —— | `GET /api/relay` 的 `reason` 会说清（没配对后端 / 没开 API 鉴权 / 开关没开） |

## 判据（改这个功能时先跑这两组）

* `python -m unittest tests.test_server_relay`（20 条）：白名单、限流、中枢的超时/队列、
  主机身份不接受冒充、二进制原样往返、两个线程的真 HTTP 端到端；
* `python -m unittest tests.test_relay_host`（13 条）：只转发该转的头、4xx 原样带回、
  白名单外一条都不发、后端不在时什么都不做、**"带标记的请求不再算本机"**这条命门。

## 没验到的（如实写）

* **没有对真后端 + 真手机跑过**：本机验证用的是假后端 + 假本机 API（真 HTTP、真线程），
  协议与安全判据都在，但"公网那台后端 + 真手机在 4G/Wi-Fi 下"的时延与稳定性没量过；
* 中继中枢是**单进程内存态**：后端必须是**单 worker**（`Dockerfile` 的 CMD 就是一个进程）。
  将来改多 worker 会出现"手机连 A、主机挂 B"的随机 503，必须换成外部登记；
* 没有做"多台电脑同时挂在中继上"的界面（后端 `/v1/relay/status` 已经能列出全部主机，
  手机地址里带的就是 hostId —— 换电脑只要换那串地址）。

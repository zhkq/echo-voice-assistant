# ECHO 3.0 安装：快路（一条命令）与离线最小包（实测）

> **这份文档解决什么**：以前的安装是「把 `echo-install` 技能交给 AI 助手，助手照 SKILL.md
> 逐步做」——慢就慢在**每一步都联网**（pip 装依赖、下模型）**加**每一步都要助手复述确认。
> 现在多了一条**不绕助手、也不联网**的快路，并且是**实测过**的（不是设计目标）。

---

## 0. 两条路（装出来的东西一样）

| | **快路**（新） | **原路**（保留） |
|---|---|---|
| 入口 | 离线包：双击 `装我.cmd`；在线包：`ECHO\scripts\install-all.ps1 -Yes` | 把资料夹交给 AI 助手，说"按 echo-install 技能装 ECHO" |
| 谁在跑 | `scripts/install-all.ps1`（一条命令走完 8 步） | 助手逐步执行 `.dsh/skills/echo-install/SKILL.md` |
| 需要联网吗 | **不需要**（离线最小包：依赖走 `bundle\wheels`、模型走 `bundle\models`） | 需要（PyPI + ModelScope/hf-mirror + python.org） |
| 需要助手吗 | 不需要 | 需要 |
| 组件安装 | **调技能里的同一个 `echo-install-components.ps1`** | 同一个脚本 |
| 设置 / 自检 / 登记 | 同一套键、同一份自检 | 同左 |

两条路**没有第二份实现**：`install-all.ps1` 只负责"就位 / 运行时 / 核心依赖 / 启动 /
打印面板地址"，引擎依赖、模型、设置、自检、登记全部交给技能里那个组件脚本。
所以技能仍然独立可用（agent 那条路一个字没删）。

## 1. 快路怎么用

```powershell
# ① 离线最小包（ECHO-kit-min-*.zip）—— 双击 装我.cmd 就行；等价的命令行：
powershell -NoProfile -ExecutionPolicy Bypass -File <kit>\install-offline.ps1 -Root D:\ECHO

# ② 在线工具包（ECHO-kit-*.zip）—— 入口在主程序里，是同一个脚本
powershell -NoProfile -ExecutionPolicy Bypass -File <kit>\ECHO\scripts\install-all.ps1 -Yes
```

`install-all.ps1` 的参数：

| 参数 | 作用 |
|---|---|
| `-Profile minimal\|main` | `minimal` = 只要 sherpa（最小实例，默认）；`main` = 再加唤醒词 KWS |
| `-Root <安装根>` | 数据/模型/运行时都在这下面，代码进 `<根>\echo-core`（默认 `D:\ECHO`，无 D 盘则 `C:\ECHO`） |
| `-Agent none\|harness\|dsh` | 智能体。**离线默认 `none`**（包里不带 DSH，见 §5） |
| `-Yes` | 无人值守，不提问 |
| `-Offline` | 离线：pip 带 `--no-index --find-links`，模型直接用包里的 |
| `-Engines` / `-Wake` / `-Diarize` / `-NotesDir` | 覆盖档位 / 额外组件 |
| `-NoShortcuts` / `-SkipStart` | 不建快捷方式 / 只装不启动 |

八个阶段（离线）：**定位 → 建运行时 → 装核心依赖 → 准备模型 → 就位主程序（复用
`scripts/install.ps1`）→ 起服务并钉死端口 → 装组件（技能脚本）→ 收尾打印面板地址**。

> **端口这一条要单独说**：组件脚本的端口推断是
> `$env:ECHO_PORT` → `<安装根>\data\echo-port.txt` → `8970`。开发机上 `ECHO_PORT=18060`
> 就指着**别人的实例**，于是第一次离线实测把 `sttModel` 写进了那个实例（值没变，虚惊一场）。
> 现在 `install-all.ps1` 会：清掉继承来的 `ECHO_PORT`、自己把本实例拉起来、等
> `<安装根>\data\echo-port.txt` 出现、再把 `ECHO_PORT` **覆盖**成本实例端口；
> 本实例起不来就**停下**（而不是让组件脚本去猜端口、写进别人的 ECHO）。

## 3. 实测：临时目录里真装一遍（离线）

```powershell
# 解包（当作同事拿到包）
tar -xf dist\ECHO-kit-min-<stamp>.zip -C C:\echo-offline-kit
# 装（= 双击 装我.cmd 的那条路，内部就是 -Offline -Yes -Agent none）
powershell -NoProfile -ExecutionPolicy Bypass `
  -File C:\echo-offline-kit\ECHO-kit-min-<stamp>\install-offline.ps1 `
  -Root C:\echo-offline-test -NoShortcuts
```

结果：**退出码 0**（同一台机器，2026-09-25）。逐阶段数字见下表（第一次跑，文件缓存是冷的）：

| 阶段 | 耗时 | 说明 |
|---|---|---|
| 定位 | 2.1 s | |
| 建运行时 | 15.0 s | 命中 uv 缓存的 CPython 3.11.15 + `ensurepip` 补 pip（**不联网**） |
| 装核心依赖 | 40.5 s | `pip install --no-index --find-links <kit>\bundle\wheels -r ECHO\requirements-core.txt` |
| 准备模型 | 0.4 s | 189.3 MB 本地复制（同盘） |
| 就位主程序 | 11.6 s | 复用 `scripts/install.ps1`（复制代码 + 快捷方式 + 自检） |
| 起服务并钉死端口 | 7.9 s | 本实例起在 8970，`ECHO_PORT` 钉死 |
| 装组件 | 7.4 s | 技能脚本：依赖（已满足）/ 模型（已就绪，跳过）/ 设置 / 自检 / 登记 |
| 收尾 | 0.6 s | 打印面板地址 |
| **合计** | **87.3 s**（墙钟 89.7 s，退出码 0） | **第一次跑（文件缓存冷）** |

交付的那一版又用**真正的手双击路径**跑了两遍（`装我.cmd` → `install-offline.ps1` →
`install-all.ps1 -Offline -Yes -Agent none`，临时目录 `C:\echo-offline-test3`）：
**合计 61.2 s / 69.7 s，墙钟 64.2 s / 70.9 s，两次退出码都是 0**，面板地址
`http://127.0.0.1:8970/`。同一台机器上的三次端到端测量是 **87.3 / 62.9 / 69.7 秒**
（第一次最慢：wheel 文件缓存是冷的），阶段构成完全一致 —— 差值全在"装核心依赖"
（40.5 s → 22.8 s → 22.8 s）。

> `C:\echo-offline-kit-final\testE.log`）。

### 怎么证明"没走网络"

1. **pip 命令行里就是离线的**（安装输出里能逐字看到）：
   `pip install --no-index --find-links "…\bundle\wheels" -r "…\requirements-core.txt"`，
   而 pip 自己打印的是 `Looking in links: …\bundle\wheels` —— **没有** `Looking in indexes: https://pypi.org/simple`。
2. **加了个"跳线"陷阱**：测试时把 `PIP_INDEX_URL` / `PIP_EXTRA_INDEX_URL` 指向一个死端口
   （`http://127.0.0.1:1/simple`）。离线引脚一旦失效，pip 会立刻去那个死端点并在日志里报错；
   两次实测都**没有**任何 index 相关输出 → 说明真的没查过任何索引。
3. **组件脚本那一步的 pip 也被钉住**：`install-all.ps1` 在调组件脚本前设置
   `PIP_NO_INDEX=1` + `PIP_FIND_LINKS=<bundle>\wheels`（pip 认这两个环境变量），
   输出里同样只有 `Looking in links:`。
4. **模型零下载**：组件脚本的 `Install-Model` 先查 `/api/models`，随包模型已 `ready=true`
   → 打印 `sherpa 已经装好，跳过`（真去下载的话，内网/断网下会卡在等待里，不会 0.4 秒就过）。
5. **运行时零下载**：uv 用的是本机缓存的 CPython；裸机那条走的是包里的嵌入包（同目录的
   `get-pip.py` 从本地 wheel 装 pip）。整条链路里没有 `Invoke-WebRequest` / `curl` 下载动作。

## 4. 与旧路径比，快多少

| 路径 | 依赖 | 模型 | 人工/助手 | 实测 |
|---|---|---|---|---|
| 旧（联网 + 助手） | PyPI 下 ~64 MB wheel（还常要重试/换镜像） | ModelScope 下 189 MB | 助手逐步确认 | **没有本机端到端实测数字**（见下） |
| 快路（离线最小包） | 本地 wheel 40.5 s | 本地复制 0.4 s | 无 | **89.7 s，退出码 0** |

**基线数据来源（如实说）**：

* 本仓库里**没有**"旧路径整机端到端耗时"的实测记录 —— `docs/3.0-试用手册.md` §10 明确写着
  "真机装完的体积与耗时…**目前只是设计目标**，别当成已验证的数字"（那一档 ≈600 MB / <3 分钟）。
* 有据可查的碎片是**分段**的，都在技能文档里：
  * `models/sherpa-onnx-streaming` 走 ModelScope：同事机器实测 **189 MB / 15 秒**（内网顺利时）；
  * 标准版 harness 本地永久安装：**223 MB / 55 秒**（`profiles.json` 的 extraLabel）；
  * `npx -y @deepseek-ai/dsh web` 冷启动 **2 分 10 秒** vs 本地入口 **9 秒**（SKILL.md）。
* 所以能说的**保守结论**：快路把"下载 64 MB wheel + 189 MB 模型"换成了"本地读同样的字节"，
  加上不再有助手逐步确认的开销；本机实测 **89.7 秒装完并起服务**。
  省下的绝对时间取决于目标机网速与助手往返（网络越差、助手越慢，省得越多）——
  这个数**我没有在同事那台机器上测过**，别当成"快 N 倍"的实测。

## 5. 没打进包 / 仍需联网的场景（如实）

* **DSH / 标准版 harness 不在包里**：`@deepseek-ai/dsh` 是私有 npm 包，**许可上不能随包分发**。
  所以离线路径 `-Agent` 默认 `none`；要会议纪要 / 归档 / 语音指令的智能体时，
  仍走 `echo-install` 技能第 5 节（联网 + npm/npx 缓存）那条路，或用已装的 DSH 桌面版。
* **模型只带 sherpa 流式那一个**（189 MB）：唤醒词 KWS（40 MB）、whisper-tiny/base/small/
  medium/large-v3、SenseVoice、Qwen3-ASR、pyannote 三件套都**不随包**（最小档的定义）。
  要它们在面板 →「能力」里按需下载（联网）。`-Profile main -Offline` 会因为"包里没有唤醒词模型"
  自动把唤醒词跳过并明确告警。
* **torch 系（SenseVoice / pyannote / Qwen3-ASR / CUDA）**：不打（铁律 L1，`profiles.json` 的
  forbid 清单）。`build_min_kit.py` 的自检里有"最小档不许带 torch"这条，带了就出不了包。
* **`onnxruntime` 打进了 wheel 但默认不安装**：ECHO 的 `app/` 里没有任何 `import onnxruntime`
  （sherpa-onnx 1.13 起把原生库拆到 `sherpa-onnx-core` 了）。它在包里是"保险"，
  要装就用同一条离线命令：`pip install --no-index --find-links bundle\wheels onnxruntime`。
* **VC++ 2015-2022 运行库**：装不了（要管理员 + 联网下载 `vc_redist.x64.exe`）。干净镜像上
  缺它时，`sherpa-onnx` 会以 `DLL load failed` 失败 —— 组件脚本会明确指出来。
  内网机器最好提前装好。
* **macOS 没有离线最小包**：`build_min_kit.py` 只出 Windows（`装我.cmd` + cp311 win_amd64 wheel）。
  mac 侧继续用原来的技能路径。
* **本包不含"解压即用"的 runtime-core**：运行时是在目标机上造的（uv 缓存 / 本机 Python 3.11 /
  包里的嵌入包）。三种都没有时，离线装不了 —— 而这三条在 Windows 上基本覆盖得住
  （嵌入包那一条在裸机上实测通过）。

## 6. 出包与维护

```powershell
python scripts\build_min_kit.py                 # 出主包 + 组离线最小包 + 自检
python scripts\build_min_kit.py --reuse-main    # 复用 dist 里已有的主包（注意：主包必须比源码新）
python scripts\build_min_kit.py --engines sherpa,whisper-base   # 想把别的档也打进去
python scripts\build_min_kit.py --wheels-from-env  # 用本机已装版本号钉住 wheel（可复现）
python scripts\build_min_kit.py --no-runtime / --no-models       # 缩包（裸机装不了 / 无模型）
```

* kit zip 的条目一律带 `ECHO-kit-min-<stamp>/` 顶层前缀（复用 `build_kit.make_zip`）。
* 自检（出包时自动跑）会拦下：技能与仓库不一致、主包里没有 `install-all.ps1`、
  wheels 里缺关键包、模型文件不全、**带了 torch**、kit 里混进 DSH 载荷。
* wheel 先落到 `dist\_offline-cache\wheels`（跨次复用，`pip download` 对同名文件直接跳过），
  再拷进 kit —— 重出包不用重新下载。
* **编码纪律**：含中文的 `.ps1` 必须 UTF-8 **带 BOM**（`edit` 工具会抹掉 BOM —— 改完确认一次，
  或跑 `tests/test_script_encoding.py`）；`装我.cmd` / `install-offline.ps1` 刻意**纯 ASCII**。

## 7. 顺手修掉的一个坑（影响旧路径）

`requirements-core.txt` 是 UTF-8（里面有中文注释），而 pip 读 `-r` 文件时，如果没有 BOM 也没有
PEP 263 的 coding 声明，会按 **locale 编码**解码 —— 中文 Windows 上是 GBK，于是：

```
UnicodeDecodeError: 'gbk' codec can't decode byte 0x80 in position 29
```

`scripts/install.ps1` 的第 5 步与 `app/components.py` 的组件安装都是 `pip install -r <文件>`，
**在中文 Windows 上必然踩到**（本机实测复现）。修法是第一行加 coding 声明：

```
# -*- coding: utf-8 -*-
```

`requirements-core.txt` 与 `requirements.txt` 都已加（各一行注释，其余内容不动；pip 与
`tests/test_default_profile.py` 都会跳过注释行）。

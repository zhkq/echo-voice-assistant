## Release 正文原文

# ECHO v2.0.2 — 补丁版

修一个**一眼就看得见**的毛病：**启动后屏幕上会多出一个空的终端窗口**，一直不走。

## 修了什么

ECHO 的运行时是 uv 建的 venv，它的 `Scripts\pythonw.exe` 其实是个 **trampoline** ——
会再 re-exec 一个**控制台子系统**的 `python.exe`。而 `Start-Process` 没有 `CreateNoWindow`
开关，`-WindowStyle Hidden` 又只管住第一个进程；那个可见的控制台是**孙子进程**自己开的，
于是被系统默认终端应用（Windows Terminal）接管成一个可见标签页，标题就是 pythonw 的路径。
实测 `pythonw.exe -m app.main` 与 `WindowsTerminal.exe -Embedding` 出现在**同一秒**；
ECHO 不退出，这个窗口就不消失。

修法：新增 `scripts/echo-launch-lib.ps1`，用 .NET `CreateNoWindow = $true`
（= `CREATE_NO_WINDOW`）启动，trampoline 拿到的是"没有窗口的控制台"，后代全部继承。
`start.ps1` / `startup.ps1` / `launch-desktop.ps1` 三处启动点统一改用它。
日志重定向照旧（改用 `cmd /c` 直接写文件，而不是 .NET 管道 —— 管道需要活着的读端，
而 `start.ps1 -Background` 启动完就退出）。

## 已经在跑 2.0.0 / 2.0.1 的

**不用重装。** 想自己修的话，把这三处启动方式换掉即可：

```powershell
# 用 .NET 的 CreateNoWindow 启动，而不是 Start-Process
# scripts\echo-launch-lib.ps1 里有现成的 Start-EchoProcess；三个启动点都改用它
```

或者直接下 2.0.2 的包装一遍（数据、模型、会议记录都在 `data\` 与 `models\`，不受影响）。

> 2.0.1 修的是会议转写 / GPU / 侧栏分组；2.0.2 只多了这一个窗口修复，其余完全一致。

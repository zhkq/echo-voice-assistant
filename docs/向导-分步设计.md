# 首装向导 · 分步设计（D23/D24）

> 定位：把 `REFACTOR-PLAN.md` §6.2.2 的向导要求落成一份**顺序清晰、每步意义明确**的设计。
> 两条关键改动：① 把"边走边下"改成 **决策相 → 确认 → 执行相**；② 读者假设是
> **没用过 ECHO、也没有技术背景的同事** —— 向导同时承担"配置"与"产品入门"两个职责。

## 0. 读者假设与文案规范

### 0.1 读者假设（写进验收，不是口号）

- 没用过 ECHO，不知道"模型 / 引擎 / 转写 / provider"是什么；不知道 DSH、Python、CUDA。
- 不懂命令行，**不会去查文档** —— 向导是他们唯一的说明书。
- 会一路点"下一步" —— 所以**默认值必须是"这台机器上最省事且能用"的组合**。
- 怕点错、怕占空间、怕弄坏电脑 —— 任何一步都要让他们确信"**还能改、不会坏、随时能补**"。
- 关心的是"我能拿它干什么"，不是"它有几个 GB、用什么框架"。

### 0.2 文案三原则

1. **先说场景，再说功能，最后才（可选地）说技术。**
   ✅「开完会把录音丢进去，它自动变成带说话人的文字稿」 ❌「sherpa-onnx 流式转写引擎 189 MB」
2. **每个技术词首次出现就地用一句白话解释**（括号内），之后才可以用词。全流程维护下面的术语表。
3. **"不做会怎样"永远说"你会失去什么"**（红字一句），不说"依赖缺失 / 不可用 / 组件未安装"。

### 0.3 术语 → 人话对照表（**验收时逐项对照**）

| 内部说法 | 界面上怎么说 |
|---|---|
| 组件 / 模型 / 载荷 | **能力包**（首次出现加一句："要额外下载、下载完就多一项本事"） |
| 转写引擎 | **把录音变成文字的方式** |
| sherpa-onnx（流式） | 边听边出字；**不需要独立显卡**，最省内存 |
| faster-whisper / Whisper 各档 | 另一种转字方式；档位越高越准、也越慢 |
| SenseVoice | 擅长中文短句（默认适合日常口述） |
| Qwen3-ASR | 擅长方言口音；**需要独立显卡**，否则慢很多 |
| 唤醒词 / KWS | **喊一声就开始**（不用按快捷键） |
| 说话人分离 / pyannote | **自动区分"谁在说"**（会议用） |
| GPU / CUDA / 显存 | **独立显卡 / 用显卡加速 / 显卡内存** |
| runtime-core | **基础运行环境**（自动装，用户无需理解；界面上不出现英文名） |
| modelsDir | **能力包存放位置** |
| provider / OpenAI 兼容 / 内网网关 | **AI 服务**（用来写纪要的那个"大脑"） |
| agent-dsh / 独立 harness | **让 ECHO 能动手**（帮你操作电脑、整理笔记）；不暴露产品名 |
| 离线兜底 | **断网也能用的小号能力包** |
| torch / pip / 轮子 | 界面上一律不出现；需要时统一说"自动准备（可能要几分钟）" |
| 笔记库 / vault / worklog | **你的笔记库**（比如 Obsidian 里放工作日志的地方）；"归档"说成**把纪要存进笔记库** |
| 在线转写 | **把录音发给在线服务转成文字**（本机不占空间，但录音内容会出网） |

### 0.4 默认即安全 + 主按钮

- 每一步**进来时默认已经勾好**"这台机器上最稳的组合"：
  - **智能体后端默认 = 标准 DSH**（`agentBackend` 的默认值本来就是 `dsh`；向导不是"问要不要装"，
    而是"检测 + 引导它跑起来"，独立 harness 作为可替代项）。
  - **转写方式默认 = 本机最轻的那档**；若体检判定这台机器跑不动本地转写，
    默认改为 **在线转写**，并明确提示"录音会发给在线服务"。
- **AI 服务（S6）刻意没有默认**：那是用户**自备**的（自己的地址/密钥），ECHO 不提供也不代管 ——
  这一步默认是"稍后自己配"，并写清"不配就不能自动写纪要"。
- 主按钮固定是 **「按建议装上」**；次要按钮是 **「这次不用」**。
  "我懒得挑"和"我不确定"必须都能一键通过 —— 否则同事会卡在每一步。

### 0.5 失败文案规范

四段式，**不出现错误码与堆栈**（堆栈只在"查看详情"里折叠）：

```
✗ 「中文短句」没装成
  大概是因为：网络断了或下载超时（这台电脑的网络检测：ModelScope 不可达）
  你可以：① 重试一次  ② 改用离线能力包（我会告诉你去哪拿）  ③ 先跳过
  跳过的话：录音不会自动变成文字，其它功能不受影响，以后随时能补
```

### 0.6 向导也是"产品入门"

- 每步卡片右上角有一个 **「这是什么？」** 可展开说明（教学位，不占主视觉）。
- 走完向导，用户应该能回答三个问题：**我现在能干什么 / 还不能干什么 / 以后怎么补**。
- 因此最后一页（S11）不是"组件清单"，而是**能力清单**（见 §8）。

## 1. 为什么两相分离（决策完再动手）

原设计隐含"选完即装"。问题：选错要卸载删除才能改；下到第 4 项才发现盘不够；
**中断即半装**；而"AI 服务"这类**只写配置不下载**的决策无处安放。
对小白读者，这些代价更重 —— 他们最怕的就是"点了就停不下来"。

三条硬规则：

1. **决策相（S0–S8）只读**：不发下载请求、不写设置。只调 `/api/components`、`/api/paths/env`、`/api/wizard/env`。
2. **确认页（S9）是唯一闸门**：点"开始准备"之前，一切都不落地。
3. **执行相（S10）不再问任何问题**：只有进度、重试、跳过。

## 2. 步骤顺序

分层原则：**先约束 → 再"能不能用" → 再"好不好用" → 再"连哪个大脑" → 再兜底 → 复核 → 执行。**

| # | 界面上的名字 | 决策内容 | 为什么在这个位置 | 不做会怎样（界面原话） |
|---|---|---|---|---|
| **S0** | 检查你的电脑 | 无（自动） | 后面每步"推荐哪个"都靠它 | — |
| **S1** | **东西放在哪** | **三处位置**：能力包 / 会议文件 / **笔记库**（各自所在盘的剩余空间） | 后面每步都报体积，**要先有基准盘来比**；笔记库决定"纪要归档能不能用" | 空间不够会中途失败；不指笔记库，纪要就只能留在 ECHO 里 |
| **S2** | 把录音变成文字 | 转写方式：**本机（轻/重）或在线** | "能不能用"优先于一切性能问题；**机器配置不够时在线就是正解** | 录音不会变成文字，纪要与指令都用不了 |
| **S3** | 喊一声就开始 | 唤醒词 | 能力层，成本小但隐私代价特殊 | 只能用热键/按钮开始录音 |
| **S4** | 分清谁在说话 | 说话人分离 | 能力层末尾：需要**外部授权** | 会议记录里分不出谁在说 |
| **S5** | 用显卡加速 | 显卡加速（仅 N 卡出现） | **必须在"本机转写"之后**：加速"谁"要先有谁 | 能用但慢 5–10 倍；**选了在线转写就没这一步** |
| **S6** | 让 ECHO 会写纪要 | **AI 服务（自备）**：填自己的地址/密钥 | 唯一不占空间的一步；ECHO **不提供也不代管** | 不能自动生成会议纪要 |
| **S7** | 让 ECHO 能动手 | 智能体后端：**① DSH 标准版（默认，可一键下载部署）/ ② 已有桌面客户端 / ③ 先不用** | 默认项 —— 不是"要不要装"，而是"帮你把它跑起来" | 不能帮你操作电脑、整理笔记（**不影响转写与纪要**） |
| **S8** | 断网也能用 | 小号能力包 | 前面选完才知道还需不需要（**选了在线转写的尤其需要**） | 断网时没有本地转写 |
| **S9** | 确认一下 | 复核 / 返回修改 | 唯一闸门 | — |
| **S10** | 正在准备 | 无（只有进度） | 统一落盘 + 统一下载 | — |
| **S11** | 你的 ECHO 现在能做什么 | 无 | 向导末页 = 日常「能力」页的同一套渲染 | — |

三条与顺序有关的说明：

- **S1 为什么是三处位置而不是一处**：能力包（最占地方）、会议文件（含原始录音，涉及隐私）、
  笔记库（归档目的地，通常是你**已有的** Obsidian 库）。三者可能落在不同盘，
  所以空间判断必须**分别做**，并在这一步就把"哪个盘不够"说清楚。
- **S2 的三条路**：① 本机轻量（不需要独立显卡）② 本机重量（要显卡，更准）
  ③ **在线转写**（本机不装任何东西、不占空间；需要联网，**录音会发给那家服务**）。
  体检结论直接决定默认与推荐：机器够 → 本机；机器不够 → 在线，并如实说明出网。
- **S5 是条件步**：没有独立显卡、或 S2 选了在线 → 这一步自动折叠成一行说明（"用不上，因为你选了在线转写"），
  不占用户注意力。

### 2.1 S7 的可自动化程度（决定按钮长什么样）

| 选项 | 现在能不能自动 | 依据 / 缺什么 |
|---|---|---|
| ① **DSH 标准版**（官方独立发行版，npm `@deepseek-ai/dsh`） | **能，全自动** | `app/harness_proc.py` 已具备完整链路：`npx -y @deepseek-ai/dsh web` 拉起子进程 → 探活 → 从 stdout 抓登录 token → 记 pid → 切走时杀整棵树。**`npx` 首次拉包就是"下载"**，所以"下载并部署"是一个动作 |
| ② 已有 DSH 桌面客户端 | **只能引导 + 检测** | `app/agents/dsh_agent.py::available()` 只做诊断（401 → 引导开"普通浏览器访问"；无凭据 → 问是否登录过；连不上 → 未运行）。**仓库里没有桌面版的下载源**，也不应替官方分发 |
| ③ 先不用 | — | 只影响"调技能 / 归档"，**不影响转写与纪要** |

由此三条界面规则：

- ① 的按钮是 **「帮我装好」**（进执行相，展示真实进度）；② 的按钮是 **「我装好了，检测一下」**
  （立即探 `127.0.0.1:43120`）；③ 是 **「以后再说」**。
- ② 选中后，向导要**顺带把 DSH 侧的开关也引导一遍**（在那台 DSH 里打开"普通浏览器访问"），
  否则检测必然 401 —— 这是用户最容易卡住的一步，不能只丢一句"连不上"。
- **缺少 Node.js 时 ① 不许假装能装**：向导给"装 Node.js 的入口 + 我装好了，检测"，或改选 ②。

**待补**：桌面版的官方下载地址、以及是否允许 ECHO 代为下载安装。确认之前，① 是唯一"一键"路径。

每步三个出口：**「按建议装上」**（主）/ **「这次不用」** / **「全按建议来」**（跳过整段）。
跳过会在确认页与末页登记后果。

```
┌──────────────────────────────────────────────────────────────┐
│ 把录音变成文字                                    [这是什么？] │
│                                                              │
│ ① 这是干什么的                                                │
│    开完会、说完话，录音丢给 ECHO，它自动变成带标点的文字稿。    │
│    （日常口述、会议记录都靠它）                                │
│                                                              │
│ ② 不装会怎样                                                  │
│    录音不会变成文字 —— 会议纪要和"发指令"都用不了。            │
│                                                              │
│ ③ 你要决定什么（默认已经帮你选好了）                           │
│    ● 中文短句（推荐）   约 896 MB · 大约 900 首歌的大小        │
│    ○ 边听边出字         约 189 MB · 最省内存，不需要独显        │
│    ○ 更准的档位         约 464 MB · 更准，也慢一些             │

│                                                              │
│    这台电脑：剩 123 GB，够用 ✓                                 │
│                                                              │
│  [ 全按建议来 ]                    [ 这次不用 ]  [ 装上 ✓ ]   │
└──────────────────────────────────────────────────────────────┘
```

- **禁用而非隐藏**（D24）：不满足条件的项灰掉并写"为什么 + 怎么办"，例如
  「需要独立显卡 —— 这台没有；装它也能用，但会慢约 20 倍，所以建议先不装」。
- **体积用人话换算**（"约 900 首歌的大小"），精确 MB 放次行小字。
- 底部恒定一条**计划条**：`已选 2 项 · 合计约 1.1 GB · 盘剩余 123 GB · 预计 5 分钟`。
  随时看得见取舍的代价 —— 这是"逐步确认"能成立的前提。
- 每步的 **「这是什么？」** 折叠块回答：它解决什么问题、什么时候会用到、和别的东西什么关系。

### 3.1 一段完整文案样例（S2；其余各步照此写）

> **把录音变成文字**
> **这是干什么的**：开完会、说完话，把录音丢给 ECHO，它自动变成带标点的文字稿。ECHO 的
> "会议纪要"和"语音指令"两项功能，都建立在"先把声音变成文字"之上。
> **不装会怎样**：录音不会变成文字；会议纪要和语音指令都用不了（其它功能不受影响）。
> **默认建议**：中文短句。它是 ECHO 的默认方式，**不需要独立显卡**，中文标点也最准。
> 想更省内存就选"边听边出字"；想要更准可以再加一个"更准的档位"——两个可以同时装，
> 日常口述用快的、正式会议用准的。
> **这台电脑**：有独立显卡（NVIDIA，8 GB 显卡内存）→ "方言口音"也能装，但占用较大，不是必须。

> **还有一条路（这台电脑跑不动本机转写时）**：**在线转写** —— 把录音发给在线服务转成文字，
> 本机什么都不用装、不占空间；代价是需要联网，**录音内容会发给那家服务**。
> 体检如果判定本机跑得动，默认就不选它；跑不动时它才是默认。

### 3.2 一段完整文案样例（S7；"可选"与"一键"的分界）

> **让 ECHO 能动手**
> **这是干什么的**：上面几步让 ECHO 能"听懂"和"写字"，这一步让它能**动手** —— 比如把会议纪要
> 存进你的笔记库、按你的话去操作文件。不装它，转写和纪要照样能用，只是这些"动手"的活干不了。
> **你要决定什么**（默认已选第一项）：
> - ● **DSH 标准版（推荐）**　点一下我来准备：需要联网，**大约几分钟**；以后归我管，你不用管它。
> - ○ 我已经装了 DSH 桌面客户端　　我会自动找到它并检查能不能用（连不上我会告诉你怎么开）。
> - ○ 先不用　　以后想加：面板 → 能力 → 随时补。
> **如果这台电脑没装 Node.js**：我会告诉你，并给两条路 —— ① 给你一个安装入口，装完回来点
> "我装好了，检测"；② 换成"我已经装了桌面客户端"。
> **体积与耗时**：以实测为准（`npx` 首次拉取的时间取决于网络），**界面上不写估算值**。

## 4. 执行相（S10）的语义

- **服务端执行**：下载跑在 ECHO 服务里（后台线程），**关面板、切页签都不中断**
  （复用现有 `POST /api/models/download` + `GET /api/models` 的 `jobs`）。
- **固定落地顺序**：① 写配置（存放位置等，先落盘）→ ② 基础运行环境 → ③ 转写方式
  → ④ 显卡加速 → ⑤ 小号兜底。
- **每项状态用人话**：`排队中 / 正在下载 42%（约还需 2 分钟）/ 正在准备 / 好了 / 没成 / 已跳过`。
- **失败**：`重试` / `跳过`；跳过即登记"因此不能做什么"。
- **可中断可续**：进度持续落盘，重开面板提示"上次装到一半，继续吗？"。
- 结束时写 `data/installed-components.json`（**面板据此显示状态，不靠扫目录猜**）。

## 5. 状态与落盘

| 文件 | 内容 | 谁写 |
|---|---|---|
| `data/wizard-plan.json` | 状态(draft/reviewing/running/done) + 环境快照 + 用户选择 + 计划 + 进度 | 决策相每次改动即落盘（可续） |
| `data/installed-components.json` | 执行后的"真值"：每项 已装/路径/时间 | 执行相 |

`settings` 只在执行相第 ① 步写；决策相的"选择"是**计划**，不是已生效配置。

### 2.3 实测挖出来的问题（都已修 + 已钉）

| 问题 | 症状 | 钉在哪 |
|---|---|---|
| 幽灵槽 | `variant=short` 一律 404（要的 `asr.short` 没人提供），默认 `long` 把用例全带绿 | `SlotRoutingTests` |
| 宣告 ≠ 可路由 | `capabilities` 说能做 `asr.timestamps`，路由却 404（同一份事实算两遍） | `SlotRoutingTests` + `pool.slots()` 单一来源 |
| 静默回退 CPU 只堵住一半 | 判据笼统问 CUDA；**向量类加载器压根没查设备**，pyannote 那句 CPU 回退在服务端可达 | `DeviceAssertionTests` |
| **撤销在唯一运维入口上是假话** | 命令行 `--revoke` 后，跑着的服务继续接受旧 JWT（轮询没实现） | `AuthTokenTests`（跨进程用例） |
| **持久凭据落在可丢弃目录里** | 鉴权库缺省落 `tmp.root`，而文档建议 tmp 挂 tmpfs → 所有客户端一起没了 | `EnvOverrideTests` |
| 部署文件里的环境变量没被读 | `ECHO_STATE_ROOT` 只写在注释里 | `EnvOverrideTests` |
| **`max_concurrent: 2` 是假的** | `async def` 端点里阻塞推理按住事件循环 → 请求全串行，`busy.active` 全程 0 | `EventLoopNotBlockedTests` |
| **大 body 出错时错误码消失** | 没读完 body 就关连接 → RST 丢掉响应体；2 KB 正常、0.9 MB 为空，且是竞态 | `ErrorCodeSurvivesLargeBodyTests`（真 socket） |

**共同形状**：都是"用例全绿、东西是坏的"，而且**只有真的把服务跑起来发请求才会暴露**。
所以两条通用教训值得记住：

1. **测试手段必须配得上被观测的现象** —— `TestClient` 会把请求串起来发，
   测不出并发；进程内 ASGI 不经过 socket，测不出 RST。
2. **同一份事实只许算一遍** —— 槽表、`vectorSpaceId`、配置默认值，
   凡是两处各算一遍的，迟早漂。

### 3.1 待拍板：降级原因词汇表不够用（2026-09-24 落地客户端时发现）

权威词汇（`统一路由` §2）只有十个：`absent / blocked / busy / circuit-open / offline /
open-failed / quota / unsupported / vector-mismatch / error`。但服务端 §6.3 的错误模型里
有几档它**明确要求分开**的：

| 服务端坚持要分开的 | 权威词汇里有对应词吗 |
|---|---|
| `client_busy`（自己占着，重试永远没用） vs `server_busy`（系统忙，该退避重试） | ❌ 只有一个 `busy` |
| `model_loading`（该等一会儿） | ❌ 没有"正在加载"这一档 |
| `unauthorized` / `forbidden`（凭据/权限） | ❌ 没有 `auth`（`能力路由` §5.2 那版**有**，权威版没有） |

**服务端那句话是**："合并成一个码，客户端就只能盲目重试" —— 而权威词汇把它们合并了。

**当前的做法（信息一点没丢，也没擅自扩词汇）**：两套词各管一件事 ——
* `reason`（权威词汇）只回答"**这一轮换不换这个后端**"；
* `code` + `retryable`（本层自己那张表）回答"**客户端该干什么**"
  （`client_busy` → 不重试；`server_busy` → 退避重试）。

**建议拍板**：要么给权威词汇加 `loading` / `server-busy`（`auth` 那档也补回来），
要么在 `统一路由` §2 里写死一句"**词汇表只管候选筛选；行为一律看 `code`**"。
两条都行，但**得选一条** —— 现在这个含糊是四域统一词汇这件事本身漏出来的。
契约由 `tests/test_capabilities_contract.py::ServerCodeCoverageTests` 钉着
（服务端每个错误码都必须有 reason + retry 策略，加了码不跟就红）。

### 2.4 管理动作（2026-09-24 补齐到命令行）

`server/main.py` 的命令行入口现在齐了，**运维不需要网页也能干活**：

```bash
--new-client "张三的办公本" --scopes "asr diarize"   # 新建 = 发一张带名字与 scope 的码
--new-pairing-code                                 # 只发码（名字/scope 由对端自报）
--list-clients / --list-codes / --show-client ID   # 看
--revoke ID                                        # 撤销（版本号 +1，立即失效）
--disable ID / --enable ID                          # 禁用（403）/ 启用（原令牌直接能用）
--set-scopes ID --scopes "asr"                      # 改权限，**下一个请求**就生效
--rotate-secret ID                                  # 换 secret；旧令牌与旧 secret 立刻全失效
```

三条容易搞错的语义（都已写进用例）：

1. **名字 / scope 跟着码走**，而且**码上带的盖过对端自报的** ——
   自报的能改名，那份清单就不算清点了。为此 `pairing_codes` 加了 `name` / `scopes` 两列。
2. **`--rotate-secret` 同时 bump `token_version`**：v1 没有宽限期，客户端本来就要重新配对，
   所以不给"旧 JWT 还能再用一小时"的窗口（留着反而让人以为轮换没生效）。
3. **`--enable` 之后不需要重新换令牌**（`disabled` 与 `token_version` 是两回事）。

`CREATE TABLE IF NOT EXISTS` 不会给已存在的表补列，所以加了一段**最小的补列迁移**
（已存在的库自动补上，数据不丢）。再多就得换真正的迁移工具。

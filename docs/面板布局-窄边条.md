# 面板窄边条布局：契约与验证方式（2026-09-19）

> 起因（用户实测截图）："这个页面的宽度有问题，需要重新整理" —— DSH 边条里的
> 「模型路由」页整页右侧被裁掉：卡片、按钮、下拉全部出血。
> 本文记录**真因、修法、以及以后怎么自己看到**（不用等人截图）。

## 1. 真因：`main` 被排成 max-content

窄边条样式下（`@media (max-width: 720px)`）有这么两件事：

```css
body { display: flex; flex-direction: column; }   /* 顶部第 574 行附近 */
main { margin: 12px auto; }                         /* 居中外边距 */
```

`body` 是 flex 列容器，`main` 是它的 flex 子项。**交叉轴上的 `margin: auto` 会让
`align-self: stretch` 失效** —— 于是 `main` 不再撑满容器，而是按自己的
**max-content 宽度**排版（内容里最宽的那条链决定）。实测：

| 视口 | `main` 实际宽度 | 结果 |
|---|---|---|
| 384（iframe 里量的） | 508 | 右侧 124px 被裁 |
| 645（DSH 边条 150% 缩放 ≈ 用户的真实视口） | 645+ | 设置/路由参数那几行被裁 |

撑宽它的具体内容通常是"`<select>` 的最宽选项文字"（`<select>` 的 min-content 就是它）
以及"设置行 = 180px 标签 + 280px 控件 + 说明"这一整行。

## 2. 修法（四条，删任何一条都会复发）

`web/app.css`：

```css
main { max-width: 1200px; width: 100%; margin: 12px auto; padding: 0 14px; min-width: 0; }
body { min-width: 0; }
.card { ... min-width: 0; }
.card-title { ... flex-wrap: wrap; min-width: 0; }   /* 标题 + 长说明要能换行 */
select.ctl, input.ctl { min-width: 0; max-width: 100%; }   /* 下拉必须能收缩 */
.settings-form, .set-row, .mcard, .mcard-body, .rt-list, .rt-row, .rt-add,
.agent-field, .cap-prov, .cap-pick, .cap-online, #rtSetHost, #rtLlmHost { min-width: 0; }
```

一句话：**给 `main` 确定宽度（`width: 100%`），其余能收缩的都允许收缩。**
守卫测试：`tests/test_panel_layout.py`（5 条，盯住上面这些声明，删掉就红）。

## 3. 怎么自己看到（无头 Edge 截图，不需要开浏览器）

```powershell
$edge = "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"
# 边条的真实宽度：450 逻辑像素在 150% 缩放下约 645 CSS px
& $edge --headless --disable-gpu --no-first-run --disable-sync --hide-scrollbars `
  --user-data-dir="C:\echo-dev\dist\_edgeprofile" `
  --window-size=645,1450 --virtual-time-budget=12000 `
  --screenshot="C:\echo-dev\dist\_shot.png" "http://127.0.0.1:18060/?view=failover"
```

然后用看图工具打开 `dist\_shot.png`（本会话里就是 `read_image`）。要点：

* **`--virtual-time-budget`** 必须给（≥8000）：面板有 6~8 个并发请求，太早截图会拍到空白；
* **`--user-data-dir` 用临时目录**：不要污染你自己的 Edge 配置，也避免两次运行撞 profile；
* **窗口宽度别小于 ~500**：Edge 有最小窗口宽度，传 384 时会得到"视口 504、截图 384"
  的假象（我第一次就这么误判过）；要测更窄的情况，用下面的 iframe 办法；
* 每换一次 `app.css` 都要重截（后端对这个目录是 `Cache-Control: no-store`，不用清缓存）。

**量具体数字（比看图更硬的证据）**：造一个临时页面，把面板放进指定宽度的 iframe，
在里面数 `getBoundingClientRect().width / scrollWidth / clientWidth`：

```html
<iframe id="f" src="/?view=failover" style="width:384px;height:900px;border:0"></iframe>
<script>
setTimeout(() => {
  const d = document.getElementById("f").contentDocument;
  for (const s of ["html","body","main",".view:not(.hidden)","#settingsForm"]) {
    const el = d.querySelector(s);
    console.log(s, el.getBoundingClientRect().width, el.scrollWidth, el.clientWidth);
  }
}, 7000);
</script>
```

判据：`main` 的宽度必须等于 `html.clientWidth`；任何元素 `scrollWidth - clientWidth > 8`
都说明它在溢出（`<input>` 里的长文本除外 —— 那是它自己的横向滚动，不影响页面）。
量完记得把临时页面删掉（`web/` 下的静态文件会被后端直接对外提供）。

## 4. 已知的、故意保留的行为

| 现象 | 说明 |
|---|---|
| `html, body { overflow-x: hidden }` | 兜底：万一还有残留溢出，宁可裁掉也不给整页横向滚动条（但现在不该再有残留） |
| 长文本 `<input>`（极简回复文案 / 归档提示词模板）横向可滚 | 单行输入框的固有行为，不是布局问题 |
| 宽屏（>860px）下设置行仍是"标签 + 控件 + 说明"一行 | 窄边条才换行；两条样式都在，靠 media query 切换 |

# ECHO 3.0 试用手册（一页纸）
> **这份东西是为什么写的**：3.0 的每一块都有用例钉着（1477 条），但**配对 → 选后端 →
> 会议走 GPU 这条链，从来没有人真的操作过一遍**。契约用例跑的是真 uvicorn + 真 HTTP，
> 可那是测试进程，不是一个人在面板上点。
>
> 照这份走一遍，能把"纸面上通了"变成"真的通了"。**全程不需要动稳定版**：手册里给的
> 是一条 dev 路线（另一个端口、另一份 `data/`）。

---

## 0. 先想清楚要哪一档

| 档 | 装什么 | 会议转写谁做 |
|---|---|---|
| **默认档（办公本）** | `requirements-core.txt` + `runtime-core` / `stt-sherpa` / `wake-kws` ≈ 600 MB | **GPU 后端**（本机不做兜底） |
| 离线增强档 | 再加 whisper / SenseVoice 等模型（按需，不是一档全装） | 可以本机 |

档位的权威表是 `components/profiles.json`（默认档**不含 torch**，有 15 条用例守着）。

**什么都不配就是 2.0 的行为** —— 不配对、不选后端时，链路与本机版完全一样。

> **会议转写有三条路**（2026-09-28 起，首装向导第 8 步就会问，见设计 §6.6）：
>
> | 路 | 怎么连 | 代价 |
> |---|---|---|
> | ① **本机后端** | 后端装在这台机器上 —— 客户端点「检测本机后端」，**读本机那份 `local-pair.json` 自动配对**（同机不用抄配对码） | 要有显卡；多一个常驻服务 |
> | ② **同事的后端** | 管理员给你一张配对串，粘一次（就是本手册 §2–§4 那条路） | 会议音频发到**内网**那台机器 |
> | ③ **在线（千问AI平台）** | 面板/向导里填平台的密钥，选「网络服务商」 | **整场会议音频发到公网**；而且它**只回说话人编号、认不出联系人** |
>
> 三选一的边界、隐私红线（**不许从 ② 自动降级到 ③**）与"哪些能自动、哪些要人点"写在
> `docs/3.0-设计总览与组件关系.md` §6.6。本手册下面 §1–§9 走的是 ② 那条路（它最长、
> 也最能说明"配对 → 选后端 → 会议走 GPU"这条链）。

### 0.1 本机后端（方案 ①）：不抄码的那条路

后端与客户端在同一台机器上时，**后端启动会自己写一份配对信息**
（`{state_root}/local-pair.json`，与鉴权库同一个目录；容器里就是那个 state 卷）：

```bash
# 后端侧：compose / 后端包默认就是开的
ECHO_LOCAL_PAIR=true
```

客户端侧（面板 → 「能力」页签 → 配对区）：

1. 点 **「检测本机后端」** —— 读到文件就自动走完配对，落盘仍是 `data/backend.json`，
   和粘配对串**产物完全一样**。
2. 按钮**点不动**时会当场写清为什么：没找到（后端还没起）／配对信息已过期
   （**在后端那台机器上重启一次后端**就会重发一张）。
3. 容器把状态卷挂在别处时（Docker 的宿主路径猜不出来），在
   **设置 → 能力 → 本机配对文件路径**里填它的宿主路径，或设环境变量
   `ECHO_LOCAL_PAIR_PATH`。

> 为什么不做"回环免令牌"：那等于**本机任何进程都能白用这块 GPU**。文件握手复用的是
> 同一套凭据信封与 TLS 指纹固定，代价更小、语义更清楚（设计 §6.6）。

## 1. 起一台后端（dev 路线）

```powershell
# 在后端那台机器上（dev 树里）
python -m server.main --config server\echo-server.example.yaml
# 或者容器里：docker compose -f server\compose.yaml up
```

三条探针，**先确认它活着**：

```powershell
curl http://<后端>:8900/v1/health        # ok + 队列/显存/临时目录/今日用量 + metrics
curl http://<后端>:8900/v1/ready         # 模型池可服务才 200（正在加载时 503 是有意的）
curl http://<后端>:8900/v1/capabilities  # 它能干什么：slots / models / limits（免凭据）
```

> 这三条**刻意不需要凭据**：探针和"配之前先看看它能干什么"都要能用。
> 真正要凭据的是三个推理端点。这条边界有用例钉着。

## 2. 发一张配对码（在后端机器上）

```powershell
python -m server.main --config server\echo-server.example.yaml `
  --new-client "我的办公本" --scopes "asr diarize embed"
```

它会打印一行可直接粘贴的串：

```
echo://pair?host=http://<后端>:8900&code=XXXXXXXX
# 配了 TLS 时（server.tls.certfile/keyfile）自动变成：
echo://pair?host=https://<后端>:8900&code=XXXXXXXX&fp=sha256:1f3a…
```

**整串粘给同事**，他不用把 host / code / 指纹拆开抄。三件事要注意：

* 串里的 **scheme 是服务端按自己有没有配 TLS 写死的**：客户端对不带 scheme 的地址
  默认按 http 处理，所以 https 后端必须写 `https://`（这一点 2026-09-24 真机联调时踩到过）。
* `fp=` 就是那张证书的指纹（`server.tls.certfile` 算出来的）。**客户端会拿它校验**，
  对不上直接拒绝配对 —— 那才是防中间人；没有它，第一次连接只能是 TOFU。
* 监听 `0.0.0.0`（出厂默认）时**不会**把通配地址给你 —— 那对客户端没有意义。
  打印的是一个探测到的本机地址，并附一句"连不上就换成同事能访问到的主机名/IP"。

**名字与 scope 跟着码走**（兑换出来的客户端就用它们），而且**码上带的盖过客户端自报的**。
码只用一次、默认 15 分钟过期。

## 3. 在客户端配对（面板）

1. 打开面板 → **「能力」页签** → 「**GPU 后端（ECHO 能力后端）**」那张卡。
2. 把**整串**（`echo://pair?host=…&code=…&fp=…`）粘进第一个框 → 点「配对」。
   只想分开填也行：地址（`10.100.0.24:8900` 这样写也行）+ 配对码。
   串里带 `fp=` 时面板会写一句"会按串里的指纹校验证书"，配不上会把原因原样显示出来。
3. 卡片上会出现一行「已配对：<后端>（cli-xxxx）」和每个后端的「能做：…」。

配完不用重启任何东西 —— 凭据落在 `data/backend.json`（Windows 上是 DPAPI 密文，
**不是明文**；Linux 上是 0600）。

## 4. 选"每个用途用哪个后端"

同一张卡下面三行，选中即生效（改完点保存）：

| 设置 | 默认 | 说明 |
|---|---|---|
| 会议转写用哪个后端 | `只用 ECHO 后端` | **没有"自动"**（2026-09-25 定）：选中的那个用不了时会**说清是哪一个、为什么**，不会悄悄换别的。三个取值 = `ECHO 后端`（含本机自建那台）/ `本机` / `网络服务商`（在线，方案 ③） |
| 说话人分离用哪个后端 | `自动` | 按默认链挑（ECHO 后端优先）；也可以点名只用某一家 |
| 声纹提取用哪个后端 | `自动` | 同上。**产出向量的能力只能落在能声明向量空间的后端上**（在线那一档不提供嵌入，见下） |
| **允许音频去哪** | `lan` | `none` = 不出机；`lan` = 允许发内网后端；`wan` = 还允许公网。**这是约束，不是优先级** —— 选在线（方案 ③）时它必须是 `wan`，否则那一档会被判 `blocked` |

> 想"锁死只用那台 GPU"就把三行都改成 `只用 ECHO 后端`。

### 4.1 方案 ③：在线转写（千问AI平台）

**平台是千问AI平台**（`https://maas.qianwenaiapi.com`），不是阿里云百炼 ——
两者接口形状几乎一样（同一套 DashScope 血统：`/api/v1/services/audio/asr/transcription`
提交、`/api/v1/tasks/{id}` 查询、`/api/v1/uploads` 取上传凭证），但**域名与 API Key 都不通用**
（2026-09-29 对着平台文档逐条核过；不带 key 打过去是 401，说明 host 与路径都在）。

面板 →「能力」→ 在线转写卡，三项（面板上是**隐藏设置**，向导第 9 步也会问）：

| 键 | 说明 |
|---|---|
| `capabilityAsrProviderApiKey` | 千问AI平台的密钥（`sk-ws-` 开头）。**填了才算配了这一路** —— 没填时路由里根本没有它（面板徽标会写「没配密钥」） |
| `capabilityAsrProviderBaseUrl` | 默认 `https://maas.qianwenaiapi.com`（**平台只有这一个域名，没有地域之分**）；只在走自建网关/代理时才填 |
| `capabilityAsrProviderModel` | 默认 `qwen-audio-3.1-asr-flash-filetrans`（整场异步 + 说话人分离）。**换模型时要留意**：同平台还有一支 `qwen3-asr-flash-filetrans`，它的请求里**没有** `diarization_enabled`，换过去会静默丢掉说话人 |

三条边界（面板文案里也有，不是只写在文档里）：

* **整场音频会上传到千问AI平台的临时存储**（48 小时后自动清理，上传凭证 300 秒有效）——
  所以 `允许音频去哪` 必须是 `wan`；
* **认不出联系人**：它只回 `speaker_id`、**不回声纹嵌入** → 会议里显示「说话人 1/2/3」，
  声纹库那一套在这条路上不参与；
* **一场会不许混来源**：`SAME_SOURCE_SLOTS` 会锁住向量空间 —— 一场会要么全程后端、要么全程在线。

平台侧还有三条**要按它设计**的约束（都写进了实现与用例）：

* 说话人分离**只支持单声道**，且官方建议音频 ≤2 小时（超了可能超时/失败）——所以这条路的
  音频是单声道、且默认按整场上限走；
* 上传凭证接口（`/api/v1/uploads`）**限流 100 QPS 且不可扩容，官方明确说别用于生产/压测**；
  临时 URL 与**模型**绑定（上传时指定哪个模型，提交时就必须用哪个），文件又与**主账号**绑定；
* 体积上限取"凭证里按模型给的 `max_file_size_mb`"和我们的硬上限里**小的那个** ——
  否则会在小模型上"传上去才发现不认"。

平台侧还支持几件我们暂时没用、但值得知道的：`parameters.keep_dialect`（保留方言，3.1 filetrans 专有）、
`vocabulary`/`vocabulary_id` 热词、`special_word_filter` 敏感词、`input.context` 上下文增强
（≤5 轮、每轮 text 合计 ≤400 字）。要用时走 `submit(..., parameters_extra={...})` 这个逃生口。
文档入口：<https://platform.qianwenai.com/docs/api-reference/speech-recognition/fun-asr-recording/restful-api>。

**实测（2026-09-29，10.8 秒音频走真平台）**：整条链成功，文本与句级时间戳都对，
单人音频给 `speaker_id=0`。**但要有预期：这条路的异步往返是分钟级** ——
同一段 10.8 秒音频两次分别等了 **31 秒 / 56 秒**（差异来自平台排队）。
所以会议转写走这条路时，面板上"等待后端"是正常状态，别当成卡死重试（重试会重复计费）。

实现细节（为什么整场一次提交、为什么不需要自备 OSS）见 `docs/3.0-设计总览与组件关系.md` §6.6。

## 7. 可选：TLS / 配额 / 管理面

**TLS**（`server.tls.certfile` + `keyfile`，两个都填才起 https）：

- 客户端**不需要装自签根** —— 配对时会把服务端证书固定下来，之后只认那一张。
- `--new-client` 打出来的配对串**带 `fp=sha256:…`**，面板粘整串就会按它对指纹：
  **对不上直接拒**（那才是真正防中间人的一步）；不带是 TOFU（首次连接即信任），
  这件事在文档里写明了，别当成等价。
- 服务端只配了 cert 或只配了 key 会**直接拒绝启动** —— 静默按 http 起等于让客户端
  明文上传音频（有用例钉着）。

**配额**：`--set-quota <client_id> --daily-audio-minutes 120`。用完回 `429 quota_exceeded`，
`Retry-After` 指到**本地明天 0 点**（实测 4648 秒）。两个注意：

* 它**不清零今天的已用量**；而且**最多 60 秒后才生效**（鉴权缓存了客户端那一行）——
  实测改完立刻打仍然 200，等缓存过期才是 429。要它马上生效就重启服务端。
* 配额用完时，**那一场会议的转写是失败（`status=error`、0 行）**，不会偷偷用本机转 ——
  日志里写着 `reason=quota code=quota_exceeded`（这正是"不兜底"该有的样子）。

**管理面（2026-09-25 起可写：发授权 / 客户端管理 / 审计）**：配置里设 `server.admin_listen`（例如 `127.0.0.1:8901`），
然后 `--new-admin ops`（口令只打印一次）→ 浏览器打开 `http://<host>:8901/admin/`。
五个页签：概览 / 模型 / 客户端 / 调用 / **存了什么**（最后一页读的是**活着的库**，
表名列名当场从数据库读出来）。**写动作故意只在命令行**。

> **面板里也有入口**（2026-09-28）：「能力」页签那张后端卡上，状态行（版本 / 显存 /
> 模型就绪数 / 今日用量）与「打开后端管理面」按钮读的都是后端 `/v1/health` 里
> **后端自己宣告**的 `adminUrl`。**同机才给按钮**（后端地址是回环时）；
> 远程后端那侧会改说"管理面只发布在后端那台机器的回环上，用 `ssh -L` 隧道" ——
> 因为它确实点不开，给一个点不开的链接比不给更难查。

## 8. "看起来坏了，其实是设计"

| 现象 | 为什么 |
|---|---|
| `409 client_busy` / `503 server_busy` | **服务端不排队**（`queue_max: 0`）：满了立刻拒，重试是客户端的事。`client_busy` 重试没用（是你自己占着），`server_busy` 才该退避重试 |
| `401 未授权或凭据无效` | 没配对 / 凭据失效 / 服务端换了 secret。面板卡片上会写原因 |
| `429 quota_exceeded` | 今天额度用完；`Retry-After` 是到**明天 0 点**的秒数，不是 5 秒 |
| https 被拒（"拒绝连接"） | 本机没有固定该后端的证书 —— **不静默跳过校验**是有意的 |
| `/v1/ready` 回 503 | 模型还在加载；等它，别反复重启（`/health` 一直 200） |
| `403 这个客户端没有 asr 权限` | 管理员给这个 client 的 scopes 不含该能力。**面板那张卡的后端状态不会因此变红** —— 它探的是免凭据的 `/v1/health`，所以这种问题要到**调用时**才暴露（会议详情那一行会写「被策略挡住」）。这是刻意的：面板状态回答"那台机器活着吗"，权限是另一回事 |
| 后端用不上时，会议**还是转出来了** | 这是**计划阶段**就用不上后端时的老路（例如「允许音频去哪」设成 `none`，或后端连不上导致能力探测为空）—— 那一场由本机引擎转，日志里有一句 `配了能力后端，但本场仍走本机引擎 —— 原因：…`，而且**详情页不会再显示上一次的计划**（没走能力层就把那一段删掉）。而**调用时**才失败的情况（配额用完 / 后端中途挂掉）**不会**退回本机：那一场是失败，详情页与日志都写原因 |

## 9. 怎么退回去

- **解除配对**：面板那张卡上的「解除配对」按钮（只忘掉本机凭据；服务端那本账归管理员）。
- **只用本机**：把三个"用哪个后端"改回 `只用本机` / `关掉`，音频就不出机了。
- 稳定版与 dev 版是**两棵树**：改 dev 不影响 `D:\ECHO`。同步稳定版只有一个入口
  （`scripts/deploy-stable.ps1`），而且要先 `-DryRun` 看计划。

  2026-09-29 已用无头 Edge 实测过**两页**：向导第 9 步（三条路 + 配对按钮 + 本机检测）
  与「能力」页签的后端卡（状态行 + 「打开后端管理面」），截图留档在
  `docs/面板-向导S8-三条路.png` 与 `docs/面板-后端状态与管理面.png`，
  配方与两个坑（必须 `--headless=new`、自动刷新会让 virtual-time 挂住）写在
  `docs/面板布局-窄边条.md` §3；**其余页面仍未实测**。
- `est_vram_mb` / `max_concurrency`：**仍是占位值**，要真 GPU 机器压测。
- **向导计划文件里的密钥** —— **2026-09-28 已收口**：`data/wizard-plan.json` 是明文草稿，

## 11. 装 ECHO 有两条路（与上面 §1–§9 的应用链路无关，但同事会先碰到）

> 详细说明、包体积、逐阶段实测耗时、以及"怎么证明没走网络"都在
> **`docs/3.0-离线最小包与快路安装.md`**。这里只留两行命令。

**快路（不绕助手；离线包连网都不用）**：

```powershell
# 离线最小包 ECHO-kit-min-*.zip：双击 装我.cmd；等价的命令行：
powershell -NoProfile -ExecutionPolicy Bypass -File <kit>\install-offline.ps1 -Root D:\ECHO
# 在线工具包 ECHO-kit-*.zip：入口在主程序里（同一个脚本）
powershell -NoProfile -ExecutionPolicy Bypass -File <kit>\ECHO\scripts\install-all.ps1 -Yes
```

装完它会**打印面板地址**（`http://127.0.0.1:<端口>/`）。实测：临时目录里 **89.7 秒**装完并起服务
（裸机没 Python 的路径 61.4 秒）——**离线包不需要联网、也不需要 agent**。

**原路（保留）**：把资料夹交给 AI 助手，说"按 `echo-install` 技能给我装 ECHO"。
技能继续独立可用，两条路装出来的东西一样（组件那一步是同一个脚本）。

> 顺带一个**修掉的坑**（影响旧路径）：`requirements-core.txt` 是 UTF-8 带中文注释，
> 而 pip 读 `-r` 文件时按**系统 locale** 解码 —— 中文 Windows 上会
> `UnicodeDecodeError: 'gbk' codec…`，`install.ps1` 第 5 步在中文 Windows 上必然失败。
> 已在两个 requirements 文件首行加 `# -*- coding: utf-8 -*-`。

# 项目进展：一套 DSH（2026-11-03）

> 面向接手的人（或未来的 agent）：这一轮把 ECHO 的智能体从"两套 DSH"收敛成"一套"，
> 并修掉了一个真实装机阻断（微信缓存长路径）。**先读第九节"断点/未决"，那里是停下来时的真实状态。**

## 1. 要解决的问题（用户原话）

- "**我不能接受用户用两套 dsh**"；
- 希望用官方桌面版（看重它**升级、安装方便**），前提是"**ECHO 启动能拉起、访问也能跳转**"；
- 桌面版必须能同时用于聊天（用户就是在桌面版里跟 agent 对话的，关掉就没法对话）。

## 2. 定下的架构（现行口径，已写进 AGENTS.md）

**一套 DSH = 官方 DeepSeek Harness 桌面端自带的 `dsh`，无头运行，`DSH_HOME` 与桌面版共用 `~/.dsh`。**

| 项 | 做法 |
|---|---|
| 程序来源 | `<桌面端>\resources\runtime\cli\bin\dsh.cmd`（升级跟着桌面端，不需要 npm/Node） |
| 进程 | ECHO `Popen` 无头 `dsh web --port 43199 --no-open`，token 换 Cookie |
| 家目录 | `paths.dsh_home_root()` → `~/.dsh`（`ECHO_DSH_HOME` / 隐藏设置 `dshHome` 可覆盖） |
| 旧数据 | `harness_proc.migrate_legacy_home()`：旧家目录（`<根>\dsh\home`、老装机 `<DATA>\harness`）**只补缺**并进 `~/.dsh`，有标记文件、旧目录不删 |
| 单实例仲裁 | 桌面版**有对外接口**（43120 可访问）→ 直接用它；当前官方桌面版 0.2.1-rc.5 **没有**这个接口（asar 里没有该开关、43120 不监听）→ ECHO **照常起无头 dsh，与桌面版两个进程共用 `~/.dsh`**（2026-11-03 用户拍板；风险如实记日志）；桌面版有接口时 `yield_to_desktop()` 才让出 |
| 跳转 | `POST /api/harness/browser`：桌面版有接口→签名 Cookie 打开 43120；否则打开无头 dsh 的 Web 界面 |
| 退出 | ECHO 停止时 `scripts/stop.ps1` 会按 `<data>\logs\harness.pid` 收掉 **ECHO 自己起的**无头 dsh（实测：否则它会留在 43199 上继续占着 `~/.dsh`） |
| 产品面 | 只有 `dsh` 一个智能体、一行启动状态；`dshAutoStart` 默认开；旧 `agentBackend=harness` 归一成 `dsh` |

## 3. 代码改动清单

- `app/paths.py`：`dsh_home_root()` 指向官方桌面端家目录；新增 `legacy_dsh_homes()`（迁移来源）。
- `app/harness_proc.py`：
  - `home()` 改为共用家目录；`find_desktop_cli()` 定位桌面端 dsh；
  - `desktop_mode()`（43120 探活）、`desktop_gui_running()`（**按进程区分 GUI 与无头 CLI**）、
    `yield_to_desktop()`（桌面版出现时停掉 ECHO 起的无头，只停自己起的）；
  - `ensure_running()` 增加桌面版分支 + 迁移调用；`command()` 优先桌面端 dsh。
- `app/agents/harness_agent.py`：`name="dsh"`、显示名「DSH（DeepSeek Harness）」，
  内部按 desktop/headless 切换 base_url 与鉴权（签名 Cookie / token→Cookie）；
  `DshAgent` 不再注册（只作父类 + 桌面版探针）。
- `app/agents/__init__.py`、`app/dsh.py`、`app/manager.py`：`active_name`/`selected_name` 归一旧值；
  `get_desktop_client()` 直接实例化探针；`dsh_start/dsh_stop` 走一套引擎（启停只动 ECHO 起的）。
- `app/boot.py`：启动页只注册 `dsh` 一行（label「DSH（唯一一套）」），`_start_dsh` 按 `dshAutoStart`；
  `refresh_agent_rows()` 按实际状态重算（含 GUI-在跑但没开浏览器访问的失败文案）。
- `app/api.py`：`/api/status` 单行校准 + 让出；`/api/harness/browser` 双分支；
  `/api/control/dsh/start|stop` 真启停。
- `app/config.py`：新增 `dshAutoStart`、`dshHome`；`harness*` 标退役/废弃；`agentBackend` 选项只剩 dsh/codebuddy。
- `app/settings_effects.py`：改智能体/DSH 设置后启动或停止、并重算启动页那行。
- `app/services.py`：组件行去掉 `harness`（`report_harness` 兼容映射到 dsh）。
- `web/app.js`：去掉退役的「启用标准版 harness」设置行；跳转提示改「DSH 界面」。
- 安装与交付：
  - `.dsh/skills/echo-install/scripts/echo-install-components.ps1`：`-Agent` 默认 `dsh`；不再装 npm harness；
    只确保官方桌面端已装；写 `agentBackend=dsh` + `dshAutoStart=true`；
    调 `POST /api/control/dsh/start` 并轮询组件 `dsh` 到 `online`（180s，超时如实报）。
  - `scripts/install-all.ps1`、`delivery/kit-install.cmd`：默认 `-Agent dsh`、去掉 `-AskDsh` 传递。
  - `SKILL.md`、`kit-readme-win.md`、`kit-readme-offline.md`：Windows 口径改成一套 DSH；macOS 段未动。
  - `scripts/install.ps1`：**Step 4 复制改用 robocopy**（修下面第五节的长路径事故）。

## 5. 真机验证记录（本机 dev，2026-11-03）

1. 启动页**只剩一行** `DSH（唯一一套）`（total 6、ready 6、失败 0），`/api/agents` 只有 dsh（+CodeBuddy）。
2. `POST /api/dsh/workspaces/ensure` 把「会议空间 / 指令空间」登记进 **`~/.dsh/storages/workspace.json`**
   （路径 `C:\echo-dev\data\meetings`、用户自定义指令目录等）→ 打开桌面版侧栏就能看到（数据层面已成立）。
3. **发现 A（临时保护，后被 D 取代）**：桌面版 GUI 开着但**没有**「普通浏览器访问」→ 43120 不监听。
   当时先加了进程级 `desktop_gui_running()` + 拒绝起无头（避免双写）；后来用户拍板要"同时用"，
   改成允许共存（见 5）。
4. **发现 B（重要事实）**：扫描官方桌面端 `app.asar`（0.2.1-rc.5）**没有** `普通浏览器访问` /
   `dsh-desktop.mode=compatibility` 这类开关；官方 nightly feed 最新也是同一版本；桌面版是 Electron
   单实例、**不对外开本地 HTTP 端口**。→ ECHO 文档里"43120 + 签名 Cookie 直接连桌面版"是 **DSH Desktop
   2.0 时代**的能力，当前版本不存在。
5. **发现 C（已修）**：新机器从**微信缓存目录**双击安装，Step 4 复制 `sidebar\...\Microsoft.Web.WebView2.Core.xml`
   报「未能找到路径"…"的一部分」= **Windows MAX_PATH(260)**，不是包缺文件（zip 里两处都有）。
   已改 `install.ps1` Step 4 用 `robocopy`（长路径原生支持；exit≥8 才失败）。
6. **发现 D（已定案并验证）**：用户要"先开桌面版、再开 ECHO、两个同时用"。既然桌面版没有对外接口，
   唯一形态 = 无头 dsh 与桌面版**两个进程共用 `~/.dsh`**。已改：`ensure_running()` 在 GUI 在跑时
   **照常起无头**（日志记 warn）；`yield_to_desktop()` 只在桌面版真有接口时才让出。
   2026-11-03 14:38 本机实测：桌面版 GUI 开着 → 启动 dev ECHO → `43199` 起来、`/api/status` 里
   `dsh` = **online「无头 dsh 在跑（与桌面版共用同一个 DSH 家目录）」**、`/api/agents` 只有 dsh + CodeBuddy、
   `POST /api/dsh/workspaces/ensure` 返回 ok（会议空间/指令空间 kept）。**但**发现停 ECHO 后
   无头 dsh 会孤儿化（43199 仍监听）→ 已修 `scripts/stop.ps1`：按 `data\logs\harness.pid` 收掉
   ECHO 自己起的那个（只杀命令行含 `dsh web --port` 且指向本树的；用户手起的不动），复测 8970/43199 都收干净。
7. **发现 E（安装器三个真机 P0，已修，2026-11-03 傍晚）**：
   * "是否已装 DSH"判据太粗暴：`<安装根>\dsh\app` **空目录**（install.ps1 会先建、老标准版卸载后
     也可能剩）被当成"已装 DSH"→ 全新机器误判。已不再建 `dsh\app`/`dsh\home`；`Ask-UpgradeDsh`
     改看真东西（官方 `dsh.cmd`、`~/.dsh` 的 settings/凭据/sessions）。
   * 判断与动作不一致：升级路径"不升级 DSH"把 `$Agent` 设成 `'none'` → 组件**根本不检查 dsh**，
     装完 ECHO 没引擎。现在无论升不升级都按 `$Agent='dsh'` 校验（不升级=只认已装、缺了如实报错）。
   * **数组 splat 错误**：`$dargs = @('-LogFile', $x); & $helper @dargs` 把命名参数按位置绑定
     （`-LogFile` 落进 `-InstallDir`、日志路径撞 `-TimeoutSec`）→ helper 一条都没执行。
     已改哈希表 `$dargs = @{ LogFile = ... }`；`harness-install-desktop.ps1` 里 `$args = @('/S')`
     改名 `$installerArgs`（`$args` 是自动变量）。实测：直接调 / 哈希表 splat 都能复用；旧写法复现报错。
   * **补充加固（同轮）**：`Is-Running` 只按进程名会把 **ECHO 的无头 dsh 当成桌面版 GUI**（同一个
     `DeepSeek Harness.exe`），已改 `Get-RunningKinds` 按命令行区分（含 `dsh-desktop-host\lib\cli.js`
     / `web --port` = 无头），升级时提示先停 ECHO；`--version` 探测加 **20s 硬超时**（坏 CLI 挂住不会
     拖死安装器）；装自定义目录时用 `Find-CliUnderRoot` **只认目标根下**的 CLI，避免拿旧安装冒充成功。

     显示「与桌面版共用家目录」；`scripts/stop.ps1` 退出时收掉 ECHO 起的无头 dsh。

     停 ECHO 后 8970/43199 都收干净。

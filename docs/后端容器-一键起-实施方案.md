# 在本机起一个能力后端（「帮我起本机后端」）—— 实施方案

> 2026-09-29 定稿。**这份文档是"客户端简化第 3 步"的落地依据**：设计口径见
> `docs/3.0-设计总览与组件关系.md`（会议 100% 依赖能力后端、无本机回落；"帮我起本机后端"已设计未实现）。
> 第 1 步（路由收口 + 如实降级）与第 2 步（删掉客户端进程内会议转写/分离）**已完成并推送**
> （`57db9e29` / `21ab45d7`），所以这份方案从"删干净之后"起步。
>
> **落地进度（2026-09-29 晚）**：§5 的 **1a `app/backend_pid.py`**、**1b `app/backend_proc.py`**
> 与 **1c `app/backend_setup.py`**（写配置 → launch → 等配对文件 → 跳过重复配对 → 配对）
> 已落地并过全量门禁；1d / 2 / 3 / 4 / 5 **未做**。
> 落地时补的一条铁律：**探活与取进程名走接缝**
> `app.platform.pid_alive()` / `process_label()` —— 业务代码里不许出现 `ctypes.windll` 或
> `os.kill(pid, 0)`（Windows 上后者是"给那个进程组发 Ctrl+C"，探活会把对端打断；
> 门禁 `tests/test_path_seam.py` 会红）。
> 另一条实测结论（写进了 1c 的实现）：**"本机配对文件在了"不等于"能连上"** ——
> uvicorn 先跑 lifespan 后绑端口，而配对文件正在 lifespan 里写，所以配对这一步要对
> "连不上"留一个重试窗口（`backend_setup.PAIR_READY_TIMEOUT`）。
> 细节见 `docs/3.0-PROGRESS.md` §8.7 / §8.8。

## 0. 已核实的事实（别再重复验证）

* **本机自动配对那一半已经落地**：服务端 `server/localpair.py`（写 `{state_root}/local-pair.json`）+
  客户端 `app/capabilities/pairing.py`（`read_local_pair` / `pair_local`）+ `app/api.py` 的
  `POST /api/capability/pair-local` + 面板接线。**缺的只有"起后端"那一半**（全仓没有任何起后端/装后端的代码）。
* `server.local_pair` 默认 **false**，交付路径设 true；**没开它就永远不写配对文件** → 面板"检测本机后端"必然禁用
  （dev 机上那条手工雏形 `data/backend-dev/` 就是这个毛病）。
* **"不走容器的扩展包"目前不存在**：`scripts/build_backend_kit.py` 只出容器档（compose + .env.example +
  server.yaml + 源码 + 两个 shell 脚本）；没有 `delivery/backend-portable/`。
* **只绑回环要改两处**：`listen: 127.0.0.1:8900` **和** 容器侧的端口发布 `127.0.0.1:8900:8900`（只改一处 = 仍对网段开着）。
* **回环后端现在会被判成"内网出网"**：`app/capabilities/echo_server.py` 的 `source = SOURCE_LAN`，
  而 `router.py` 在 `privacy=none` 时只放行 `SOURCE_LOCAL` → 会挡住只绑回环的本机后端。**需用户拍板**（见 §7-4）。
* dev 机自测可用现成 `venv/`（`data/backend-dev/run-backend.cmd` 就是先例），但它自己那份 yaml 缺 `local_pair: true`；
  且它的 `torchaudio` 是 `2.10.0+cpu`（torch 是 `+cu128`）—— 正是 AGENTS.md 记的 ABI 坑，只在 dev 上没被吃到。

## 1. 两条交付路

### 1A 容器路（宿主有 NVIDIA GPU + Docker）
探测：`docker version` / `docker compose version` / `docker info` 里有没有 `nvidia` runtime / `nvidia-smi -L` /
磁盘 / 8900+8901 端口。镜像来源优先级：本地已有 tag → 交付带的 `.tar`（`docker load`）→ 内网 registry →
**最后**才现场 `compose build`（必须带 `ECHO_PIP_INDEX`，国内 pip 慢上百倍）。
状态卷一律放 `{echoBase}\backend\`：`models`(ro，优先复用客户端模型库) / `state`(耐久：auth.db + local-pair.json) /
`tmp`(可丢) / `cache`（**必须**，它同时是 `MODELSCOPE_CACHE` 与 `HOME`；缺了每个 `/v1/asr` 都 503）。

### 1B 扩展包路（不走容器）
`{echoBase}\backend\`（与 `echo-core` 平级，升级 echo-core 不动它）：`app/`+`server/` 源码、**独立 venv** `runtime/`、
可选 `wheels/`、`state/` `tmp/` `cache/`、客户端生成的 `server.yaml`；日志/pid 落 `{DATA}\logs\`。
python/torch 来源：**随包带完整 CPython 3.11 + wheelhouse**（照 min-kit 的 `bundle/runtime`+`bundle/wheels` 先例；
**别用 python.org embeddable 装 torch**，待真机验）。torch 判据是**同 CUDA 源标签**（新卡 cu126：实测
`torch 2.14.0+cu126` + `torchaudio 2.11.0+cu126`；老卡 cu118 + 钉 `torch==2.7.1`、**不装 pyannote**、配置里也不宣告
`diarize`/`speaker-embed`）；安装期必须做与 `server/Dockerfile` 同一条 ABI 校验（"标签一致 + `import torchaudio` 通过"）。

## 2.「一键起」流程

`plan()`（**只读**，先给人看：走哪条路/变体/体积/时长/缺什么/要不要联网）→ 用户点"开始" → job →
`preflight → fetch → configure → launch → wait-pair-file → pair → ready → done`，每阶段 `ok/failed` + 人话 + 下一步。

* **configure**：写 `server.yaml` = `listen: 127.0.0.1:8900` + `admin_listen: 127.0.0.1:8901` +
  **`server.local_pair: true`** + `auth.jwt_secret`（**生成一次后持久化，绝不重生成**）+ `state_root` / `tmp.root` /
  `models.root`（指客户端模型库，不复制）+ `models.device: cuda`；扩展包路还要 `MODELSCOPE_CACHE` / `HOME` 指可写目录。
  **并自动写 `capabilityLocalPairPath`** —— 路径是客户端自己选的，**不用问人**（设置项保留，供手工部署覆盖）。
* **launch**：`CreateNoWindow`（照 `scripts/echo-launch-lib.ps1` 的 `Start-EchoProcess`，**别用 `Start-Process`**）；
  cwd=`{echoBase}\backend`；stdout/err → `{DATA}\logs\backend.log|err`；pid → `{DATA}\logs\backend.pid`。
* **pair**：等 `local-pair.json` **出现**（≤60 s、1 s 轮询）→ `pair_local`。**已经配对到同一个回环地址时跳过**
  （否则每次都会在服务端新建 client，把管理面清单撑爆）。
* **ready 三层（缺一不可）**：L1 `GET /v1/health` 200；L2 `GET /v1/ready` 必须 200（503 时把 `failed[]` 原样报出）；
  **L3 一次真实自测** `POST /v1/asr`（客户端本地生成 1 秒 16k 单声道 wav）—— 只有它能挡住
  "`/v1/health` 全绿但每个 `/v1/asr` 都 503"（AGENTS.md 记的那个坑）。L4 `/v1/diarize` 可选：老卡"没有这一档"
  要**如实说"这块卡做不了分离"**，不算失败。
* 失败/取消：**任何一步失败都不改已有设置**（尤其不把 `capabilityMeetingAsrBackend` 提前改成 `echo-server`）；
  解包走 `backend.part-<stamp>` + 原子 rename；取消 = 删 part（保留 wheels/cache 可重试）。

## 3. 生命周期

只停 **ECHO 自己起的**（pid 文件为凭）；手工起的实例**绝不碰**。开机自启**默认关**（面板给开关）。
**客户端退出：后端留着**（会议是分钟到小时级），设置里给"随客户端停"（默认关）。
升级：容器换 tag + `up -d`；扩展包覆盖 `app`/`server`/`runtime`，**`state/` 与 `cache/` 一个字节不动**，
`jwt_secret` 与 `auth.db` 必须保留（否则所有客户端要重配）。卸载：停 → 删 `backend/`（删凭据前问一句）→
清客户端那几个键 + `unpair()`。本机后端是 **1:1**；同机**不许两个**（已有实例就如实说"已经有一个在跑"并直接进入配对）。

## 4. 诚实降级（面板必须说"哪一条不满足 + 下一步"，**绝不悄悄回落**）

| 前置不满足 | 面板要说的话 | 下一步 |
|---|---|---|
| 没 Docker 且没可用 Python | 两条路各自缺什么 | 装一个 / 连同事的后端 |
| `nvidia-smi` 缺失或报错 | **原文**贴出报错 | 装驱动；容器路先验 `docker run --rm --gpus all nvidia/cuda:12.4.0-base-ubuntu22.04 nvidia-smi` |
| 显存不够 | "这块卡 X GB；qwen3asr+对齐器峰值 4.6 GB、pyannote 2.6 GB，同时常驻会顶爆" | 小卡只起 asr（SenseVoice），分离如实不可用 |
| 老卡 sm_<7.5 | "只能转写，**这块卡做不了说话人分离**"（配置里不宣告那两档） | 自动选 cu118 |
| 磁盘不够 | 需要 ~X GB（模型 6 + 镜像/venv 3~5），现有 Y | 清盘 / 换盘 |
| 8900/8901 被占 | 占用者是谁（**是我们的 → 直接配对**；不是 → 不起第二个） | 停占用者 / 换端口 |
| torch 装上但 ABI 不符 | **报校验原文**（"torch +cu128 而 torchaudio +cpu"） | 换变体 / 清 runtime 重装 |
| 权重缺失/下载失败 | 缺哪几棵、看的是 `models\hub` 还是 ModelScope 缓存 | 客户端面板下载 / rsync / 含权重包 |
| **禁止** | 悄悄回落客户端进程内引擎（第 2 步已删）、悄悄改用在线（等于把会议音频发公网） | 唯一出口是 `app/meeting.py` 的 `waiting-backend` 那种**如实说** |

## 6. 最容易翻车的 5 点（每条的"先验一步"）

1. **Windows + Docker Desktop 的 GPU 直通** → 先 `docker run --rm --gpus all nvidia/cuda:12.4.0-base-ubuntu22.04 nvidia-smi`；
   不通就整条容器路降级成扩展包路（这正是两条路都要有的价值）。
2. **宿主路径→卷映射 + 只读根（`docker cp` 必失败）** → `docker compose config` 看渲染 + 起后 `docker exec … ls /opt/echo/models/hub`；
   要送文件只走可写卷（`/var/echo/tmp`）或薄镜像层。
3. **权重到底在哪**：dev 的 `models\hub` 里**没有** Qwen3-ASR（它在 ModelScope 缓存里）；
   客户端 `modelinfo.ready()` 与服务端 `stt._resolve_local_model()` 两条判据要各算一次，不一致就在 `plan()` 里说清"我看的是哪一处"。
4. **显存与并发**：8 GB 卡上 4.6 GB + 2.6 GB 不能同时常驻；`vram_budget_mb` **没有环境变量**、只能靠生成的 `server.yaml`；
   出厂 `max_concurrent=6` 在小卡上要按 `docs/后端容器部署.md` §9 的算账下调。
5. **"只绑回环"的假安全**：容器路只改 `ECHO_LISTEN` 不改 `ports` 仍对网段开着；
   且 `privacy=none` 会挡住回环后端（见 §7-4）→ 起好后**在另一台机器**上 `curl http://<宿主IP>:8900/v1/health` 必须连不上。

## 7. 需要用户拍板的 5 件事（各带推荐）

1. **扩展包的 Python/torch 从哪来** → 推荐 **随包带完整 CPython 3.11 + 离线 wheelhouse**（内网要能离线一键成功；
   与 min-kit 的 `bundle/runtime`+`bundle/wheels` 同一条路）。
2. **扩展包带不带权重** → 推荐 **不带**，复用客户端模型库 + 缺哪个当场下（含权重作为第二档）。
3. **客户端退出后后端留不留 / 自启** → 推荐 **留着**；自启默认**关**，面板给开关。
4. **只绑回环的后端算不算"出网"** → 推荐 **判 `SOURCE_LOCAL`（不算出网）**：只绑回环 = 音频没离开这台机器；
   把没出网的判成出网，会逼用户放宽一个本该保守的许可，而许可一放宽，**真正的内网后端也会跟着被放行**。
   ⚠️ **这会改现有行为**（`echo_server.py` 的 `source` 改成按地址判），必须用户点头。
5. **一键起失败后会议怎么办** → 推荐 **本批只如实说"这一场没有转写引擎 + 为什么"**；
   `docs/3.0-设计总览与组件关系.md` 里的"离线队列 / 分段 pending"是**独立一件事**，别和一键起绑在一起。

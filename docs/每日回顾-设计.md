# 每日回顾（Voice Daily Review）— 设计

> 状态：**设计已成型，待用户确认后实施**
> 日期：2026-10-06
> 作者：ECHO × DSH 联合设计（含真机实测证据）

## 0. 一句话

下班开车时对 ECHO 说「我们来回顾今天」，ECHO 录音 → 转写 → 交给 DSH「每日回顾」工作区里
**当天那个会话**；DSH 用 `daily-review` skill 整理、登记到 Obsidian 工作日志、并追问；
ECHO 只把回复里 `【播报】…【/播报】` 那一段念出来（≤2 句 + 1 个问题）。

## 1. 目标与非目标

### 目标
1. 车里**免手操作**完成"口述 → 整理 → 登记 → 追问 → 补充"的多轮闭环。
2. 整理与追问的**智力**全部归 `daily-review` skill（在 DSH 里维护、可迭代）。
3. 每天的回顾**独立会话**，事后能在 DSH 侧栏点开回看、继续补。
4. 播报**极短**：单轮 ≤2 句 + 1 个问题（用户 2026-10-06 明确要求：语音反馈不能冗长）。

### 非目标（本期不做）
- 全双工实时语音（理由见 §7.1，实测与调研都指向"不划算"）。
- 语义端点检测（Smart Turn 等）—— 本期先用**静音 + 超时 + 显式口令**兜住，留接口。
- AEC（回声消除）：本期靠"播报时不收音"的时序避让，不做信号级处理。

## 3. 方案

### 3.1 核心决策：**工作区在安装根下，写入权限走 DSH 的 defaultPreset**

三条路径各归其位，**不互相绑死**：

| 角色 | 值 | 用来干什么 |
|---|---|---|
| **工作区**（= 会话 cwd） | `{echoBase}/review` | 会话落点、侧栏分组「每日回顾」 |
| **笔记库根目录** | `C:\Users\zhkq\OneDrive\笔记\笔记-2026\笔记-2026` | skill **读**历史日志/待办、**写** `01-工作日志\YYYY-MM-DD.md` |

由 F5 可知：会话 cwd = `{echoBase}/review`，而笔记库在它之外 → `workspace-write` 下**写不进去**。
解法不是把工作区扩成笔记库，而是**把 DSH 新建会话的默认权限档位改成 `danger-full-access`**：

```python
client.rpc("settings/update", {"ns": "permission",
                               "patch": {"defaultPreset": "danger-full-access"}})
```

**这条路 ECHO 早就在用**（`app/worklog.py:91 ensure_dsh_default_access()`），
注释里写明它的由来：*"会议归档要把纪要写进 vault，而笔记库在归档会话的工作区之外……
实测整场要 10 分钟上下，用户看到的就是『归档失败』"*。
它读的是 `settings/describe` 的 `permission` 命名空间，改的是**未来会话的默认档位**
（DSH 文档原话："`permission` 设置命名空间为未来会话持有 `defaultPreset`"），
**不影响已存在的会话**，也不需要重启任何进程。

> ⚠️ **更正**：本设计早期版本写过"DSH 做不到按工作区放宽权限"并据此把工作区设成笔记库根。
> 那个结论**只对了一半** —— 确实没有"按工作区"这一档（F6），但**有"未来会话默认档位"这一档**，
> 而且可远程修改。所以 3.1 改为上表。这是本轮最值得记住的一条：**先查自己仓库里有没有已解决的同类问题**。

**代价（必须如实说）**：这是一个**全局默认**，改完之后**用户在 DSH 里手动新建的会话**
也会是全盘访问。这与 `worklogEnabled=true` 时的现状一致，且 ECHO 每次归档前都会复核一次。
不想接受就关掉 `dailyReviewEnsureSessionAccess`（新增设置，默认跟随 `worklogEnsureSessionAccess`）。

### 3.2 会话契约（复用现有适配器，零新增协议）

```python
client = dsh.get_client()                                  # F1
wid, created = client.ensure_workspace(vault_path, title="每日回顾")   # F2
if created: client.ensure_workspace(vault_path, title="学习")          # 兜底改名策略见 §3.5
sid = db.get_or_create_review_session(date_str)             # 每天一条，见 §3.3
client.prompt(sid, prompt_text)                             # F4
reply, done = client.wait_for_reply(sid, timeout=180)       # F4
spoken = extract_broadcast(reply)                           # 【播报】…【/播报】
providers.speak_async(spoken)
```

### 3.3 会话生命周期：每天一个，当天内续话

- 自然日第一次说「我们来回顾今天」→ `session/create` 建**新**会话，标题带日期。
- 当天后续轮次 → **复用**同一 sid（多轮上下文靠 DSH 自己的会话记忆）。
- 跨天 → 新建。判据用**本地日期字符串**，与 `session_id` 一起落 ECHO 的 `sessions` 表
  （新增 kind `review`，`agent=self.name`，与 `command` 同构 → 换后端自动失效）。

### 3.4 回合内契约（最重要的一处）

ECHO 发给 DSH 的文本 = 环境信息 + 用户原文 + **本回合输出契约**：

```
【环境信息】当前时间：2026年10月06日 18:30（星期二）……【/环境信息】
【今日口述·原始转写】<ASR 原文，不做改写>【/原始转写】
请按 daily-review skill 整理并登记到 Obsidian 工作日志。本回合必须输出：
1) 屏幕可见的整理结果（可以长，给人回看）；
2) 恰好一段播报稿，用【播报】开头、【/播报】结尾，内容 **≤2 句 + 1 个问题**，
   不要 Markdown、不要列表、不要编号——它是要被念出来的。
```

**为什么给"原始转写"而不是让 ECHO 先整理**：原始转写是唯一真相，整理稿只是视图；
DSH 侧能溯源到原话，才能回答"我第二段到底怎么说的"（调研硬建议 §2）。

**为什么用固定标记而不是让 ECHO 截断**：`conclusion_only()` 是猜哪句该念；固定标记是
skill **显式声明**哪句该念。前者在"整理结果里有多个结论"时必然截错。

### 3.5 名称策略（一个已知的坑，必须有兜底）

`ensure_workspace(path, title="每日回顾")` 会把笔记库这个工作区**改名**为「每日回顾」。
而它现在很可能**已经是**一个名为「学习」的工作区 → 按 `_apply_title` 的"用户没改过才改"判据
（`dsh_agent.py:309`，当前名 ≠ basename 就认定为用户自己起的）→ 返回 `user-named`，**不改名**。

于是**分两种情况**，都要能用：

| 情况 | 现象 | 处理 |
|---|---|---|
| 笔记库还没登记过 | `workspace/create` 新建，名字 = 目录名，随后被改成「每日回顾」 | 正常 |
| 笔记库已是「学习」工作区 | 返回 `user-named`，分组名保持「学习」 | **接受**；日志里如实记一句，不硬改用户起过的名字 |

> 不做"改成学习"的硬编码兜底：那是把用户的命名当常量写进代码，正是 `_apply_title` 要避免的。
> 若用户希望侧栏看到「每日回顾」而不是「学习」，那是**改分组名**的事，走面板/DSH UI，不由本功能偷偷改。

### 3.6 ECHO 侧语音编排

新增一个**回顾模式**（独立于现有 `capture()` 的单轮语义）：

```
① 触发：唤醒词/热键 → 命中回顾意图（"我们来回顾今天/每日回顾"）
② 开场播报：「好，开始今天的回顾，你说。」（一句话，不占轮次契约）
③ 循环 {
     录音：record_command(max_ms=120000, hangover_ms=1200)   ← F8 现成
     转写：走现有 _transcribe_command()                       ← 现成
     若命中结束口令（"说完了/结束回顾"）→ 提交并收尾 / 退出
     提交：client.prompt(sid, 环境+原文+契约) → wait_for_reply  ← 复用
     播报：extract_broadcast(reply) → speak_async             ← F9 的去 Markdown 管线复用
   } 直到用户说"结束回顾"或超时
④ 收尾播报：「今天的回顾记好了。」（一句）
```

**麦克风时序**：播报期间不收音（现有 `record_command` 是前台独占，播报走 `sd.play` 不占麦锁）。
即"半双工避让"，不做 AEC —— 这与 ECHO 现状一致，零新增风险。

### 3.7 播报稿的二次兜底

即使 skill 没按契约给出 `【播报】` 段（模型偶发不听话），ECHO 也不能把整篇念出来：

```
spoken = extract_broadcast(reply)          # 有标记就用标记
      or conclusion_only(reply)            # 没有就退回现有"极简结论 + 字数上限"
      or "整理好了，你看一眼会话。"          # 再兜一层
```

三层兜底，任何一层生效都不会出现"念一整篇"。

**第四道闸（朗读前）**：`assistant._review_speak()` 在真正调用 TTS 之前再夹一次，
上限取 `min(dailyReviewBroadcastChars, maxBriefChars)`。理由是"任何一环失效都不该让车里
听到长稿"：技能不听话、或**设置被调成很大的值**时，前三层都可能放行。
上限必须**两个都取小** —— 只取 `maxBriefChars` 的话，把它设成 100000 兜底就没了
（这条正是被 `test_clamp_happens_even_if_the_setting_is_huge` 逮出来的）。

## 7. 附录

### 7.1 为什么不做全双工实时语音
调研结论（含来源）已落盘 `dist/_voice_drive_report.md`。三条要点：
① DSH 是轮次制、思考秒级，双向流的价值区间被吃掉；
② 车内噪声会让 VAD 式 barge-in 误触发；
③ 长口述需要"可回退的文本真相"，全双工"说完即定"改不了。

### 7.2 为什么不用官方 SDK（`dsh --profile sdk`）替代现有桥
SDK 的代价：会话**不进侧栏**、要自养子进程、要自己写 JSON-RPC 客户端与
事件流文本提取（"取助手文本"这类事 `wait_for_reply` 已经做好了）。
它唯一的实质优势是权限可控（`DSH_PERMISSION_MODE`），而权限这条已经有更省的做法
—— 复用 ECHO 自己的 `settings/update{permission.defaultPreset}`（§3.1）。
**性价比为负**。保留为将来"要脱离 GUI 独立跑"时的备选。

### 7.3 一处已知缺口（留给后续）
`record_command` 只有"静音收尾"，没有**语义端点**。用户列举到一半停顿 1.4 秒就会被收轮
（`dailyReviewSilenceMs`，可调），下一轮变成"补充一句……"。这是可接受的降级，但若实测别扭，
下一步接 Pipecat Smart Turn v3（开源、8MB、CPU 12ms、中文准确率 88.6%）。

## 8. 顺带修掉的一个既存 bug：`expand_path` 会改字

**怎么发现的**：本功能的提交模板里同时有占位符和 `【/播报】`，于是
`config.expand_path()` 被走到 —— 实测它把 `【/播报】` 变成了 `【\播报】`。

**根因**：`expand_path()` 对**任何**含 `{` 的字符串无条件跑 `os.path.normpath`。
`normpath` 会把 `/` 折成 `\`（它以为在处理路径）：
`'【播报】x【/播报】 … {transcript}'` → `'【播报】x【\播报】 … {transcript}'`。

**影响面比本功能大**：触发条件是"**含 `{占位符}` 且带斜杠**"，所以**所有"模板类"设置**
都中招（`worklogPrompt`、`dailyReviewPrompt`、以及用户自己写的任何模板）。而且它**静默**：
写进去是好的、读回来已变形，面板上看不出、日志里也没有。

**修法**：加 `_looks_like_path()` 判据 —— 多行、或去掉 `{ECHO}`/`{DATA}` 后仍有花括号的，
只做占位符替换、**不 normpath**。真正的路径项（`{ECHO_BASE}/meeting`、`C:\a\b`）行为不变。
判据刻意保守：漏掉一次 normpath 只是分隔符不统一（Windows 照样能用），
而 normpath 的代价是改用户输入的字。

**判据**：`tests/test_paths.py::ConfigPathTests::test_expand_path_does_not_rewrite_text_templates`。
